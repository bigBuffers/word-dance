## 0. 一页结论

- **图是什么**：一张 800×500 的 SVG，分两层——**场景层**（`<g id="scene">`，没有任何文字，单独看也完整）和**单词层**（`<g id="word-art">`，最后一层：单词本身，用开源识字字体 Andika 的字形轮廓画成路径，按拼读块分色，不发音字母是虚线的「幽灵字母」，双写字母成对，外加一个由画面演出来的记忆钩子）。画风是评选出来的「晨光动画」，人物固定为朵朵、乐乐、奶奶、团子。
- **这次上线什么**：让线上系统认识这种图（清洗规则、带 / 不带单词层两种取法、记忆钩子的文字、设置里的开关），并把**小学前 100 个词**（按学习顺序）和已确认的 10 张样例导入线上。其余词暂时保持现在的图。
- **开关**：设置页「学习设置」里多一个「图片上显示单词」，默认开；关掉后同一张图不带单词层。
- **图怎么来**：不走线上的自动生成（那条路一次成图、看不到渲染结果，达不到这个质量）。图在 `studio/` 里离线制作（自动出美术指导 → 画 → 程序校验 → 渲染检查 → 评审），合格后用 `wd images-import` 导入。批量画法和每张的消耗由试验确定（§6）。

## 2. 现状（代码事实）

1. 小学 600 词现在都是 `claude_svg` 图（`prompt_version = 'svg-v2'`，平均 1.8 KB），由 `ai/svg.py` 调 CLI 一次生成，`images/store.activate_svg` 清洗（`sanitize_svg.clean(allow_text=False)`）、打 AIGC 标记、按 sha256 存成 `images/<2hex>/<sha256>.svg`、激活并把旧图标成 `superseded`（`backend/wd/images/store.py:173-213`）。
2. 清洗器的元素白名单没有 `filter` / `clipPath`（`backend/wd/images/sanitize_svg.py:42-58`），`url(#id)` 只允许出现在 `fill` / `stroke`；上限 60 KB。新图用到高斯模糊、投影和裁剪。
3. 图片经 `GET /media/images/{path}` 原样下发（`routers/media.py:38-48`，不可变缓存，SVG 带 `default-src 'none'` 的 CSP）；前端是 `<img>`（`components/study/WordImage.tsx`），所以页面脚本碰不到图里的图层——**隐藏单词层必须由服务器给出另一个版本**。
4. `ImageMeta`（`schemas.py:1247-1256`、`types.ts`）没有「这是记忆图卡」的标记，也没有图自带的记忆文字；学习卡的「记忆」一栏只显示 `content.mnemonic_zh`（`StudyCard.tsx:274-277`）。
5. 「换一张」（接口 29）会排 `fetch_image`，对小学词先搜图库，能把一张画换成剪贴画（11-07 记录在案的缺口）。
6. 新增一个 `user_settings` 列的代价和做法见 `2a1359d`（`dance_mode`，迁移 0015）：一条 `ADD COLUMN`、DTO、`settings_row_to_dto`、路由、契约文档、15 个带 `Settings` 夹具的前端测试。

## 3. 规格

### 3.1 记忆图卡的识别与校验
- 一张 `word_images` 行是记忆图卡 ⇔ `provider = 'claude_svg'` 且 `prompt_version` 以 `memo-` 开头（本期 `memo-1`）。`text_free = 1` 不变（字母是路径，没有 `<text>`）。
- 结构校验（`backend/wd/images/memo.py`，导入时执行，不依赖字体库）：根 `viewBox="0 0 800 500"`；根的直接子元素里有 `<g id="scene">`，且**最后一个**子元素是 `<g id="word-art">`；`#word-art` 里 id 形如 `wa-<序号>-<字符>` 的 `<path>`（忽略 `-dot` 后缀的那种）按序号排起来正好拼出词头里的字母和数字（空格、连字符、撇号、句点不算），每个序号恰好一次；清洗后 ≤ 60 KB。不满足 → 拒绝导入并说明原因。字形是否真的是字体轮廓由 `studio/tools/check` 把关（那边有字体）。
- 清洗：`sanitize_svg.clean(svg, allow_text=False, effects=True)`。`effects=True` 额外放行元素 `filter`、`feGaussianBlur`、`feDropShadow`、`clipPath` 和属性 `filter`、`clip-path`、`stdDeviation`、`in`、`result`、`clipPathUnits`、`filterUnits`、`flood-color`、`flood-opacity`；`url(#本地id)` 额外允许出现在 `filter` 和 `clip-path` 里。默认 `effects=False`，现有调用点（线上自动生成的图）行为不变。

### 3.2 两种取法（接口 52）
`GET /media/images/{path}?plain=1`：`path` 是 `.svg` 且文件里恰好有一个 `<g id="word-art"` 时，返回去掉这一层的同一张图（清洗器的输出是规范化的，单词层是根的最后一个子元素：从它的起始标签截到文末，补回 `</svg>`）；否则与不带参数时完全一样。响应头不变（不可变缓存按完整 URL 生效）。`plain` 只接受 `1`；其他值按没有参数处理。

```ts
}
```
`frontend/src/api/types.ts` 已先行写入（2026-11-13）；`docs/API.md` §9 必须与它逐字一致，`schemas.py` 字段对应。`ImageMeta` 在照片、旧图、模板卡上：`word_layer: false`、`hook_zh: null`、`note_zh: null`。接口 15（`PUT /api/settings`）接受 `image_word`（布尔）。

### 3.5 导入命令
`wd images-import DIR --manifest FILE [--dry-run] [--only LEMMA …]`：
- `FILE` 是 JSON：`{"prompt_version": "memo-1", "model": "<做图的模型>", "cards": {"<lemma>": {"alt_zh": "…", "hook_zh": "…", "note_zh": "…"}}}`；图在 `DIR/<lemma>.svg`（lemma 里的空格写成 `_`）。
- 逐词：按 `lemma` 找公开、未合并的词（找不到 → 报错跳过）；结构校验（§3.1）；清洗 + AIGC 标记 + 存盘；与当前在用的图 sha256 相同 → 记为 `unchanged`；否则激活（旧图变 `superseded`，文件保留）并写入 `hook_zh` / `note_zh` / `prompt_version` / `model`，`image_state = 'ready'`。
- 末尾打印汇总（imported / unchanged / rejected 及原因）；有 rejected 时退出码 1；`--dry-run` 只校验不写入。
- `wd images-import --undo FILE`：对清单里每个词，如果在用的是记忆图卡，把它标成 `superseded`，并重新激活该词最近一张非记忆图卡的 `superseded` 图（没有就回到模板卡）。这是回滚图片的办法。
- 命令属于 `wd.images.handler` 那一组（和 `fetch-image` 一起登记在 `cli.py`）。

### 3.6 不让记忆图卡被自动换掉
- 前端：`image.word_layer` 为真时不显示「换一张」。
- 后端：`fetch_image` 处理到一个在用图是记忆图卡的词时，除非是管理员明确要求（现有的 `requested` / 管理端入口），否则直接结束并记 `{"skipped": "memory_card"}`；`generate_svg` 同理（非 `requested` 时本来就不会覆盖在用的图，补上测试即可）。

### 3.7 前端

## 5. 风险
1. **导入会替换 110 个词在用的图**：旧图保留为 `superseded`，`--undo` 可以整批换回；上线和导入前会先给你看 100 张的总览页。
2. **文件变大**：每张约 30–45 KB（现在 1.8 KB），110 张约 4 MB；夜间备份的图片包相应变大，可忽略。
3. **老设备渲染模糊滤镜**：每张限制约 10 个带模糊的图层；平板上要实际看一眼（验收清单）。
4. **`?plain=1` 的截断**依赖清洗器输出的规范形式（单词层在最后）；导入时的结构校验保证这一点，接口对不满足的文件原样返回。
5. **字体**：字形转成了路径，设备上不需要装任何字体；Andika 的 OFL 许可允许这样嵌入，需在许可页注明。

## 6. 做图流程与批量画法（另见 `studio/README.md`）
10 张样例每张反复画了 9–14 轮、约 30 万 token，不能照搬到 100 张。正在做的试验：先由「美术指导」自动给每个词写场景和记忆钩子（另一位逐条核对钩子属实、画得出来），再用几种更省的画法（不同模型、不同的看图返修次数）各画同样 4 个词，评审对照已确认的样例盲评，选出在保持质量前提下最省的画法，并得到每张的实际消耗。100 张按选出的画法分批做，每张过程序校验（拼写、字形、清洗规则），整批过评审，出总览页给你看，然后导入。

## 8. 实现时的修订（2026-11-13，集成后回写；以代码和契约文档为准）

规格（§3）没有变，下面是实现时补上的细节和比原文更严的地方。代码审查之后又改了几处行为，单列在 §8.1；本节里因此过时的句子已经改成现在的样子。

- **§3.1 清洗**：`filter` / `clip-path` 只接受 `none` 或**恰好一个** `url(#本地id)`——比 `fill` / `stroke` 的规则严（滤镜的值在 CSS 里是列表，照搬填充色的规则会放过第二个指向外部的引用）；`blur()`、`circle()` 这类 CSS 函数一律丢弃（`style` 属性整个不留，§8.1）。
- **§3.1 结构校验**多查几项：`scene`、`word-art` 两个 id 全文件各只出现一次；`wa-…` 只能出现在 `#word-art` 里的 `<path>` 上（落在场景层的字母关掉单词后还会留在画面里）；拼写按词的显示形式**区分大小写**（`Monday` 的第一个字母必须是 `wa-0-M`）；序号可以不连续；单词层的起始标签必须写成 `<g id="word-art" …>`（`id` 在最前），因为 `?plain=1` 就是从这里截的。连字符、撇号这类不算字母的字形，`tools/letters` 给的 id 是 `wap-<序号>`，不参与拼写核对。
- **§3.4 三句话**：先把空白压成单个空格再量长度；`alt_zh` 超过 200 也是拒绝而不是截断；清单里的 `model` 要 1–80 个可打印字符（§8.1）。60 KB 的上限量的是清洗后的文件，存盘时再加一行 AIGC 标记（约 100 字节）。
- **§3.5 `unchanged` 的判定**：存盘的文件带着导入当天的 AIGC 标记，直接比 sha256 第二天就永远不相等了；所以先给待导入的图打上在用那一行的模型和日期，再比。图没变而三句话变了：就地更新三句话，汇总里仍记为 `unchanged`（行尾注明 `captions updated`）——改一个钩子不必重画、也不必先撤再导。
- **§3.5 `--undo`** 也接受 `--dry-run` 和 `--only`；撤回之后这个词回到图卡到来时的样子（往前找哪一张、什么时候回模板卡、`image_state` 是什么，规则在 §8.1）；清单里有词库不认识的词时退出码 1。
- **§3.6 「管理员明确要求」怎么认**：`fetch_image` 的任务参数多一个 `requested: true`，由管理端换图（接口 69）写入，和学习者的任务合并时保留；带 `provider` / `query` 的任务同样算明确要求；命令行 `wd fetch-image <词>` 是运维自己的决定，不拦。被拦下的任务结果是 `{"skipped": "memory_card"}`，`image_state` 回到 `ready`。**「不合适」**（11-13 已定，§8.1）：学习者在记忆图卡上点「不合适」只记录这条反馈，图卡不下线、不排取图；把图卡撤下的是管理员处理这条反馈时的「换图」（接口 71）——那时图卡先标成 `rejected`，随后的取图已经遇不到图卡，不受拦截。
- **§3.2**：`plain` 只认单独出现一次的 `1`（`plain=0`、`plain=true`、空值、重复出现都按没有参数处理）；截出来的图不带 `ETag` / `Last-Modified`（不可变缓存下用不到）。
- **§3.3 体验区**（接口 77 / 78）：示例词即使用上了记忆图卡，`ImageMeta` 仍是 `word_layer: false`、钩子为空——未登录的人没有开关可关，公开的图片地址也不提供 `?plain=1`，一律显示带单词的整图。
- **§3.7 「记忆」一栏不再等内容**：图的钩子随图而来，例句还在生成、顺延或失败时也照常显示；只有 `note_zh` 而没有 `hook_zh` 时不显示（提醒是给钩子作注的），退回内容里的联想句。
- **§3.7 替代文字**（集成时补）：记忆图卡的 `alt` 用图自己的 `alt_zh`（就是这张图的画面描述），排在内容里的 `image_alt_zh` 前面；其他图不变。
- **§3.8 工具**：`tools/check` 不留任何自带规则的后备——仓库里的清洗器没有 `effects=True` 或没有 `memo.check_structure` 时直接报错退出（退出码 2）；多一个包装 `tools/build_gallery`；`letters` 的默认字体就是 `Andika-Bold`；自测入口 `make studio-check`（不进 `make test`）。依赖、字形轮廓和 `tools/check` 后来补的规则见 §8.1。
- **§3.9**：许可页把 Andika 单列为第 4 节，只放版权声明和许可链接（站点分发的是画进图里的字形轮廓，不分发字体文件；许可全文随字体文件在 `studio/fonts/OFL.txt`）。

### 8.1 代码审查之后的修订（2026-11-13 下午）

实现完成后做了一轮五个角度的代码审查，28 条发现逐条复核、全部处理（经过和数字在上线说明第 3 节「审查与修复」）。规格（§3）仍然没有变；下面是因此**改了行为**的地方。

- **§3.1 清洗，记忆图卡模式多两条**：① 不保留任何 `style` 属性——原来只丢带 `url(` 的，`style="filter:blur(…)"`、`clip-path:circle(…)`、`image-set('https://…')` 都能从这里绕过上面那条「恰好一个本地引用」和下面的模糊预算；② 属性值里带反斜杠的属性一律丢弃——`u\72l(#g)` 在浏览器眼里就是 `url(#g)`（CSS 转义），而清洗器的规则认不出它。两条都只在 `effects=True` 时生效：线上自动生成的图走的默认模式输出逐字节不变（和基线做了 14 万次差分比对，0 处不同）；那些图一直经 `<img>` 和媒体接口的 CSP 显示，要不要同样收紧是另一件事，没有顺手改。10 张样例里没有 `style`，也没有反斜杠，清洗结果不变。
- **§3.1 结构校验多了「模糊预算」**（`memo.py` 里的三个常数；§5 风险 3 说的「每张约 10 个带模糊的图层」原来只是 studio 的规矩，导入并不查）：带 `filter`（值不是 `none`）的元素最多 **16** 个；一个 `<filter>` 里的 `feGaussianBlur` / `feDropShadow` 最多 **3** 个；每个 `stdDeviation` 是一个或两个 **0–60** 的普通数字（不带正负号、指数、单位）。超出的图卡拒绝导入，原因里写着怎么改。依据是量出来的：10 张样例和批量试验的图最多 7 个带滤镜的元素、每个滤镜 1 个基元、`stdDeviation` 0.8–7；审查时造的图（一个滤镜里串 12 个投影，文件才 1 KB；1000 个图形挂一个模糊）在不用 GPU 的桌面 Chrome 上要画 18–47 秒，有的一分多钟也出不来，而它们都能通过原来的校验。卡着三个上限的图 1–1.5 秒。`studio/tools/check` 在 14 个以上先给警告。没有管的：滤镜一层套一层的深度和滤镜区域的大小（16 层互相嵌套、滤镜区域是画布几千倍的图量到 8 秒）。
- **§3.1 / §3.2 去掉单词层之后的画面必须自己站得住**：场景层用到的渐变、滤镜、裁剪路径必须定义在单词层**之外**（根的 `<defs>` 里）。定义写在 `#word-art` 里的，整图看着正常，`?plain=1` 截出来的那张却没有它们（背景变白、模糊和裁剪失效），studio 的对照图也看不出来——这种图卡现在拒绝导入，并点名是哪几个 id。单词层自己用的定义可以留在层里，也可以用根上的。10 张样例都没有这种写法。
- **§3.3 旧响应的重放**（契约没变）：推荐词判了「不熟悉」时，整份响应会存进 `review_logs.result_json`，设备没收到就重发、服务器照存下的那份回答。上线之前存下的响应里，`ImageMeta` 没有这次新加的三个字段，原样回放过不了响应校验——一个设备会一直重试的 500。现在回放时由 `services/screen.upgrade_stored` 把缺的字段补成 `false` / `null` / `null`（接口 32 和 45）；响应模型本身仍然不带默认值。反方向没法修：新代码存下的响应，回滚到 `ea77832` 之后回放是 500，直到新代码回来——所以上线和回滚都挑没人正在学的时候重启。
- **§3.4 `model`**：1–80 个**可打印**字符。它会写进文件的 AIGC 标记，而标记是在所有检查做完之后才加的；里面有控制字符的话，整批图存下来都不是合法的 XML（空跑还查不出来）。清单里任何地方出现半个代理对（`"\ud83c"` 这种合法的 JSON、却不是文字的东西），整份清单拒绝（退出码 2）。
- **§3.5 清单的键**：两个键指的是同一个词（`moon` / `Moon` / ` moon `）时整份清单拒绝（退出码 2）——原来是悄悄处理两遍，后一个的钩子盖掉前一个。图的文件名按词库里的 lemma 取（小写、单个空格、空格写成 `_`）：键写成 `Ice  Cream` 读的是 `ice_cream.svg`，在区分大小写的文件系统上也一样。
- **§3.5 导入只清洗一次**：拿去和在用的图比对的、最后存盘的，是同一份清洗结果（`store.prepare_memo` → `store.store_memo`）。原来存盘前又洗了一遍，而清洗器对「子元素被丢光的元素」不是幂等的（第一遍写成 `<defs></defs>`，第二遍写成 `<defs/>`），这样的图每次重跑都是 `imported`、多出一行。过了 studio 校验的图不受影响（被丢掉的元素在那边就是错误）。
- **§3.5 `unchanged` 顺便补文件**：图没变、但 `images/` 里它的文件不见了（搬服务器漏拷、图片目录比数据库旧），重新导入时按原路径原样写回，行尾注明 `file restored`（空跑只报告 `file missing`）。「再导一遍」本来就是文档里写的修法，原来它只会回答 `unchanged`。
- **§3.5 存不进去不中断整批**：磁盘满、图片目录不可写、数据库一直锁着——这一张记 `rejected: could not store …`，后面的照常处理，汇总照样打印，退出码 1；再跑一遍补齐，已经进去的是 `unchanged`。
- **§3.5 `retired`**：管理员处理反馈时撤下的那张图卡（下面 §3.6），之后整份清单重新导入（比如导那 100 张的时候）不会把它悄悄换回来：单列一行 `retired`，不算错误、不影响退出码，用 `--only <词>` 点名才恢复；重画过的文件是另一张图，照常导入。判断的依据是这个词最近一行「同一张图」的状态是 `rejected`。
- **§3.5 `--undo` 的去向**：这个词回到**图卡到来时**的样子。从图卡往前找最近一张不是记忆图卡的图（中间的记忆图卡不管是什么状态都跳过）：`superseded` 且文件还在 → 重新启用；`superseded` 但文件没了 → 再往前找；`rejected`（被反馈撤下、之后没有取到新图）→ 回模板卡，更早的图不复活；一张都没有 → 模板卡。回模板卡时，这个词以前取过图（有跑完的 `fetch_image` 任务；被图卡拦下的那种不算）→ `image_state = 'failed'`，这样失败图的自动重试还会管它；否则 `'none'`。原来的写法（「最近一张 `superseded` 的旧图」）会把早就被换掉的旧图翻出来。管理员已经撤下图卡的词，在用的不是图卡，`--undo` 不碰它。
- **§3.6「不合适」只记录，不下线**（11-13 定；原来列在上线说明「未决」第 3 条）。学习者在记忆图卡上点「不合适」，或在「反馈问题」里选配图的原因：接口 28 照样回 `201 {id}`，`content_reports` 多一行（`image_id` 就是这张图卡），**别的都不变**——图卡不标 `rejected`，`image_state` 不动，不排取图任务，不写 `image_rejected` 事件。反馈在「管理 → 内容反馈」里等着；管理员在那里点「换图」（接口 71 的 `refetch_image`）才是撤下图卡的那一步，之后取到什么（图库的图、旧式示意图，或者什么都没有、回模板卡）就显示什么。照片、旧式示意图、模板卡上的「不合适」和以前一样。会替换图卡的途径因此只剩管理员和运维自己的决定：接口 71、接口 69、`wd fetch-image <词>`、`--undo`。
- **§3.7 前端跟着改的三处**：① 记忆图卡上点完「不合适」，详情页只提示「已收到反馈，谢谢」，不再每 3 秒去问有没有新图，按钮也不变灰（学习卡上本来就没有这个入口）；② 图没加载出来（断网、文件丢了）时，「记忆」一栏不显示图的钩子，退回内容里的联想句，和「显示配图」关掉时一样——§3.7 的「图片显示着」现在包括「加载成功了」；按图片地址记，换了取法、换了图、换了词或者重试成功都不受上一次失败的影响；③ 登录页体验区的替代文字先用图自己的 `alt_zh`（体验区的记忆图卡 `word_layer` 是假，原来读出的是内容里那句和新图对不上的描述）。
- **§3.7 设置页**：开关的说明文字改成「关掉后，带单词的配图只显示画面」——「记忆图卡」这个词在 App 的界面上别处都不出现；标题「图片上显示单词」没动。设置页所有带开关的行，开关一律靠右对齐（新开关因为多一行说明，原来和别的开关不在一条竖线上）；说明文字不加粗、放不下会折行。
- **§3.8 工具**：`studio/requirements.txt` 是三个依赖——fonttools、skia-pathops、defusedxml（§3.8 原文少写了 skia-pathops）。`tools/letters` 默认输出**合并过的**不重叠轮廓（字体里 f、t、k、e 由几块重叠的轮廓拼成，合并后幽灵字母的虚线描边不会在字母内部出现重影）；`--raw-outlines` 输出字体的原始轮廓，10 张样例用的是它，`tools/check` 两种都认。`make studio-check` 每次运行都按 `requirements.txt` 核一遍依赖：装齐之后是空操作，第一次装到一半断了的环境下次自动补齐。`tools/check` 的字形校验补了几条——字母和它外层各组的 `transform` 合起来只能是平移、等比缩放和小角度倾斜（5° 以内不提示，5°–15° 警告，超过 15° 报错；镜像、上下翻转、压扁、拉长、斜切一律报错）；看不看得见按填充、描边、透明度沿外层的组继承着判断；出没出画布按字母墨迹的外框量（出界报错，离边不到 20 px 警告）；`-dot` 路径得真是字体里那个点、在原位、跟着字母一起动才算数；任何一张渲染图没出来都是错误（退出码 1）；对照图和总览页改 id 时认得 `url('#id')` 这类写法。导入那道门新加的几条（模糊预算、去掉单词层后自己站得住、`style` 和反斜杠）`check` 跑的是同一份代码，报的是同一句话，没有另抄一份。
