# word-Dance — Frontend contract (React 19 + TypeScript 5.9 + Vite 8, Simplified-Chinese UI)

Package `frontend/`. Pins: `react@^19.3`, `react-dom@^19.3`, `react-router@^7.18` (**not 8**), `vite@^8.3`, `@vitejs/plugin-react@^6.1`, `typescript@~5.9`, `vitest@^5`, `jsdom@^30`; the shell's runtime packages exactly as pinned in mobile/package.json — `@capacitor/core@8.6.0`, `@capacitor/app@8.1.2`, `@capacitor/local-notifications@8.3.1`, `@capacitor-community/text-to-speech@8.0.2` (bump both together, §6.6). Plain CSS (custom properties), no UI kit, no CSS framework, no CDN assets, no web fonts. Data types come verbatim from `API.md` §9 (`src/api/types.ts`). UI copy comes from `src/i18n/zh.ts` (Section 8) and must follow the glossary in DESIGN §0.3.

Import example: `import { StateBadge } from '@/components/word/StateBadge'` (alias `@` → `src`); no component lives directly under `components/`.

Build: `npm run build` → `frontend/dist`; FastAPI serves the files of `dist` itself — `/assets/*` `public, max-age=31536000, immutable`; `manifest.webmanifest` (and a future `sw.js` / `registerSW.js`) `no-cache`, so an install or update check always sees the current one; every other file of the snapshot (icons, `favicon.svg`) `public, max-age=3600` — and answers `index.html` (`no-cache`) for every other non-`/api`, non-`/media` path, **except** a path under `/assets/` that is not a file: that is a 404 `not_found` (a tab left open across a deploy asks for the old hashed chunk and must not receive `index.html` as a script). The installability surface is static (manifest, PNG icons, `apple-touch-icon`, the two `*-web-app-capable` metas): no service worker, no install prompt, no offline cache — on iOS 26 the home-screen bookmark opens standalone by itself, Android Chrome installs from the browser menu. Icons: `cd frontend && sips -s format png -z 192 192 public/favicon.svg --out public/icons/icon-192.png` and likewise 512 from `favicon.svg`, 192/512 `icon-maskable-*.png` and the 180² `apple-touch-icon.png` from `public/icon-maskable.svg` (macOS `sips` renders SVG; on Linux use `npx @vite-pwa/assets-generator` or `@resvg/resvg-js`). Dev: Vite on :5173 proxies `/api` and `/media` to :8000 (same-origin cookies).

## 3. State management

* **Session**: `AuthContext` loads `GET /api/auth/me` once; exposes `user`, `settings`, `server`, `counters` and `refreshCounters()` (re-fetches `/api/auth/me` after suggestion accept/reject/undo, bank adds/import and attention resolution so the badges stay current); `updateSettings(partial)` calls `PUT /api/settings` and replaces the cached object. Every sign-in goes through `applyAuth(res: AuthResponse)` — `user` / `settings` from the response, then one `/api/auth/me` for the server flags and counters — which `login(username, password)` and `register(body)` wrap and the code sign-in (endpoint 81), the stale-phone confirm (83) and dispute (84) call directly; `<RequireGuest/>` redirects the moment `user` is set, so a `CodeLoginResponse` that carries a `challenge` instead of a user never reaches it. While logged out the public `GET /api/health` flags are `health` (`needs_setup`, `registration_mode`, `sms_enabled`, `email_enabled`, `captcha` and — slice 2-A — `wechat_enabled`, `qq_enabled`, `apple_enabled`, the three bools `ServerFlags` carries for a session as well; a WeChat login confirmed through endpoint 113 goes through `applyAuth` like every sign-in, the QQ / Apple redirect flows arrive as a full-page navigation with the cookie already set by endpoint 122). 401 anywhere → context cleared → `/login?next=`. Slice 1-B: `session` (`MeResponse.session`) is kept as `SessionInfo | null` (null while logged out; `applyAuth` resets it and `loadMe` fills it): `session.guardian` drives the shell's 切回家长 bar, `session.gate_until` seeds the 我的孩子 page's gate state. The switches 104 / 105 and the child-device login 107 go through `applyAuth(res)` like every sign-in — never `logout()`, so `auth:signed-out` never fires (the native shell keeps its reminder; `NativeBridge` re-syncs on the new `settings` by itself, §6.6); after 104 the page navigates to `/today` (`<RequireOnboarded/>` sends a fresh child to `/welcome`), after 105 to `/children`.
* **Page data**: `useApi(fetcher, deps)` → `{data, error, loading, reload, setData}`; optimistic updates patch `setData` and roll back on error with a toast.
* **Study session**: `study/queue.ts` pure reducer (Section 5.2) + `StudyPage` effect that flushes pending grades. Pending grade events (with their `client_event_id`) are mirrored to `localStorage['wd.pendingGrades']` and flushed on reload before refetching `/api/today`.
* **Per-viewer conveniences in `localStorage` (never authoritative, all access try/catch)**: last 词库 tab, 译 toggle state, last 筛词 stage, pending grades, the 磨耳朵 options (`wd.listen`: `{mode, sentence, zh, repeat, gapSec}` — per device, so a tablet and a phone can differ; sanitised on every read, §5.9).
* **Polling**: `usePolling(fn, intervalMs, {enabled, max})` — `/api/today` every 30 s while `pending_content > 0` and the tab is visible; `GET /api/words/{id}/content` every 5 s (max 24) for the visible card **only while `content_deferred_until` is null** (a non-null value — budget deferral / AI paused — stops polling and switches the card to the 「明天补齐」 copy, §5.1.5); `GET /api/words/{id}` every 3 s (max 30) for 待校验 / 重新校验中 custom words.
* **Toasts**: `useToast()` global queue, bottom-centre, ≤ 3 visible; undo toasts carry an action and a countdown (8 s for 已掌握, 5 s for list toggles). On a page with a sticky grade / verdict bar (`StudyCard`, `ScreenCard`) the bar publishes its reach through `useBottomBarOffset` (`--bottom-bar-h` + `html.has-bottom-bar`) and the toasts stack above the buttons instead of covering 认识 / 不熟悉.

1. **Front**: headword, phonetic, 🔊 (auto-pronounce if `settings.auto_pronounce`), stage chips, kind badge (复习 / 新词 / 推荐词 / 加练). 提示 reveals a cloze of the first example (headword/forms → `___`). `screen` items show 推荐词 and the buttons 认识 / 不熟悉 / 跳过 directly (no reveal). **单词之舞** (`settings.dance_mode !== 'off'`, §6.5): the headword is a `DancingWord` with the word's `DanceSpec`; whenever a card shows — the front face of a 新词 / 复习 / 加练 card, however often the word has been reviewed, and a 推荐词 card alike — the letters enter syllable by syllable and the syllables beat (the stressed one highest), the syllable chips under the word mark the stressed one; 🔊 and `P` replay it at any time, the reveal does not. A 推荐词 card plays the spelling + stress dance only: its header never gets the semantic (no stage object, pose colour or ghosts, 🔊 / `P` replay `'form'`), also after the peek, so a word's first show gives away its spelling and never its meaning (until 2026-11-16 推荐词 did not dance at all and 复习 / 加练 cards only while `srs.repetitions < 3` — the owner asked for every card to dance on show).
2. **Reveal** (tap, 显示释义, Space): with `dance_mode === 'full'` and a `dance.semantic`, the headword on the back performs its meaning once as the face mounts (语义舞, §6.5: up rises, in walks into a box) — never on the front, so the meaning is not leaked before the learner has tried to recall it; back shows `meaning_zh` (or ECDICT translation when content is missing), image (if `show_images`; a 记忆图卡 without its word layer when `image_word` is off — `WordImage`, §4), examples (highlighted, Chinese behind 译 unless `zh_examples='always'`), collocations, 记忆 (`memoryLines`, §4: with the picture shown — `show_images` on and the picture not failed to load — and an `image.hook_zh`, the picture's hook and under it, quieter, `image.note_zh` — also while the examples are still pending, deferred or failed, because the hook comes with the picture; otherwise `content.mnemonic_zh` once the content is ready), 易混 chips (from accepted `confusable_group` suggestions), collapsible 词典释义 (ECDICT definition/translation), SRS line, and the preview 「下次：模糊 → 明天 · 记住了 → 3 天后」 computed by `utils/srsPreview.ts` (same formulas as `srs.py`; verified against `GradeResponse.next_due_zh` in tests).
3. **Grade bar**: 不熟悉 (red, key 1) · 模糊 (amber, key 2) · 记住了 (green, key 3); secondary 已掌握 (outline → primary with 建议 badge when `mastery_suggested`, key 4) · 跳过 (text, key S). 已掌握 when suggested acts immediately with an 8-s 撤销 toast; 撤销 calls `POST /api/words/{id}/mark {action:'restore', context:'today'}`, which puts the exact prior SRS state back and re-opens the card (the reducer's `restore(itemId)` returns it to the queue; toast `study.restored`); a 409 `undo_expired` shows `errors.undoExpired`. The deliberate re-add from the 已掌握 list later is `{action:'unfamiliar'}` (re-add semantics). When not suggested a `ConfirmDialog` appears first («确定已掌握？该词将移出生词库，随时可在「已掌握」中恢复。»). `P` pronounce, `Z` toggle 译, `H` hint.
4. **Requeue**: after 不熟悉 / 模糊 or 记住了 on a new card (an **intermediate** grade: `GradeResponse.item.result === null` and `requeue_at` set — API.md 45), toast 「10 分钟后再见」 and the item **stays ungraded**: it remains in the reducer's `order` (never enters `graded`), re-enters the visible queue ≥ 10 cards later or at the end, and is shown when `requeue_at ≤ now`, otherwise the session waits with 「还有 1 个词将在 N 分钟后复现」 and a 现在就复习 link; the second grade is a new event with a fresh `client_event_id` and the server answers 200 (the item is only *done* when a grade returns a non-null `result`; `done/total` counts those). A 推荐词 graded 不熟悉 whose `GradeResponse.study_item` is non-null is appended to the end of the local queue as a 新词 card (toast `screen.addedToday`); null → toast `screen.addedTomorrow`.
5. **Content pending**: if `content_state === 'queued'` and `content_deferred_until === null` the back shows dictionary data + skeleton lines + 「例句生成中…」 and polls; if `content_deferred_until` is set (today's AI budget is spent, or AI is paused — API.md 24) the back shows the dictionary data **without** a skeleton, the notice `study.contentDeferred` 「今日 AI 额度已用完，例句将在明天补齐」, no polling and **no** 「生成例句」 button; `none`/`failed` → 「今天的例句暂时生成不了，先用词典释义学习」 plus a 「生成例句」 button (`POST /api/words/{id}/content/request`, then polling resumes; 409 `budget_exhausted` → toast `errors.budgetExhausted` and the card switches to the deferred copy, 503 → `errors.aiDisabled`, 60/day). The card is always usable.
6. **Optimistic grading**: the card advances immediately **and the event `{client_event_id, grade}` is POSTed at once** — there is no client-side undo window for grades (a posted grade with a fixed `client_event_id` cannot be reversed by replay); the only undo is 已掌握's 8-second 撤销 toast, which is a *server* `restore` (point 3). On network failure the event stays in `pending` and retries with backoff (1 s, 3 s, 10 s…); banner 「有 N 个结果待同步」 when the backlog > 1 for > 10 s. 409 `item_already_graded` is treated as success (refetch).
7. **Session summary** (`SessionSummary`): ring completes, counts (复习 26 · 新词 10 · 推荐词 15), 不熟悉 words list (chips → detail), 「连续学习 13 天」, buttons 再来一组新词 / 再筛一组推荐词 (while `can_request_more`) / 去筛词 / 回到今日. Calls `POST /api/today/complete`.
8. `?batch=<id>`: `batch.gradable === true` (today's batch, or yesterday's while it has ungraded items — the 「继续昨天的学习」 entry) → the normal session on the ungraded items with the grade bar; `false` → read-only replay: no grade bar, outcome chips shown.

### 5.2 Queue reducer (`study/queue.ts`, pure, vitest-covered)

State `{batchId, order: itemId[], cursor, revealed, requeue: {itemId, at}[], pending: GradeEvent[], graded: Record<itemId, result>, startedAt}`. Actions: `load(items)` (ungraded first, skipped after unskipped; an item with `requeue_at` set goes to `requeue`, not `graded`), `reveal`, `grade(itemId, grade, response)` — **final** (`response.item.result !== null`): moves the item to `graded`; **intermediate** (`result === null`, `requeue_at` set): removes it from the visible position and inserts it into `requeue` (it stays in `order`, never in `graded`); either way appends `response.study_item` to `order` when present — `skip(itemId)` (moves to the end), `tick(now)` (pulls due requeues back into `order` at `cursor + 10` or the end), `flushPending`, `restore(itemId)` (after a successful server `restore`: removes the item from `graded`, re-inserts it at `cursor`). There is **no** `undo` action: grades are posted immediately (§5.1.6) and undo exists only as the server `restore`.

### 5.3 Today page (`/today`)

Before a batch exists: 「今日词汇将于 08:00 推送」 + 立即生成 (`POST /api/today/build`) — the only build path besides the scheduler (再来一组 is disabled in this state: API 46 answers 409 `batch_not_ready` → toast `today.buildFirst`). While `building`: items are shown immediately and 再来一组 works; the header shows `today.pending(n)` 「N 个词的例句生成中」 **only while `counts.pending_content > 0`** (budget-deferred and AI-paused items are not counted, so the notice disappears when nothing is generating). When `previous_open_batch` is non-null a card 「继续昨天的学习（还剩 N 个）」 (`today.continueYesterday`) links to `/study?batch=<id>` — this is how a late session is finished after midnight (API.md 43/45); it is shown above today's CTA and also in the `status:'none'` state. After completion: 「今日完成 🎉 明天 08:00 见」 (`today.seeYou` is time-neutral: push times run 00:00–23:59) + 再来一组 + 去筛词 + 去词库. 顺延 note when `deferred_reviews > 0`. **磨耳朵**: while the batch holds a review / new / extra word that is still in the bank (`batch.items.some((it) => it.kind !== 'screen' && (it.mine?.state === 'new' || it.mine?.state === 'learning'))` — the rule of the playlist itself, endpoint 123: the word's state now, not the item's grade) the secondary block button `today.listen` 「磨耳朵」 → `/listen` sits directly under the CTA (`btn--secondary btn--lg btn--block`), and the 「今日完成」 card carries the same link — words already graded can still be listened to; a batch of 推荐词 only, a day whose words have all left the bank (marked 已掌握 / 已认识, or removed), or no batch, has no entry, so the entry never opens an empty list (§5.9).

Batches of 30 with 再筛 30 个. Each verdict posts `POST /api/screen/verdict` with a `client_event_id`; 不熟悉 toast 「已加入生词库」, or 「已加入生词库，今天就学」 when `added_to_today` (the returned `study_item` is a second `kind='new'` row for the same word — inside a running study session it is appended to the local queue), or 「已加入生词库，明天开始学」 when today's new-word quota is full.

`GET /api/today/playlist` (endpoint 123, `ListenPlaylist`: today's review / new / extra words in batch order, one row per word, without the words that have left the bank since — 已掌握 / 已认识 / removed) is loaded once with `useApi`. The page only reads: nothing is graded, nothing is written, the streak and the today badge are untouched. It is bare (no shell) and laid out like the study session: head (回到今日 · 磨耳朵 · 「i / n」) with a progress bar, the mode `Segmented` 跟着听 / 听写 and its options, the stage, the sticky transport bar (`useBottomBarOffset`).

1. **跟着听** (`mode: 'follow'`): per word the headword (`spoken_en`, the learner's accent, rate 0.92) → the Chinese gloss (`gloss_zh`, `zh-CN`, rate 1; switch 中文) → the example sentence (`sentence_en`; switch 例句) → its translation (`sentence_zh`; both switches) — 350 ms between segments, 900 ms between words; a part the row lacks (`null`) is left out. The stage shows `display`, `/phonetic/`, `meaning_zh` (the dictionary-style meaning is *shown*, the gloss is what is *read*) and, with 例句 on, the sentence and its translation; the line being read carries `.is-active` and `aria-current`. Both switches off = the words in a row.
2. **听写** (`mode: 'dictation'`): per word the headword `repeat` times (每词读 1 / 2 / 3 遍, default 2), each reading followed by `gapSec` seconds of writing time (间隔 3 / 5 / 8 / 12 秒, default 5); no Chinese, no sentence. The stage shows only 「第 i 个」, one dot per reading and 「听到单词后写下来」 — the word, its phonetic and its meaning are **not in the DOM** (nor in the Media Session title) until the end, playing or paused. A row with `spoken_en: null` is skipped. After the last word 「对答案」: a numbered list of every word (`display`, `SpeakButton`, `meaning_zh`), 再听写一遍 and 回到今日. A word whose headword was never read through in this run — nothing could read it, the row has no `spoken_en`, or the learner moved on with 下一个 before it ended (`ListenState.unread`) — carries the muted tag 「没读」 (`listen.unread`, a `.badge`), so the learner checking the paper knows which row to skip; a word that failed once and was heard on a later try is not marked.
3. **Start**: playback starts by itself when the playlist arrives. A browser that refuses sound before a tap (iOS Safari — `utter` answers `blocked`) parks the player in `blocked`: the stage offers the button 「点一下开始播放」 (the play button works too), `play()` runs inside that tap, and the chain needs no further taps (one shared `<audio>` element, §6.4). Inside the Capacitor shell no tap is needed at all. The same parking spot serves a clip the browser pauses by itself in mid-playlist (audio focus lost to a call or another app, the headset unplugged — `utter` answers `blocked` for it too): the page shows the play button and 「点一下开始播放」 instead of a 暂停 button over a dead chain, and one tap reads the current word again.
4. **Transport**: 上一个 / 播放 · 暂停 / 下一个 (icon buttons with `aria-label`) and 重新开始; keys Space (play / pause) and ← / → (previous / next). Resuming after a pause, and every changed option or mode, re-reads the **current word from its first segment**; previous / next while paused only move. 下一个 on the last word ends the playlist. At the end 跟着听 shows 「听完了」 with 再听一遍 and 去学习 (→ `/study`). On both finished screens the keyboard is off and previous / next do nothing (the headset's play key is ignored on the answer sheet as well), so a stray key cannot take the answers away; changing 遍数 / 间隔 keeps the sheet, switching the mode goes back to the first word without playing (no answer sheet for a dictation that never ran — the page tells the player in the same batch as it stores the option, so the other mode's finished screen is never painted in between). The finished screens replace the transport bar, so a keyboard focus that sat on it falls to `<body>`: the screen's heading (对答案 / 听完了, `tabIndex={-1}`) then takes it — announced, and Tab goes on from there; a focus that is still on a control (the mode, 遍数 / 间隔) is left alone.
5. **What cannot be read**: `utter` (§6.4) answers `unspoken` when no route could read a segment; it is skipped at once (no pause after it; in 听写 the word is not tried again and gets no writing time), counted once however often its word is re-read, and the page says 「有 N 段没能读出来」 (`listen.skipped`). Chinese that neither the server (`ServerFlags.audio_zh`) nor the device can read (`utterAvailable('zh-CN')` false) is left out of the chain up front with the note 「这台设备读不了中文，只播放英文」 (`listen.noZh`; the 中文 switch keeps the stored preference). Where that cannot be known beforehand — the app shell until its plugin has refused the language, a voice list that is still empty, a server Chinese clip that fails in mid-session (`zhOff`) — the first Chinese segment is tried once; when it fails the note appears and the player takes the options without Chinese with `setOptions(effective, {reread: false})`: the word being read is **not** started over, its Chinese still to come is skipped, and the Chinese segments already counted are forgotten, so no 「有 N 段没能读出来」 stands beside the note. **A server out of reach** (`utter` answers `offline`, §6.4: the clip could not be fetched even after two more tries, or the session is gone, and the device cannot read the segment either) is not a segment to skip — every later one would fail the same way and the playlist would run out in a second, the 听写 answer sheet appearing in mid-dictation: the player parks on the current word (`status: 'paused'`, `offline: true`, nothing counted) and the stage says 「连不上服务器，点播放再试一次」 (`listen.offline`) until 播放 tries that word again. Nothing can read English → the state 「这台设备现在读不出声音」 + 去学习; no listenable word (or no batch) → 「今天还没有可以听的词」 + 回到今日; a failed load → the head (回到今日 — the route is bare, so it is the only way out) with the error + 重试.
6. **Options** live in `localStorage['wd.listen']` as `{mode, sentence, zh, repeat, gapSec}` (`useLocalPref`; per device, never synced); `sanitizeOptions` replaces every missing or out-of-range field by its default `{follow, true, true, 2, 5}`.
7. **Leaving and backgrounding**: unmounting the page disposes the player and silences the voice (`stopUtter`); a hidden tab or a dimmed screen is **not** paused. While playing, `listen/screenAwake.ts` holds a Screen Wake Lock where `navigator.wakeLock` exists (secure contexts only — not on a plain-http LAN origin; asked for again when the page returns to the foreground), and `listen/mediaSession.ts` binds play / pause / previoustrack / nexttrack for headsets and the lock screen and names what is playing (the word in 跟着听, the position in 听写); both are feature-detected no-ops elsewhere and fail silently.

**`listen/player.ts`** (pure, vitest-covered): `segmentsFor(item, options)` → the `word` / `gloss` / `sentence` / `sentenceZh` / `gap` segments of one word; `class ListenPlayer` with the injected `{utter(text, 'en' | 'zh'), stop(), wait(ms, signal), onChange(state)}` and `load(items, options)`, `play()`, `pause()`, `toggle()`, `next()`, `prev()`, `seek(i)`, `restart()`, `setOptions(o)`, `dispose()`; state `{status: 'idle' | 'playing' | 'paused' | 'blocked' | 'finished', index, segment, round, unspoken, offline, unread}` (`offline`: paused by the player itself because `utter` answered `offline`, false again once it plays or the playlist ends; `unread`: once finished, the 0-based indexes of the words whose headword was never read through in this run — kept as the complement of a `heard` set that `load()`, `restart()` and the mode reset clear, not derived from the unspoken count, which never forgets a miss). One chain runs at a time: every transport call bumps a generation number, aborts the wait in flight and stops the voice, so an older chain that wakes up later returns without touching the state; every chain starts in one place, which refuses a disposed player (its status may still say `playing`). `setOptions` re-reads the current word only when the change alters what is read (the mode, or a field that mode uses — 例句 / 中文 mean nothing to 听写, 遍数 / 间隔 nothing to 跟着听); with `{reread: false}` (Chinese that turned out to be unreadable, item 5) it never does. The first `utter` of a chain is called synchronously inside `play()`, so the tap's gesture covers the first clip. The page maps `'en'` to `settings.accent` at `DEFAULT_RATE` (0.92) and `'zh'` to `zh-CN` at rate 1.

### 6.4 Pronunciation (`hooks/useSpeech.ts`, `audio/serverAudio.ts`, `audio/utter.ts`)

Three routes, chosen per call by `speechRoute(accent)`:

```ts
export function speechRoute(accent: Accent): SpeechRoute | null {
  if (isNative()) return 'native';                                        // the shell's TTS plugin (§6.6)
  const synth = speechSupported();                                        // speechSynthesis + SpeechSynthesisUtterance exist
  if (synth) {
    const voices = window.speechSynthesis.getVoices();
    if (voices.length === 0 || pickVoice(voices, accent)) return 'synth'; // an English voice is listed (exact lang first — a Premium / Enhanced voice, then Google/Microsoft/Samantha/Daniel —, else any 'en') — or no list yet: Chrome fills it asynchronously, the browser default speaks meanwhile
  }
  if (serverAudioEnabled()) return 'server';                              // the list has no English voice and ServerFlags.audio says GET /media/audio has a provider
  return synth ? 'synth' : null;                                          // the browser default; null = nothing can speak
}
```

One voice at a time: every call first silences the others (`stopServerAudio()`, `speechSynthesis.cancel()`; the plugin flushes itself). **synth**: `new SpeechSynthesisUtterance(text)` with `lang`, the picked voice and `rate` (0.92 by default), then `speak()`; voices load asynchronously (`voiceschanged`), and the first user gesture unlocks audio on iOS — naturally satisfied because `speak()` is always triggered from a click/key handler. **native**: `speakNative` (same `rate`); when the plugin rejects — no TTS engine the plugin can reach (the Android container of HarmonyOS NEXT answers code `UNAVAILABLE` for ever: the plugin initialises its engine once at launch and never retries), no English voice, an engine error — the server clip speaks instead if `ServerFlags.audio` is true. **server**: `playServerAudio(text, accent, rate)` sets the clip URL `GET /media/audio?text&accent[&v=<ServerFlags.audio_key>]` (`clipUrl`; the server ignores `v` — a switched provider or voice is a new URL for the week-long browser cache; `diagnose` fetches the same URL) as the `src` of one shared `<audio>` element and calls `play()` synchronously — still inside the tap, so autoplay policies are satisfied however long the server takes; same-origin, so the session cookie goes along, the browser's HTTP cache keeps a clip for a week and the site's CSP (`default-src 'self'`, no `blob:`) allows it — at `playbackRate = rate` (pitch preserved), and resolves when the clip ends or when a later play / stop cuts it short (resolved, not rejected, like `speakNative`). Two ways a clip would otherwise never settle are watched for: the user agent pausing the element by itself in mid-clip (audio focus lost to a call or another app, the headset unplugged) rejects `paused` — a `pause` event on the current clip while the element is `paused` and not `ended`, so neither the `pause` every natural end fires before `ended` nor the stale event of the app's own `pause()` landing on the next clip counts —, and a clip that has not fired `playing` within `STALL_MS` (20 s: the server may hold a request 8 s for a slot, plus the synthesis) of `play()` rejects `network` without a diagnosis, which would hang on the same network. When the server refuses the clip, `pronounce` falls back: `{reason:'off'}` switches the route off for the session and the browser default voice speaks (as before clips existed); `{reason:'missing'}` — the server's read-only `cache` provider lacks this one clip — lets the browser default speak this text only, the route staying on; the shell, which has no `speechSynthesis`, hears the toast instead. A diagnosis a newer call overtook reports `interrupted`, never its reason, so the hook cannot speak the older text. Only when the element fails is the URL fetched once more to learn why (`diagnose`: 503 `audio_unavailable` → `off` / `missing` / `busy` / `failed`, 400 → `invalid`, 401 → `auth`, 429 → `busy`, a 200 → `decode` — the server serves it, the device cannot play it, no response → `network`). `off` switches the server route off for the session (`setServerAudio(false)`; `AuthContext` sets the flag, the key and the Chinese flag (`setServerAudio(audio, audio_key, audio_zh)`) from `/api/auth/me` on every load, so the module-level `speak()` of auto-pronounce / key `P` knows it without the context — and the next `/me` reflects whatever the restarted server says); a browser that still has `speechSynthesis` then falls back to its default voice, silently, as before clips existed.

**What the learner hears about it** (the hook only; the module-level `speak()` stays silent) — one copy per cause (`speechFailureCopy`): `zh.word.voiceFetchFailed` (`network`: check the connection), `voiceBusy` (`busy`: the two synthesis slots, the waiters' cap or the 60 misses / minute budget), `voiceServerFailed` (`failed`: the provider broke — the server log says why), `voiceTextUnsupported` (`invalid`: the server refused the text), `voicePlayFailed` (`decode`: the device cannot play the clip), `voiceMissing` (`off`, or the plugin rejected without a server to turn to: no English voice on the device and none on the server), `voiceClipMissing` (`missing`: the server's read-only cache has no clip for this text and the device has no voice either), nothing for an autoplay refusal (`blocked`), a clip the browser paused by itself (`paused`), a lost session (`auth`, which `client.ts` announces itself) or a call a later tap superseded (the hook numbers its calls: only the latest owns `speaking` and the toast). `supported` (→ `SpeakButton` disabled state) = speechSynthesis, the shell, or the module flag `serverAudioEnabled()` — true once `/me` lands, false again after a 503 `off`. Tests: `hooks/useSpeech.test.ts` (routes incl. the empty voice list, the browser-default fallback, the hook without speechSynthesis, copy per reason, one voice at a time, the double tap), `hooks/useSpeech.native.test.ts` (the plugin → server fallback and its copy), `audio/serverAudio.test.ts` (the URL played synchronously, the `v` fingerprint on it, the diagnosis, interruption, `paused` with its two guards, the stall watchdog, `serverAudioSpeaks` per language and the session's `zhOff`), `auth/AuthContext.test.tsx` (`/me` → `setServerAudio`), `components/word/SpeakButton.test.tsx` (enabled by the server flag alone).

**磨耳朵's voice (`audio/utter.ts`, §5.9)** — `useSpeech` cannot be chained: its browser route returns at once and it prefers the device's voice. `utter(text, lang: SpeechLang, rate): Promise<'ended' | 'unspoken' | 'blocked' | 'offline'>` (`SpeechLang = Accent | 'zh-CN'`, `audio/serverAudio.ts`) reads one segment and resolves when it is over. It never rejects, and it is synchronous up to `play()` / the plugin call / `speak()`. The route order is the reverse of `speechRoute` — a playlist wants the same voice on every device, clip after clip without further gestures, and Chinese on a device that has no voice at all:

1. **server**, when `serverAudioSpeaks(lang)`: English = `ServerFlags.audio`; Chinese = `ServerFlags.audio_zh` (the provider has a Chinese voice; the clip is `GET /media/audio?text&accent=zh-CN`) and no Chinese clip has come back `failed` / `invalid` in this session (`zhOff`, set by `diagnose` — a server without the voice, an older server that knows no `zh-CN`, or a page loaded in the first seconds after a server start, when the flag is optimistic (API.md §9.1) and the server turns out to have no Chinese voice, is asked once, not once per word; English is untouched). `busy` is asked once more after 1.5 s; `network` (the clip could not be fetched at all) is asked again 1.5 s apart while the segment is younger than 3 s — two more tries, which an ordinary restart of the service does not outlast; a request that hung until the stall watchdog is not asked again, and once a clip has stayed out of reach through its retries the following ones are asked once each until a clip plays again, so a long outage costs the wait once, not per segment; `blocked` (autoplay refusal) is returned at once — no other route would be allowed to speak either — and so is `paused` (the browser paused the clip by itself: a tap plays it again); `interrupted` is `ended`; every other failure falls through to the device.
2. **native**, inside the shell: `speakNative(text, lang, rate)`, until the plugin has rejected the language — remembered for the session; code `UNAVAILABLE` (no engine) rules out both languages.
3. **synth**: English with `pickVoice`, Chinese with `pickZhVoice` — a `zh-CN` / `zh-Hans…` / `cmn…` voice (Premium / Enhanced first), else another `zh` voice (Mandarin before Cantonese); a known list without one is not spoken at all (an English voice reads Chinese as silence), an empty list (Chrome fills it asynchronously) lets the browser pick by `lang`. The utterance is settled by `onend` / `onerror` (`not-allowed` → `blocked`, `interrupted` / `canceled` → `ended`, anything else → `unspoken`) and by a watchdog of 4 s + 0.35 s per character, at most 30 s — a started utterance that lost its `onend` (Chrome, long remote-voice utterances) counts as heard, one that never started (iOS outside a gesture) as `unspoken`; the utterance stays referenced until then so it is not collected.
4. nothing → `unspoken` — or `offline` when the server route ended with `network` or `auth` (401: the session is gone) and no device route read the text: the server could not be asked, so the next segment would fail the same way, and the caller parks instead of skipping (§5.9 item 5). A device that does read the text answers `ended` as always.

`stopUtter()` and the next `utter()` cut whatever is being read on every route; the cut call resolves `ended`, and the caller's own generation number (`listen/player.ts`) tells whether to go on. `utterAvailable(lang)` answers "may some route read this language right now" — optimistic for the plugin until it has refused and for a voice list that is still empty — and drives the listen page's no-voice state and its `noZh` note. `useSpeech`, `SpeakButton` and auto-pronounce are unchanged: the device's voice first. Tests: `audio/utter.test.ts` (the route order and the synchronous first `play()`, the busy retry, the network retries and `offline`, `blocked` and `paused`, the refused plugin, the events and the watchdog of the browser route, the Chinese voice pick, interruption, `utterAvailable`), `audio/utter.server.test.ts` (over the real `serverAudio`: English and Chinese clips chained on the one element, `blocked` then the tap, `stopUtter`, a refused Chinese clip asked once, a clip the browser paused, a server out of reach asked again and then `offline`, a clip that never starts).

### 6.5 单词之舞 (`components/word/DancingWord.tsx`, `dances.ts`; docs/WORD_DANCE_DESIGN.md §4.1–4.2)

The headword of the study card and the detail page is a `DancingWord` when `settings.dance_mode !== 'off'` and the word has a `DanceSpec` (API.md §9 / §9.1: derived server-side from display + phonetic, `null` for phrases and words without a transcription). Two dances, both pure keyframe plans (`dances.ts`) fed to `element.animate()` — only `transform` / `opacity` / `color`, so they composite: **拼写舞** — the letters enter in reading order (85 ms apart, 55 ms for words of 8 letters or more, +150 ms — 120 ms for those long words — at every syllable boundary, `fill: 'backwards'`); **重音舞** — the syllables then beat in turn (300 ms each, the stressed one 330 ms), the primary-stressed one jumps highest (−0.6em, ×1.18, `--dance-accent` = `--brand-ink`), silent letters stay still and muted (`.dword__l--silent`), doubled letters jump together once more (`twinPlan`). No 小学 word exceeds 2.5 s (`danceDuration`; `dances.test.ts` pins the worst shapes: January, February, tomorrow, umbrella). **When it plays**: whenever a study card shows — the front face of a `new` / `review` / `extra` card (no repetition limit) and a 推荐词 (`screen`) card, which `StudyCard` gives the spec with `semanticEnabled={false}` — when the word detail page opens a word (`WordDetailPage` passes `autoplay` = `'full'` in `dance_mode` `'full'`, else `'form'`: the page shows the meaning anyway; the header mounts once per loaded word, so a reload of the page's data plays it again and unrelated state does not), and on 🔊 / key `P` at any time — `StudyPage` passes `danceAutoplay` (`dance_mode !== 'off'` and a current card) (`DancingWord` plays it in a mount-only layout effect, before the first paint, so the word never flashes whole) and owns `danceToken` for key `P`, `WordHeader` adds the 🔊 replays on top; a remount (the reveal) does not replay the spelling + stress dance — the back face's `autoplay` is `'semantic'` only, and `DancingWord` replays only on a token that moves after mount. 🔊 keeps working where nothing can pronounce (no `speechSynthesis`, no shell, no server clips): `SpeakButton` stays enabled for the replay with the label 再跳一次 and just skips the speech; with server clips (§6.4) it speaks as well. **Static fallback**: no `element.animate` (jsdom) or `prefers-reduced-motion` → `.dword--static`, plain letters with the stressed syllable in `--brand-ink`, so the information survives without motion. The syllable chips (`<ol class="syl" aria-label=音节>`, `rab · bit`, stressed chip filled) show whenever the spec has two or more chunks; a one-chunk spec shows none. Sound and motion run in parallel, not in sync (Web Speech has no timing events worth using); the dance works without speech (Android WebView). **语义舞** (P2): a spec with `semantic` (`source: 'claude'`, chosen by `generate_dance` from the 30-primitive library — 28 at P2, `hop` / `onto` added by P3 —, API.md §9 `DancePrimitive`) plays its one meaning motion when the BACK face mounts at the reveal (`StudyCard` passes `autoplay="semantic"` there when `danceAutoplay` holds and `dance_mode === 'full'`), never on the front; 🔊 / `P` on the back replay `'full'` = spelling + stress + meaning, on the front `'form'` only. `dances.semanticPlan` maps each primitive to one motion (word-level: grow / shrink / spin / thud / float / stretch / squash / hop / enter / exit / arc / onto / under / behind / between / repeat / dim / glow; letter-level: rise / fall / dash / creep / split / join / shiver / shimmer / wave / droop / color; `multiply` fans ghost copies out and back), ≤ 2.5 s, em-based so it fits the card at 360 px; seven primitives stand on a small stage object drawn by CSS (`.dword-stage--box|roof|shelf|table|tree|bars`; the `onto` shelf sits behind the in-flow letters through an isolated stacking context, so descenders paint over it); `poseColor` gives cold / hot / sad and the colour words a rest colour that also serves as the static fallback (no size or letterform change, design principle 5). `dance_mode === 'form_only'` (`semanticEnabled=false`) drops the object, the ghosts, the pose and the motion. The setting lives in 学习设置 as the three-way segmented 「单词之舞」 全部 / 只拼读 / 关 (`dance_mode: 'full' | 'form_only' | 'off'`, P3; `settings.danceModes`).

### 6.6 Native shell (`native/capacitor.ts`, `native/NativeBridge.tsx`; docs/MOBILE_APP.md)

The same build is loaded by the Capacitor remote shell in `mobile/` (iOS / Android). `isNative()` is `Capacitor.isNativePlatform()`; in a browser it is false and every function below is a no-op, so nothing changes for web users. In the shell: `NativeBridge` (mounted once in App.tsx under the router and AuthProvider) installs the listeners — Android back button (history back, else minimise), resume, notification tap → navigate to its path — tags `<html>` with `native` / `native-<platform>` (`global.css` gives `.auth` / `.welcome` the top inset), and keeps the device's daily reminder in step with the settings: `syncDailyReminder(settings)` cancels notification 1001 and, when `push_enabled` and notifications are granted, schedules it daily at `push_time` converted from `settings.timezone` to the device clock (`localReminderTime`), title / body from `zh.native`, `extra.path = '/today'`; the notification is scheduled inexact (`isExactNotification: false` — the plugin's exact default opens the system alarm-settings page from `schedule()` on Android 14+); it runs once the session is known (never while `/api/auth/me` is loading and never because it failed or the session expired), on resume of a known session and whenever `push_enabled` / `push_time` / `timezone` change; only an explicit sign-out cancels it (`AuthContext.logout()` dispatches `auth:signed-out`, `client.ts` `AUTH_SIGNED_OUT_EVENT`).
