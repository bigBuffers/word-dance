## 3 词集变化

### 3.1 定义（PLAN §0 / §4.2）

| 阶段 | 成员 |
|---|---|
| `xs` 小学 | 国家 2022 课标二级 505（含括注变体）∪ 2022 附表 {基数词、序数词（单 token）、月份、星期} ∪ `be/do` 人称形式继承（`am, is, are, does`） |
| `zk` 初中 | `xs` ∪ 国家三级 1600 ∪ 2022 附表 {地理名称及派生、缩写、节日、地名景点、其他专有名词} ∪ 上海 2020 单词表 ∪ 上海附表 ∪ 上海词组（ECDICT 有条目且过严格门者，`kind='phrase'`） |
| `gk` 高中 | 高中课标 2025 修订 3100 ∪ 2020 修订 3000（显式并集；两份国家名称附表只存档） |
| `cet4` / `cet6` | 不变（现有行逐字保留；新行取 ECDICT 标签） |

不规则动词附表不授予成员；`xs ⊆ zk` 由构建器断言；**`zk ⊄ gk` 是事实**——高中表去掉了大量初中日常词，上海词组又只在初中。反例数以这条 SQL 为准，不是常量：
`select kind, count(*) from words where stage_zk=1 and stage_gk=0 group by kind`。在交付种子（`stats.json.content_sha256` = `24f3b949…6692`，9,618 条）新导入的库上共 **544** 行：
`phrase` 376（上海词组）· `word` 156（`chopstick`、`mooncake`、`qipao`、`twenty-first` …）· `abbreviation` 7（`PLA`、`UNESCO`、`WTO` …）· `proper_noun` 5（`Italy`、`Paris`、`Singapore` …）；
其中 430 行只有初中一个旗标（= `stats.json.only_stage.zk`）。PLAN §4.4 / §6 的「212 个单词（+ 333 个词组）」是设计期按词头的估算，口径与这条 SQL 不同，不要拿它对数；
`stats.json` 没有这个键，以这条 SQL 为准。所以「高中生」预设仍是 初中 + 高中 而不含小学，「仅高中新增」也不等于「高中减初中」。

### 3.2 数字去哪里看

- 每阶段累计词数 `stats.json.per_stage`，「仅本阶段新增」= `first_stage`（`stage_min = <索引>`），课标外 = `first_stage.none` / `stageless`，多词条目数 = `per_kind.phrase`
  （含附表里的多词地名、节日等，不只是上海词组），上海词组数 = `lists["shmeea20:phr"].members`（= `tokens["shmeea20:phr"]`），令牌计数 = `tokens`。
  交付种子的实际值（`stats.json`）：`per_stage` 小学 600 · 初中 2,549 · 高中 3,260 · 四级 4,722 · 六级 7,671；`first_stage` 600 / 1,949 / 1,255 / 1,726 / 3,850 / NULL 238；
  9,162 → 9,618 行（`total_words`；`new_words` 456 = `total_words` − 迁移前的 9,162 行，其中上海词组 334 = `lists["shmeea20:phr"].members`，不是 `per_kind.phrase` 395）。PLAN §4.8 的设计期复算（2,548 / 1,948 / 9,617 / 455 / 333）与之差 ≤ 1 行，在 ±1% 容差内。
- 旧 → 新的 `stage_min` 迁移矩阵与逐词清单在 `data/seed/DIFF.md`；`wd import-seed --dry-run --report <path>` 对线上库给出同一矩阵（上线第 7 步要与排练一致）。
- 对现有数据的影响（在线上副本上复算）：两位用户的 77 个生词 **0 个**失去阶段；49 个有 AI 内容的词 0 个失去阶段；课标外词 0 个被持有、0 个有内容或图。

### 3.4 种子与导入的其他变化

- `main.seed_check` 捕获一切导入异常，记 `system_events('seed_import_failed')` 后**继续启动**（旧行为是重启循环）。

## 6 上线步骤（Mac launchd；= PLAN §8）

数据目录 `D=/Users/sqin/word-dance-data`；服务 `com.word-dance.server`，备份代理 `com.word-dance.backup`；所有 `wd` 命令需 `export WD_DATA_DIR=$D`。
排练的输入必须是**持久**的：PLAN §7 的 `$SCRATCH`（`/private/tmp/claude-501/…/<会话>/scratchpad`）是一次性会话目录，随会话消失，Lighthouse 上也不存在——第 0 步用你自己选的私有目录 `$M`，库拷贝取自线上库（服务停着时 `cp $D/word-dance.db`；不停机则 `VACUUM INTO` 一致副本，见下），ECDICT zip 在 `deploy/fetch_ecdict.sh` 的下载位置（`$D/tmp/ecdict-sqlite-28.zip`）或你保存它的目录核对。
**`wd serve` 启动即执行迁移，所以顺序必须是：先备份、再停、再切、再起。** 0011 与 0013 是表重建，不可在服务运行时应用；0012 纯附加。

0. **预检**（不停机）：S7 的 §7 门禁全部通过；S5 已合入（否则按 §5 末条处理）；`shasum -a 256 <ecdict-sqlite-28.zip 的保存路径>` 等于 `deploy/fetch_ecdict.sh` 钉死的 `ea01f76a…f3f6`（只在要重建种子时需要；上线本身不读 ECDICT）；管理页任务列表没有在飞的 `claude` 调用；选无人学习的时段（回滚会丢失迁移后的学习记录）。
   排练（本机；Lighthouse 部署前在目标机再做一次）。**顺序与 PLAN §2.5 第 2–3 步有一处不同：拷贝上不要先 `wd migrate`——排练脚本自己应用这三个迁移并对比迁移前后，先迁过的拷贝只会让它 `[skip] 0011 row-level +1 comparisons`，排练就失去了意义。**
   ```sh
   M=<私有目录>; .venv/bin/python -c "import sqlite3; sqlite3.connect('$D/word-dance.db').execute(\"VACUUM INTO '$M/word-dance.db'\")"   # 不停机的一致副本（服务停着时直接 cp 也行）；排练永远不写 $D
   WD_DATA_DIR=$M .venv/bin/wd migrate --dry-run                      # 只看清单：恰好 (11,'primary_stage') (12,'word_images_meta') (13,'word_forms_alias')；不要在这里 `wd migrate`
   .venv/bin/python -I scripts/rehearse_migration.py $M/word-dance.db # 脚本应用迁移并核对，退出 0：逐行 +1、旗标和、difficulty+1、CHECK/FK 探针、0012 四列、0013 alias、integrity/fk、不变量、二次运行空、空库 0001→0013
   WD_DATA_DIR=$M .venv/bin/wd import-seed --dry-run --report $M/dry.json && WD_DATA_DIR=$M .venv/bin/wd import-seed
   WD_FULL_SEED_DB=$M/word-dance.db .venv/bin/python -m pytest -q backend/tests -m full_seed   # 硬门（默认 skip，必须显式设变量）
   WD_DATA_DIR=$M .venv/bin/wd check db                               # 四条不变量 ok
   ```


  而词库 / 筛词列表对 `stage_min = 5` 的行不满足旧 `StageIndex` 校验，返回 500（`schemas.py` / `security.py`）。0012 单独回代码无害（显式列名 INSERT）。
- 回滚丢失快照之后的学习记录，所以第 4–10 步一气呵成、选无人学习的时段。
- **只想退种子**（保留代码与迁移）：`git checkout 75df534 -- data/seed/vocab.jsonl.gz && .venv/bin/wd import-seed --force`——旧文件只改写它含有的 9,162 个 lemma：这些行 `stage_xs` 清零、`stage_min` 回到新索引 2..5、`legacy:*` 令牌换回旧的 `zk` / `gk` 令牌。
  新种子新增的 456 行不在旧文件里，导入器从不删行也不改文件里没有的 lemma（`seed.py` 把它们列为 `orphans … kept`），所以它们**保留新种子的阶段**——排练实测：`--force` 之后仍有 16 行 `stage_xs=1`，`stage_min` 1 / 2 / 3 = 16 / 425 / 15，初中页签仍显示 382 条只在初中的词组。

## 8 诊断与排练工具

| 工具 | 作用 |
|---|---|
| `wd check db` | 从 schema 11 起追加四条不变量：`stage_min_consistent`（`stage_min` = 最低旗标的索引，NULL = 无旗标）、`xs_subset_zk`、`stages_json_known`（`json_each`，SQLite < 3.38 只报 `query failed`、不计失败）、`seed_version_matches_file`（`kv.seed_version` == `WD_SEED_PATH` 的内容哈希；文件缺失则跳过，文件不可读——截断、解压体损坏——计 1 violation 而不是回溯，与 `seed_check` 一样捕获一切异常）。每条 `invariant <name>: ok \| N violation(s)`，任一非零 → `[FAIL] db`、退出 1 |
| `scripts/rehearse_migration.py <拷贝>` | 用 `wd.db.run_migrations` 对**私有拷贝**应用待办迁移并逐项核对 PLAN §2.2 的排练清单（见第 6 步 0），退出码 = 失败项数；可重复运行（已迁移的库只跑结构与不变量检查）；永远不要用 `/usr/bin/sqlite3` 排练（`legacy_alter_table=1` 会掩盖缺 `DROP VIEW` 的 RENAME 错误） |
| `wd import-seed --dry-run --report PATH` | 不写任何东西，输出 insert / update / unchanged / orphans / 旗标增减 / `stage_min` 矩阵 / 未知阶段码；上线第 7 步与排练报告比对 |
| `WD_FULL_SEED_DB=… pytest -m full_seed` | 读 `stats.json` 比对导入后的库（硬门；`make test` 不设该变量） |
