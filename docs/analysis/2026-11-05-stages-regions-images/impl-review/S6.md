## 4 发现（按严重度）

### major

1. **发布说明 §3.1 的 `zk ⊄ gk` 数字与所附 SQL 不符。** 文中写「复算 ≈ 212 个初中有、高中无的词，`select count(*) from words where stage_zk=1 and stage_gk=0`」。在交付的 `data/seed/vocab.jsonl.gz`（9,618 条，`stats.json` 同版）上该 SQL 得 **544**（新导入库 `by kind: word 156 / phrase 376 / abbreviation 7 / proper_noun 5`；单 token 168、多词 376）。212 是 PLAN 设计期的复算值（SYNTHESIS 甚至是 117），既不在 `stats.json`（没有这个键；`only_stage.zk` = 430 是另一个量）也无法用所附 SQL 复现，违反本切片自己定下的「数字一律以 `stats.json` 为准、≈ 只用来说明量级（±1%）」约定——操作者在上线第 8 步跑这条 SQL 会得到 2.5 倍的数字。**修法**：删掉 212，改为「以 SQL 为准；交付种子上 544，其中 376 为上海词组/多词条目、156 为单词（`… and kind='word'`）」，或请 S3 在 `stats.json` 加 `zk_not_gk` 键后引用。
   文件：`docs/releases/2026-11-k12-stages.md:51-52`。

2. **`wd check db` 对解压体损坏的种子文件崩溃。** `_seed_version_line` 只捕获 `(OSError, EOFError)`；`gzip` 对「头有效、deflate 体损坏」的文件抛 `zlib.error`（复现：10 字节头 + 异或后的体，`WD_SEED_PATH=… wd check db` → `zlib.error: Error -3 while decompressing data: invalid block type` 回溯，而不是 `1 violation(s)` 或 `query failed`）。`main.seed_check` 对同一文件是 `except Exception`，所以服务能起、诊断却崩，与 `diag.py` docstring「reported, never raised」及实现者报告「unreadable → violation」相悖；`wd check all` 也随之中断。**修法**：`except Exception as e`（或加 `zlib.error`），仍记 1 violation。
   文件：`backend/wd/diag.py:148`（`except (OSError, EOFError)`）。

### minor

1. **`rehearse_migration.py` 的「不是 word-Dance 库」守卫不可达。** `snapshot(conn)` 在 `before["version"] < 1` 判断之前执行，空文件 → `kv_get` 抛 `no such table: kv` 回溯；文本文件 → `db.connect` 抛 `file is not a database` 回溯。把 `db.connect` 与 `snapshot` 包进 `try/except sqlite3.Error` 并走 `rep.check(..., False)` 即可。文件：`scripts/rehearse_migration.py:324-333`。
2. **ECDICT 词性码 `u` 写成「助动词 / auxiliaries」。** `frontend/src/utils/pos.ts` 与 `backend/wd/images/style.py:12` 都把 `u` 定为 interjection（`int.` 感叹词）。文件：`docs/releases/2026-11-k12-stages.md:99`、`docs/DESIGN.md:584`。
3. **发布说明 §6 第 0 步用了未定义的 `$SCRATCH`**（PLAN 在 §7 标题里定义过，发布说明没有）；同一步把顺序定为 `migrate --dry-run → rehearse_migration.py`（正确），但 PLAN §7.3 是先 `wd migrate` 再跑脚本——按 §7.3 字面执行时脚本会 `[skip] 0011 row-level +1 comparisons`，失去排练价值。建议发布说明写明「脚本自己应用迁移，不要先 `wd migrate`」，并提醒 S7 按发布说明顺序执行。文件：`docs/releases/2026-11-k12-stages.md:116-125`。
4. **`query failed` 不翻 `ok`（实现者自报偏离）。** SYNTHESIS §3.9 的草图让外层 `except sqlite3.Error` 把整个检查判 FAIL；PLAN 只说「只报 `query failed`」。实现选择「unverifiable ≠ violated」，已写进 `diag.py`、ops.md §1 与发布说明；PLAN §8 第 8 步「四条不变量 ok」在 SQLite < 3.38 上两种读法都无法逐字满足。实际影响几乎为零（Ubuntu 22.04 的 3.37.2 编译了 JSON1，24.04 是 3.45），但这是产品负责人/S7 应知情确认的口径。文件：`backend/wd/diag.py:122-128`。
5. **发布说明 §3.2 两个「词组」量混用。**「词组数 = `per_kind.phrase`」（交付种子 395 = 全部多词行）与「新增 ≈ 455，其中词组 ≈ 333」（上海词组新行，`lists.shmeea20:phr.members` = 334）是不同的量；≈ 2,548 / 1,948 / 9,617 与当前 `stats.json` 的 2,549 / 1,949 / 9,618 差 1（在容差内、已标 ≈）。建议把每个 ≈ 数字标注对应的 `stats.json` 键。文件：`docs/releases/2026-11-k12-stages.md:57-58`。

7. **两条恒真断言。** `assert … >= 0` 与 `assert "zk_subset_gk" not in lines` 不检验任何行为；可删或改为断言 `zk ∧ ¬gk` 行存在时 `check_db` 仍 ok。文件：`backend/tests/unit/test_diag.py:82-84`。
