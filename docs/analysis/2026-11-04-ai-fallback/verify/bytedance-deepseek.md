## Omissions / new findings

1. **Thinking cannot be switched off on the CLI→DeepSeek route (cost).** Gateway protocol https://code.claude.com/docs/en/llm-gateway-protocol: for "a model ID Claude Code doesn't recognize, such as a gateway alias" the CLI sends "Thinking with a fixed budget rather than adaptive reasoning, and no effort or context management fields"; env-vars https://code.claude.com/docs/en/env-vars: `MAX_THINKING_TOKENS` "Set to `0` to disable thinking on the Anthropic API … On third-party providers, `0` omits the `thinking` parameter instead"; model-config: thinking "can't be turned off" on Opus/Sonnet/Haiku 5.5 and Fable, and features are enabled "by matching the model ID against known patterns". DeepSeek: with `thinking` and `effort` both absent "默认开启思考" (effort high); "`adaptive` is treated as `enabled`"; `medium`→`high`. CLI `--effort` has no off value. Net: on the wrapper-only route every `generate_content` call pays DeepSeek reasoning tokens at ¥4–8/M output unless an empirical `MAX_THINKING_TOKENS=0` test shows the CLI emitting `type: disabled`; the ¥54–108/month figure is only guaranteed by Option B's explicit `thinking: {type: disabled}`. Kimi (always on, default effort `max`) and MiniMax-M3.1-Flash (`disabled` → 400) have the same property by design.
2. **Forced tool calls are unavailable on DeepSeek while thinking is on — on both APIs.** Anthropic path: `tool_choice.any` "Treated as `auto`; does not force a tool call", `tool` → "returns a 400 error in thinking mode"; OpenAI path: "思考模式下不支持 `required` 和指定具体 tool 的用法，API 会返回 `400` 错误。请先关闭思考模式。" Claude Code's `StructuredOutput` tool is unforced anyway (structured-outputs doc), so JSON reliability on DeepSeek rests on instruction-following plus CLI retries; Option B must send `thinking: disabled` before `tool_choice` or it 400s.
3. **Client-side budgets can be made real for fallback models, but only via managed settings.** `modelPricing` (settings-reference, v2.1.242+, Managed scope) prices a custom ID row ("such as a gateway model alias") for `total_cost_usd` and `--max-budget-usd`; `modelUsage[].costBasis: "unknown"` (v2.1.246+) lets the runner detect unpriced calls. Without it, unknown IDs cost $0 in `total_cost_usd`, so the existing $0.25/call, $3/day, $40/month caps silently stop protecting fallback spend.
4. **What the CLI sends to an unrecognised model ID (every provider).** `CLAUDE_CODE_MAX_OUTPUT_TOKENS`: "For a model ID Claude Code can't resolve to a model it knows, the default is 32000 and the cap is 128000" (so Ark's 4k default is moot on the CLI path); context assumed 200K with a startup warning (`Model "…" isn't recognized · context assumed to be 200k tokens`) — use the `[1m]` suffix as DeepSeek's guide does or `CLAUDE_CODE_MAX_CONTEXT_TOKENS`; `role: "system"` mid-conversation entries and beta tool fields such as `strict` are sent and may 400 on a strict upstream (CLI retries without system messages; `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` stops beta fields); `count_tokens` is optional ("Claude Code falls back to a character-based estimate"). DeepSeek adds: "For certain main-agent requests from Claude Code or OpenCode in thinking mode, compatibility handling can increase the effective max_tokens above the requested value. In these cases, this parameter does not provide a strict output-token limit" — the CLI's `max_tokens` is not a hard per-call cost cap there.
5. **Kimi specifics the digest lacked.** Official tier table (F12): Tier0's 1 concurrency / 3 RPM / 1.5M TPD persists until ¥50 cumulative and "代金券不计入累计充值总额"; K3.1 Pro default effort is `max` on both APIs (reasoning tokens billed at ¥68/M), highspeed variant ¥26/¥136; the Anthropic endpoint has no named-`tool` choice and no `claude-*` alias mapping (send `kimi-k3.1-pro` explicitly); `kimi-k2.7-code`, the model Kimi's own guide calls most robust for complex schemas, is closed to new sign-ups.
