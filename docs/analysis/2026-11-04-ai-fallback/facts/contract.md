# Contract slice — what a fallback model must satisfy, and where automatic provider failover hooks into word-Dance

Slice key: `contract` · Date: 2026-11-04 · Repo: /Users/sqin/word-dance @ 9ab13a5 (nothing modified) · Scratch: `…/scratchpad/fallback/` (measurement script and rendered prompts under `measure/`).

## Summary

1. The whole AI surface is one seam: `interfaces.ClaudeRunner.run(conn, *, kind, system_prompt, user_prompt, schema, max_budget_usd, timeout_s, word_count, job_ids) -> ClaudeResult(ok, status, structured, cost_usd, call_id, model_used, error)`. The four handlers only consume `structured` + `status`; everything Anthropic-specific lives in `ai/runner.py` (argv, env allow-list, envelope parsing, regex classifier), `ai/budget.py` (USD maths), `ai/ledger.py` (`model_requested/model_used`, no provider), `ai/probe.py` (flag tiers) and `common.AUTH_BANNER_ZH`.
2. A replacement must return JSON that validates against five schemas that use only `type/properties/required/items/minItems/maxItems/enum/description` (string **and integer** enums, one array-of-arrays), then survive strict post-validation: the headword must appear in ≥3 example sentences (≥2 on the last attempt), Chinese fields must contain CJK, lengths/ratios are enforced, `word`/`input`/`id` must be copied verbatim, headwords pass the user-input validator. Measured prompts: content 10 words = 6.3 KB total (system 2,993 B + user 1,585 B + schema 1,740 B); lookup 20 strings = 3.9 KB; consolidate worst case = 56.5 KB (2,000 headwords + 80 items with 120-char notes; `PROMPT_MAX_BYTES=96,000`), typical night 5.1 KB; SVG 1.1 KB. Expected outputs: ≈1,006 bytes compact JSON per content item (≈3,800 output tokens / 10 words at the measured 2.55 bytes/token), ≈100 output tokens per consolidate item, 600–1,050 tokens per SVG.
3. Option A (point the existing `claude` CLI at a domestic Anthropic-format endpoint through a second wrapper) is zero-code but changes the contract under the runner: `total_cost_usd` is a client-side estimate (≈0 for unknown model IDs → daily/monthly caps and prewarm `spent` go blind), `--json-schema` is a `StructuredOutput` **tool call** with client-side validation/retries, `--max-budget-usd` becomes inert, the CLI still talks to anthropic.com for managed settings/telemetry/fast-mode checks unless silenced, and the classifier misses `403 Request not allowed`, `402/余额不足`, `429`, `令牌已过期`. Manual switch: 0.25 d; CLI-slot failover: ≈4–5 d.
4. Option B (OpenAI chat-completions adapter behind the protocol) is the D3 plan (`providers/openai_http.py`, schema transform, price table, HTTP→status mapping); Option C (Anthropic Messages adapter, tool_use/`output_config.format`) shares 70 % of B. B ≈ 8–10 d including failover, admin surface, tests, smoke and docs; C adds ≈2–3 d. Regression surface: 18 test files reference the runner/fake/ledger, 10 reference the pause keys, plus `scripts/smoke.py`, `check_contract.py`, 3 frontend test files.
5. The failover should be a sticky, provider-scoped state machine in `common.claude_call` (choose provider → reserve → run → classify → maybe switch + immediate retry on hard triggers) with `kv.ai.active_provider`, a cooldown and a recovery probe every 30 min through the existing `probe.check`; `kv.claude.paused_until` must become the primary's pause only, the manual admin pause a global one. Hard triggers: auth (incl. the managed-settings string seen 15× in the live DB), spawn_error, 403/forbidden, network/DNS, usage-limit strings; soft: 3 consecutive overloaded, 2 consecutive timeouts; never `invalid_output`; optional: daily/monthly cap exhaustion when the fallback is free.
6. Provenance needs no schema change for content (`word_contents.model` already stores `result.model_used or cfg.ai_model`), but the ledger does: recommend additive migration 0010 `ai_calls.provider TEXT NOT NULL DEFAULT 'claude'` (SCHEMA.sql stays byte-identical to 0001 as the test pins) rather than overloading `model_requested`.
7. An eval harness (`scripts/eval_provider.py` + `scripts/mock_provider_server.py`) can reuse the real prompt builders, the real schemas (`jsonschema` 4.26 is already in the venv), the pydantic mirrors and `content.validate_item`, and should be run first against the mock, then against each candidate with the same 50-word sample; the 48 existing Sonnet rows are the paired human-review baseline.

## Findings

### F1 — The provider seam is already one protocol; only five modules know about Anthropic
**Claim.** Handlers never see the CLI; swapping the model is a runner/budget/ledger/probe/banner change, not a handler change.
**Evidence.** `backend/wd/interfaces.py:82-109` (`ClaudeResult`, `ClaudeRunner` protocol); every handler calls `common.claude_call` (`backend/wd/ai/common.py:133-184`) which calls `runner.run_claude` (`backend/wd/ai/runner.py:383-495`); handlers then read only `result.ok/status/structured/cost_usd/model_used/call_id` (`content.py:412-447`, `lookup.py:538-560`, `consolidate.py:500-518`, `svg.py:109-143`). Anthropic-specific code: argv builder `runner.py:124-149`, env allow-list `runner.py:49-62,158-174`, envelope parser + regexes `runner.py:71-74,229-285`, USD estimates `budget.py:29-35`, `--max-budget-usd` per kind `budget.py:51-59`, flag tiers `probe.py:115-151`, banner `common.py:37`. `budget.reserve` already accepts `model_requested` (`budget.py:277`), `ledger.insert_call` stores it (`ledger.py:26-57`).
**Implication.** Options B/C can be implemented as a `providers/` package behind `run_claude`, keeping every handler and the §6.3 outcome table untouched.
**Confidence.** high

### F2 — Structured-output capability checklist (what every schema actually requires)
**Claim.** The five schemas use exactly `type, properties, required, items, minItems, maxItems, enum, description` (pinned by `tests/unit/test_schemas.py:22-23`, forbidden: `$ref, additionalProperties, minLength, maxLength, minimum, maximum, anyOf/oneOf/allOf`). Features that trip strict implementations:

| schema | items/call | strict-mode hazards |
|---|---|---|
| `content_v1` (1,762 B) | `items` 1–12 | integer `enum [1..5]` (`difficulty`), `examples` array of objects `minItems 0/maxItems 4`, `image_keywords minItems 1/maxItems 4`, 10 required keys, descriptions contain Chinese |
| `lookup_v1` (1,842 B) | 1–20 | string enum `kind` (5 values), integer enum, 13 required keys incl. two booleans |
| `consolidate_v1` (1,584 B) | `items` 1–80 | **array of arrays** `confusable_groups` (`maxItems 15`, inner `minItems 2/maxItems 4`), nested object `fill` with its own integer enum, `confidence` number, three top-level required arrays |
| `svg_v1` (213 B) | 1 | a ≤8,000-char SVG inside a JSON string (escaping) |
| `probe_v1` (332 B) | 1 | integer + string enums, `tags minItems 1/maxItems 2`; success is exact equality with `{"ok":true,"echo":"word-dance","level":2,"mode":"b","tags":["probe"]}` (`probe.py:42,91-92`) |

All object schemas already list every property in `required` (no optional keys), so the OpenAI-style strict rule "All fields or function parameters must be specified as `required`" and "`additionalProperties: false` must always be set in objects" (https://developers.openai.com/api/docs/guides/structured-outputs, accessed 2026-11-04) only needs `additionalProperties:false` injected; that page lists `minItems`/`maxItems` and numeric constraints as supported and caps schemas at "up to 5000 object properties total, with up to 10 levels of nesting". Anthropic's own `output_config.format` is narrower: "Array `minItems` (only values 0 and 1 supported)", not supported: "Array constraints beyond `minItems` of 0 or 1", "`additionalProperties` set to anything other than `false`"; "beta headers are no longer required" (https://platform.claude.com/docs/en/build-with-claude/structured-outputs.md, accessed 2026-11-04) → `consolidate_v1.confusable_groups.items.minItems:2` and every `maxItems` must be stripped into descriptions for Option C. JSON-object mode on DeepSeek: "Set the response_format parameter to {'type': 'json_object'}", "Include the word "json" in the system or user prompt, and provide an example of the desired JSON format", "if the model's output cannot be recognized as JSON, the API replaces the non-JSON content with spaces (U+0020)" (https://api-docs.deepseek.com/guides/json_mode, accessed 2026-11-04). Pydantic mirrors (`ai/models.py:15-110`) ignore unknown keys but type `difficulty: Literal[1,2,3,4,5]`, so a quoted `"3"` or a boolean fails; `models.valid_items` drops invalid items silently (`models.py:113-126`).
**Implication.** Any adapter needs one `schema_transform(schema, dialect)` step (add `additionalProperties:false` everywhere; for Anthropic also drop `maxItems` and `minItems>1` into `description`) plus post-hoc validation against the **original** schema; a vendor whose json_schema mode ignores integer enums or nested arrays must be run in json_object/tool mode — exactly what the eval harness (F17) measures.
**Confidence.** high (schema facts), medium (per-vendor strict behaviour is the provider slice's job)

### F4 — Post-validation rules a weaker model must still pass
**Claim.** Beyond schema validity the handlers enforce (all strings first pass `common.clean_text`: control chars/HTML tags stripped, any `http://`, `https://`, `<script` → the field is rejected, `common.py:39-59`):
* **content** (`content.validate_item`, `content.py:122-194`): `word` equals the requested lemma or display case-insensitively, else `unmatched` (job retries); `valid` must be a boolean; `meaning_zh` 1–120 chars **with ≥1 CJK char**; `meaning_en` ≤200; each example `en` 15–240 chars, ≥70 % ASCII, **must contain the headword, an inflection from `word_forms`, or the lemma's ≥4-letter prefix** (`contains_headword`, `content.py:108-119`); `zh` 2–200 chars with CJK; ≥3 usable examples (≥2 when `attempts >= max_attempts`) else `retry`; collocations ≤4 × ≤60; mnemonic ≤100 (truncated); `image_keywords` must match `^[A-Za-z][A-Za-z ,'-]{1,40}$` and the image blocklist, else fall back to `[lemma]`; alt ≤60; `difficulty` a JSON integer 1–5 (bool rejected). `valid=false` on a seed word is an anomaly (one retry alone, then `content_state='failed'`, `content.py:371-389`); on a user word it hides the word (`reject_word`, `content.py:255-273`). If **every** item fails the call is reclassified `invalid_output` (`content.py:440-444`).
* **lookup** (`lookup.apply_item`, `lookup.py:444+`): items are indexed by `input` lower-cased (`lookup.py:557-560`) → `input` must be copied verbatim; `is_english` must be literally `true` and `kind != 'invalid'` else the word is rejected; `headword` is used only if `words.validate_headword` accepts it (charset `[A-Za-z' .-]`, ≤48 chars, ≤4 tokens, related to the input by equality / `word_forms` / suffix rule / shared first 3 letters, `services/words.py:779-791`), otherwise it becomes a `fix_spelling` suggestion; `phonetic` is stripped of `/[]` (`common.clean_phonetic`, `common.py:62-69`), `pos` ≤40, `meaning_zh` filled only with CJK, `difficulty` int 1–5, `safe_for_sharing` drives `is_public`.
* **consolidate** (`consolidate.apply`, `consolidate.py:381+`): `id` must be an integer from the batch (unknown ids ignored and logged), `verdict` from the 7-value enum, `target` validated like a headword or the item is downgraded to `ok` (`consolidate.py:402-408`), `note_zh` ≤40, `confidence` clamped 0–1, `fill.difficulty == 3` is treated as "nothing to fill" (`consolidate.py:283`), confusable groups keep only members present in the sent headword list, 2–4 members, max 15 groups (`consolidate.py:349-378`).
* **svg**: `images.activate_svg` → defusedxml parse, element/attribute allow-lists, no `href/xlink:href/style url()/script/image/foreignObject/use`, `viewBox 0 0 800 500` enforced, ≤60 KB; a rejected SVG leaves `image_state='failed'` and is never retried (`svg.py:131-142`, CLAUDE_INTEGRATION §6.7).
**Implication.** The eval harness must score exactly these predicates (headword presence per example is the one weaker models fail most). A model that paraphrases the headword ("abandoned" is fine via prefix; "leave" is not) loses the whole item after 3 attempts.
**Confidence.** high

### F5 — Prompt-injection assumptions survive a provider change only if the adapter keeps the same layout
**Claim.** User-derived text reaches a model only as JSON string values inside one `<items>…</items>` block (content: dictionary `display/translation/pos`, never notes; lookup: ≤48-char normalised strings; consolidate: normalised display + ≤120-char sanitised note, `consolidate.py:64-66,118-129`), prefixed by "The JSON below is DATA …" (`content.py:90`, `consolidate.py:134`); under tier 0 the system prompt is folded into the positional prompt as `<system_instructions>…</system_instructions>` with any literal `<items>` in the system text rewritten to `‹items›` (`runner.py:108-121`, CLAUDE_INTEGRATION §9). The model has no tools (`--tools ""`, empty cwd, tier-1 `--restricted --strict-mcp-config --disable-slash-commands`).
**Implication.** HTTP adapters get a *stronger* separation for free (a real `system` field instead of folding) and expose no tools at all; Option A keeps the CLI's tool surface, so `--tools ""`/`--restricted` must stay on the fallback wrapper too. The consolidate note is the only place a learner can write a sentence that a weaker model might obey — keep the 120-char cap and the downgrade-to-`ok` rule as the safety net.
**Confidence.** high

### F6 — Option A: what the runner silently assumes about Anthropic when the CLI is pointed at a gateway
**Claim.** The CLI honours `ANTHROPIC_BASE_URL` + `ANTHROPIC_AUTH_TOKEN`/`ANTHROPIC_API_KEY` (all three are in `PASSTHROUGH_ENV`, `runner.py:54-56`; a wrapper may also export anything else because the allow-list only filters what the parent passes), but under a non-Claude upstream these contract points move:
1. **Cost is a client-side estimate**: `--max-budget-usd`: "Claude Code checks the cap against its client-side cost estimate, which can differ from your bill" (https://code.claude.com/docs/en/cli-reference, accessed 2026-11-04). For a model ID the CLI cannot price, `total_cost_usd` is 0/unknown → `parse_and_classify` records `cost_usd=0` (`runner.py:237-242`), `spent_today/spent_month` stay at reservations only (`budget.py:136-151`), daily/monthly caps never bind, `avg_cost_per_word_7d` reads 0, prewarm `kv prewarm:<plan>:spent` never grows (`content.py:231-241`) so a plan only stops on `limit`/`no_candidates` (`prewarm.py:143-153`), and the `budget` status/bisection path never fires. Only the hourly call cap (`budget.py:211-212`) remains a real guard.
2. **`--json-schema` is tool use with client-side retries**: "your message stream carries a tool call named `StructuredOutput` that you never defined. Claude Code adds this tool to the session, and the agent calls it to return its answer"; "When that object doesn't match your schema, the `tool_result` carries `is_error: true` instead and the agent calls `StructuredOutput` again"; failure ends with subtype `error_max_structured_output_retries`, and "A result can also end with subtype `success` but no `structured_output` value" (https://code.claude.com/docs/en/agent-sdk/structured-outputs, accessed 2026-11-04). `parse_and_classify` maps both to `error` (no regex matches; `runner.py:258-279`) → backoff/bisect instead of `invalid_output`. Each retry is another upstream round-trip inside the 180-s window.
3. **Model name and provenance**: `--model` "Sets the model for the current session with a model alias such as `sonnet` … or a model's full name" (cli-reference). An alias is resolved client-side and the gateway maps it: DeepSeek documents "`claude-opus*` → `deepseek-v4-pro`; other `claude*` → `deepseek-flash`" and `tool_choice` support only for `none`/`auto` (https://api-docs.deepseek.com/guides/anthropic_api, accessed 2026-11-04, fetch summary). `model_used` = first `modelUsage` key (`runner.py:235-236`) will therefore name a Claude ID while a domestic model answered → `word_contents.model` lies. Fix: `WD_AI_MODEL` must carry the vendor ID (e.g. `glm-4.5-flash`) for the fallback slot; the wrapper may also export `ANTHROPIC_DEFAULT_SONNET_MODEL` ("Model ID that the `sonnet` alias resolves to") and `ANTHROPIC_DEFAULT_HAIKU_MODEL` ("also used for background functionality") (https://code.claude.com/docs/en/env-vars, accessed 2026-11-04) — neither is in `PASSTHROUGH_ENV`, so they belong in the wrapper, not in `.env`.
4. **Unknown model IDs change what the CLI sends**: "Request fields for a model ID Claude Code doesn't recognize … Everything current Claude models accept on the Claude API, including adaptive reasoning, effort, and context management, which an Amazon Bedrock or Agent Platform upstream can reject"; inference goes to "`/v1/messages?beta=true`"; "The `output_config` body field carries effort, structured-output format, and task budget settings"; mid-conversation `role: "system"` entries are sent "for Claude Opus 4.8, models released after it, and unrecognized model IDs", a `400` such as `Unexpected role "system"` makes Claude Code "retr[y] without system messages"; `CLAUDE_CODE_DISABLE_EXPERIMENTAL_BETAS=1` removes "The structured-output `output_config.format` field. Requires Claude Code v2.1.287 or later"; context is assumed "200K" (https://code.claude.com/docs/en/llm-gateway-protocol, accessed 2026-11-04). `CLAUDE_CODE_MAX_OUTPUT_TOKENS`: "For a model ID Claude Code can't resolve to a model it knows, the default is 32000 and the cap is 128000" (env-vars page). Anthropic's position: it "doesn't support routing Claude Code to non-Claude models through any gateway" (https://code.claude.com/docs/en/llm-gateway, accessed 2026-11-04).
5. **The CLI's own network calls**: "Claude Code also sends nonessential background traffic outside the gateway path, to Anthropic and to third-party services such as GitHub: version checks, telemetry, release notes" → `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`; "The WebFetch tool's domain safety check isn't affected and still calls `api.anthropic.com`" (irrelevant with `--tools ""`); the fast-mode check "goes directly to `api.anthropic.com`" (https://code.claude.com/docs/en/llm-gateway-connect, accessed 2026-11-04). Server-managed settings are "fetch[ed] from the claude.ai admin console" (https://code.claude.com/docs/en/settings, accessed 2026-11-04) — this is the exact failure already in the live DB: 15 calls (ids 33–47) failed with "Your organization requires remote managed settings to load, but they could not be loaded. Run `claude auth login` to re-authenticate, check your network connection, or contact your administrator." (classified `auth` only because `log ?in` matches "auth login"). A fallback wrapper must therefore run the CLI with a **separate, login-free config dir** (`CLAUDE_CONFIG_DIR`, already pass-through, `runner.py:50`) so no Enterprise OAuth profile is present to trigger the managed-settings fetch; with `ANTHROPIC_AUTH_TOKEN` set "requests carry that credential in place of a developer's claude.ai subscription login" and "In non-interactive mode (`-p`), the key is always used when present" (llm-gateway / env-vars pages). Whether the managed-settings fetch is skipped when a token is set is **not** stated — verify with one `wd claude-check` under the fallback wrapper.
6. **Classifier gaps**: `AUTH_RE` (`runner.py:71`) does not match `403`, `forbidden`, `Request not allowed` (the string this network gets from api.anthropic.com per `~/word-dance-data/bin/claude-wrapper` lines 8–9 and the project memory), nor `402`, `insufficient balance`, `余额不足`, `欠费`, `令牌已过期` (Zhipu's 401 body, owner's probe), nor usage-limit phrases (`usage limit`, `plan limit`, `enforced_spend_limit_reached`, `credit balance`); `OVERLOADED_RE` (`runner.py:73`) lacks `\b429\b`; network errors ("Can't reach the API server … (ENOTFOUND)", "Connection refused … (ConnectionRefused)", "API returned an empty or malformed response (HTTP 200)" — wording from the gateway-connect troubleshooting table) all land in `error` and go backoff → bisect → dead instead of pause/failover.
7. **Unchanged/fine**: `--tools ""`, `--no-session-persistence`, tier-1 flags, `--system-prompt`, the `<items>` layout, `save_raw`, timeouts, process-group kill. `--fallback-model` ("Accepts a comma-separated list tried in order", cli-reference) is a Claude-only chain and must stay empty on the fallback slot. **Naming collision**: `WD_AI_FALLBACK_MODEL` already means this CLI flag (`config.py:91,334`, `runner.py:145-146`, `deploy/env.example:62`, `docs/DEPLOY.md:320`) — rename it `WD_AI_CLI_FALLBACK_MODEL` before introducing `WD_AI_FALLBACK_*` provider keys.
Chinese-language source for the Zhipu endpoint: https://docs.bigmodel.cn/cn/guide/develop/claude/introduction (accessed 2026-11-04): base URL `https://open.bigmodel.cn/api/anthropic`; "某些场景下智谱与 Claude 接口仍存在差异，但不影响整体兼容性" (no parameter-level list on that page).
**Implication.** Option A is viable as a manual, best-effort switch (wrapper + `.env` edit + restart) but not as the long-term contract: budgets, provenance, structured-output failure semantics and the classifier all degrade, and the CLI keeps a dependency on anthropic.com reachability unless silenced.
**Confidence.** high for 1, 2, 4, 5, 6 (documented/observed); medium for 3 (DeepSeek mapping from a fetch summary; Zhipu mapping unverified)

### F7 — Option A integration: touch points and effort
