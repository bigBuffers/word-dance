## 1 The problem (release note docs/releases/2026-11-k12-stages.md §9 末, PLAN §9.2 #5)

Every "which word next" list orders by the adult COCA rank `words.frq` ASC with NULL/0 last:
- 词库 page `GET /api/vocab` default `sort=freq`: ORDER BY (w.frq IS NULL OR w.frq = 0), w.frq, w.lemma  (backend/wd/routers/vocab.py `_ORDER`; `difficulty` sort = COALESCE(w.difficulty + 1, w.stage_min, 6) then the same frq tail; `alpha` = w.lemma)
- 筛词 `GET /api/screen/next` (backend/wd/services/screen.py:65): ORDER BY {_STAGE_DISTANCE}, (w.frq IS NULL OR w.frq = 0), w.frq, w.lemma
- 每日推荐词 (daily batch "screens", backend/wd/services/batches.py:61 `_SCREEN_ORDER`, used at :271 select_words and :697 add_more/extra): same as screen
- admin 预生成 candidates (backend/wd/ai/prewarm.py:52): ORDER BY (w.frq IS NULL OR w.frq = 0), w.frq, w.lemma
- lookup prefix suggestions (backend/wd/routers/words.py:106): same frq order (search convenience, arguably out of scope)
`_STAGE_DISTANCE` (screen.py:34 and batches.py:60, two identical copies):
  CASE WHEN w.stage_min = :cur THEN 0 WHEN w.stage_min > :cur THEN 2 * (w.stage_min - :cur) - 1 ELSE 2 * (:cur - w.stage_min) END
  (DESIGN.md §6.3 step 4: 0 for the 主攻阶段, then higher stages, then lower.)
