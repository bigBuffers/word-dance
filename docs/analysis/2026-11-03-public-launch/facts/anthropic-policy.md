# Fact slice: anthropic-policy (24 findings)

## Summary

Today word-Dance reaches Claude only by spawning the Claude Code CLI under the operator's interactive OAuth login (backend/wd/ai/runner.py:123-146 builds `claude -p … --tools "" --model sonnet --max-budget-usd …`; runner.py:158-174 hands the child HOME so the `~/.claude*`/Keychain credentials are used; docs/CLAUDE_INTEGRATION.md:3 and docs/DEPLOY.md:3 state "no ANTHROPIC_API_KEY"), and on the Mac that login is an employer-provided Claude Enterprise seat. Anthropic's current documents (all retrieved 2026-11-03) do not permit turning that login into the engine of a public service: the Consumer Terms (effective 2025-10-08) forbid making the account "available to anyone else", reselling, and automated access except "via an Anthropic API Key"; the Usage Policy forbids "services that route requests through consumer subscriptions"; the Claude Code legal page says OAuth is "intended exclusively for purchasers" of plans "to support ordinary use of Claude Code and other native Anthropic applications", that developers "should use API key authentication through Claude Console", and that Anthropic "does not permit third-party developers … to route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users"; for Team/Enterprise, "Each Enterprise seat is assigned to one named individual, and only that person may use it" and customers hosting Claude Code "may not pay for, resell, or intermediate Claude usage on their end users' behalf". The 2026 enforcement history (January block and reversal; 19-20 February documentation clarification; 4 April block of third-party tools on Pro/Max; 13 May announcement of a separate programmatic credit; 15 June pause; 7 October monthly API credits) concerns a subscriber's own programmatic use and never opens a path to serve strangers from a subscription. The sanctioned path for a product backend is a Claude Console organization billed by API key under the Commercial Terms, which expressly permit powering "products and services Customer makes available to its own customers and end users", assign Output ownership to the customer, and bar training on customer content; the code already passes ANTHROPIC_API_KEY through (runner.py:54, 170-173), and `claude -p` with an API key is a documented pattern "billed as Agent SDK usage", although Anthropic steers plain generation to the Messages API/Client SDK and recommends `--bare` (which never reads OAuth credentials) for scripted calls, contradicting docs/CLAUDE_INTEGRATION.md:33. Regions: mainland China, Hong Kong and Macau are absent from the Supported Regions list (Taiwan, Singapore, Japan, US present); the policy keys on where a person is "physically located", where an entity is "incorporated or headquartered", and majority ownership, and the Usage Policy forbids providing "others (including end users)" access in violation of it, so an audience of learners inside mainland China is a direct constraint regardless of where the server runs. Pricing for the model the code's `sonnet` alias resolves to today (Claude Sonnet 5.5, id `claude-sonnet-5-5`) is $2 input / $10 output per MTok, $2.50 (5-min) / $4 (1-hour) cache writes, $0.10 cache reads, and $1/$5 with the 50% Batch API discount; a new Console org starts with a $500/month spend cap (or lower Evaluation-tier limits) and 4,000 RPM / 2M input tokens per minute for Sonnet 5.5. Claude.ai itself is 18+, but API products may serve minors under the "Guidelines for Organizations Serving Minors" (age verification, content moderation, AI disclosure, child-safety system prompt, COPPA-type compliance, periodic audits), which matters because the app targets 初中/高中 learners; vocabulary example sentences are "general information or educational content", not a High-risk AI Recommendation; outputs belong to the customer and no attribution to Anthropic or Claude is required. Consumer-account traffic may be used for training with 5-year retention when the setting is on, while commercial/API traffic is not trained on and is retained 30 days, a further reason the public deployment must run under commercial terms.

### [anthropic-policy-1] (high) Current code path: operator OAuth login drives every Claude call

- EVIDENCE: backend/wd/ai/runner.py:123-146 (`build_argv`: `claude -p <prompt> --output-format json --json-schema … --tools "" --no-session-persistence --model <cfg.ai_model> --max-budget-usd …`); runner.py:158-174 (`claude_env` sets HOME/PATH so the CLI finds credentials under `~/.claude*` or the macOS Keychain); runner.py:426-437 (`subprocess.Popen` of that argv); backend/wd/config.py:85-87 and :328-330 (`claude_bin` default `/home/sqin/.local/bin/claude`); docs/CLAUDE_INTEGRATION.md:3 ("verified … `claude` 2.1.299 authenticated for user `sqin`, no `ANTHROPIC_API_KEY`"); docs/DEPLOY.md:3 ("credentials in `/home/sqin/.claude*`, no `ANTHROPIC_API_KEY`"); deploy/word-dance.service:33-34 ("the claude CLI must read and write /home/sqin/.claude and /home/sqin/.claude.json (OAuth credentials)"); deploy/install.sh:11 ("must be the user whose `claude` CLI is authenticated (sqin)"); README.md:46; ATTRIBUTION.md:63 ("run headlessly … on the operator's own machine under the operator's own Anthropic account"); owner machine note /Users/sqin/.claude/projects/-Users-sqin-word-dance/memory/claude-cli-macos-needs-login-env.md (observed 2026-11-02: "claude.ai enterprise login, OAuth credentials in the login Keychain"). deploy/env.example contains no ANTHROPIC_* line (grep 2026-11-03).
- IMPLICATION: Every content, lookup, consolidation and SVG call made on behalf of a public user would be authenticated by, and metered against, the owner's personal Enterprise seat. All terms findings below evaluate exactly this path; the iOS app would not change it because the app would call this backend, not Anthropic.

### [anthropic-policy-2] (high) Consumer Terms: account sharing, resale, automated access

- CLAIM: Anthropic's Consumer Terms of Service (effective Oct 8, 2025) prohibit making a consumer account available to others, reselling the Services, and automated access except through an API key; outputs are assigned to the user.
- EVIDENCE: https://www.anthropic.com/legal/consumer-terms (page header "Effective Oct 8, 2025"; raw text retrieved 2026-11-03). §2: "You must be at least 18 years old or the minimum age required to consent to use the Services in your location, whichever is higher." and "You may not share your Account login information, Anthropic API key, or Account credentials with anyone else. You also may not make your Account available to anyone else." §3: "You may not access or use, or help another person to access or use, our Services in the following ways: … To develop any products or services that compete with our Services, including to develop or train any artificial intelligence or machine learning algorithms or models or resell the Services." and "Except when you are accessing our Services via an Anthropic API Key or where we otherwise explicitly permit it, to access the Services through automated or non-human means, whether through a bot, script, or otherwise." §4: "Subject to your compliance with our Terms, we assign to you all of our right, title, and interest—if any—in Outputs." Preamble: "Our Commercial Terms of Service govern your use of any Anthropic API key, the Anthropic Console, or any other Anthropic offerings that reference the Commercial Terms of Service. For clarity, this does not include Claude.ai or Claude Pro use for individuals or entities."
- IMPLICATION: A Pro/Max/Ultra login cannot lawfully be the engine of a service used by strangers: proxying their requests makes the account 'available to' them and is automated non-API access. The explicit carve-out ('via an Anthropic API Key') is Anthropic's own pointer to the permitted path.

### [anthropic-policy-3] (high) Usage Policy: proxying consumer subscriptions and regional end users

- CLAIM: The Usage Policy expressly prohibits providing access to Claude through services that route requests through consumer subscriptions, and prohibits giving end users access in violation of the Supported Regions Policy; it binds end users of integrating products too.
- EVIDENCE: https://www.anthropic.com/legal/aup (raw text retrieved 2026-11-03; page header reads "Effective Nov 12, 2026" with a "See version history" control, i.e. the displayed text is the version taking effect nine days after retrieval). Scope: "Our Usage Policy … applies to anyone who submits inputs to Anthropic's products or services … This includes individuals using our apps (such as Claude.ai and Claude Code), developers and businesses using our API and developer platforms, customers accessing Claude through cloud providers and authorized resellers, and the end users of products or services integrating Claude." Prohibitions: "Resell, proxy, or otherwise provide access to Claude through unauthorized means, including services that route requests through consumer subscriptions or misrepresent the product or client being used"; "Access, facilitate, or provide others (including end users) with access to our products or services in violation of our Supported Regions Policy"; "Circumvent a ban through the use of a different account …".
- IMPLICATION: Independently of the Consumer Terms, routing a public web/iOS user base through a consumer subscription is a named prohibited use. Whether the service charges money is irrelevant to the wording. The exact wording of the version in force until Nov 12, 2026 was not retrievable (version history is a client-side control), so the quoted text should be treated as the forward-looking policy.

### [anthropic-policy-4] (high) Claude Code legal page: OAuth is for plan purchasers' ordinary use; products must use API keys

- CLAIM: Anthropic's Claude Code documentation states that OAuth credentials exist only for subscription purchasers' ordinary use of native Anthropic applications, that developers building products should authenticate with Console API keys, and that routing requests through plan credentials on behalf of one's users is not permitted and may be enforced without notice.
- EVIDENCE: https://code.claude.com/docs/en/legal-and-compliance (retrieved 2026-11-03): "OAuth authentication is intended exclusively for purchasers of Claude Free, Pro, Max, Ultra, Team, and Enterprise subscription plans and is designed to support ordinary use of Claude Code and other native Anthropic applications." Anthropic does not permit third-party developers to offer Claude.ai login into their own applications, or to route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users. Moreover, developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow." - IMPLICATION: This is the most specific official statement for the planned architecture: a backend serving strangers is 'routing requests … on behalf of their users'. Enforcement is described as possible without notice, i.e. the service could lose its AI engine abruptly, and the owner's account (an employer seat) could be affected.

### [anthropic-policy-5] (high) Claude Code hosted in products: no intermediating usage for end users (applies under Commercial Terms, hence Team/Enterprise too)

- CLAIM: Even under the Commercial Terms, a customer that runs Claude Code inside its own product may not pay for, resell, or intermediate Claude usage for its end users; each end user must authenticate with their own credentials.
- EVIDENCE: https://code.claude.com/docs/en/legal-and-compliance (retrieved 2026-11-03), section "Can customers offer Claude Code in their products?": "Unless we've mutually agreed otherwise, preinstalling or running Claude Code in your products or services (e.g. in hosted sandboxes or other agent infrastructure) requires agreeing to our Commercial Terms of Service and complying with the conditions below: The Claude Code binary must not be modified … Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf. Each end user must authenticate with their own Anthropic API key, Claude subscription plan credentials, or 3P inference provider credential … That usage is billed directly to the end user under their own agreement with Anthropic …" and: "This does not restrict how customers provision and manage their own API keys … provided the resulting usage is billed to the key owner under their agreement with Anthropic … and is not resold or intermediated as described above."
- IMPLICATION: Running the unmodified `claude` binary server-side for public users is exactly 'running Claude Code in your products'; the only compliant shape is the operator's own API key billed to the operator (the second quoted paragraph), or each user bringing their own credential. A Team/Enterprise seat login does not satisfy this.

- EVIDENCE: https://code.claude.com/docs/en/agent-sdk/overview (retrieved 2026-11-03): "Unless previously approved, Anthropic does not allow third party developers to offer claude.ai login or rate limits for their products, including agents built on the Claude Agent SDK. - IMPLICATION: `claude -p` is documented as the CLI form of the Agent SDK (see headless finding), so these rules cover the app's runner. Public marketing may say 'Powered by Claude' but must not present the product as Claude Code.

### [anthropic-policy-7] (high) Enterprise/Team seats are personal, per named individual, and belong to the employer's contract

- CLAIM: An Enterprise seat may be used only by the one named individual it is assigned to, credentials may not be shared or used by others, and the governing contract (Commercial Terms) is between Anthropic and the organisation, which is the 'Customer' entitled to build products for its own end users; an employee seat holder is a 'User' of that Customer. Enterprise plans are also excluded from the monthly API credits.
- EVIDENCE: https://support.claude.com/en/articles/13393991-purchase-and-manage-seats-on-enterprise-plans (fetched 2026-11-03, "Updated over 2 weeks ago"): "Each Enterprise seat is assigned to one named individual, and only that person may use it." ### [anthropic-policy-8] (medium) 2026 enforcement history, part 1: January block and February clarification

- CLAIM: In January 2026 Anthropic blocked consumer OAuth tokens outside its own apps, reversed after backlash, and on 19-20 February 2026 updated its documentation to state that using Free/Pro/Max OAuth tokens in any other product, tool or service, including the Agent SDK, violates the Consumer Terms.
- EVIDENCE: The Register, 20 Feb 2026, https://www.theregister.com/software/2026/02/20/anthropic-clarifies-ban-on-third-party-tool-access-to-claude/5014546 quoting Anthropic's documentation: "Using OAuth tokens obtained through Claude Free, Pro, or Max accounts in any other product, tool, or service — including the Agent SDK — is not permitted and constitutes a violation of the Consumer Terms of Service." and Anthropic engineer Thariq Shihipar (January 2026): "Third-party harnesses using Claude subscriptions create problems for users and are prohibited by our Terms of Service." The article attributes the practice to "token arbitrage" (subscriptions cheaper than API tokens). The current wording of the same policy is on https://code.claude.com/docs/en/legal-and-compliance (retrieved 2026-11-03), quoted above.
- IMPLICATION: The restriction is not theoretical: Anthropic has already cut off subscription-token harnesses once and banned accounts. A public service on a subscription would be a prime target of the same detection ('unusual traffic patterns without any of the usual telemetry').

### [anthropic-policy-12] (high) Headless `claude -p` is the Agent SDK CLI; `--bare` is the recommended scripted mode and disables OAuth

- CLAIM: Anthropic documents `claude -p` as the CLI form of the Agent SDK for scripts, recommends `--bare` for scripted/SDK calls (to become the default for `-p`), and states that bare mode never reads OAuth credentials, so an API key is required; the project's integration contract forbids `--bare` precisely to keep OAuth working.
- EVIDENCE: https://code.claude.com/docs/en/headless (retrieved 2026-11-03): "The Agent SDK … is available as a CLI for scripts and CI/CD"; "`--bare` is the recommended mode for scripted and SDK calls, and will become the default for `-p` in a future release."; "In bare mode, Claude Code never reads OAuth credentials or the system keychain. For the Anthropic API, set ANTHROPIC_API_KEY in the environment, with a key created in the Claude Console …"; "Set ANTHROPIC_API_KEY before running it, because bare mode doesn't use your subscription login"; on cost fields: "With --output-format json, the response payload includes total_cost_usd … Both figures are client-side estimates and can differ from your actual bill." Also documents `--json-schema` ("structured output in the structured_output field") and `--max-budget-usd`. Project docs: docs/CLAUDE_INTEGRATION.md:33 ("**Never** `--bare` (disables OAuth, FACTS §3)"); runner.py:123-146 does not pass `--bare`; cost parsing relies on `total_cost_usd` (docs/CLAUDE_INTEGRATION.md:122, budget guardrails :401-406).
- IMPLICATION: Docs and code disagree with Anthropic's recommended scripted mode: when `--bare` becomes the `-p` default, the current OAuth-based runner stops authenticating unless an API key is present or an opt-out flag exists. The app's per-call/daily/monthly budgets are built on a client-side estimate; under subscription auth it is not a bill at all, under an API key it approximates the Console invoice.

### [anthropic-policy-13] (high) Official recommendation for a product backend: Messages API / Client SDK rather than the CLI

- CLAIM: Anthropic's own decision table steers code that only needs model calls to the Client SDK/Messages API, reserving the Agent SDK/CLI for workloads that need Claude Code's agent loop and tools; the app disables all tools, so it uses none of what the CLI adds.
- EVIDENCE: https://code.claude.com/docs/en/agent-sdk/overview (retrieved 2026-11-03), "Compare the Agent SDK to other Claude tools": "Call the Claude API directly from your own code → Client SDK → Direct access to the Claude API from any of the client SDK languages. You write the tool loop yourself …"; "Embed Claude Code's agent in your own Python or TypeScript application … → Agent SDK"; "To drive the same agent loop from a language other than Python or TypeScript, run the CLI as a subprocess with the -p flag and --output-format json." https://code.claude.com/docs/en/legal-and-compliance: "Developers building products or services that interact with Claude's capabilities … should use API key authentication through Claude Console …" https://support.claude.com/en/articles/17154008-…: "API credits cover claude -p and the Claude Agent SDK when you run them yourself with an API key from your linked Claude Console organization, because that usage is billed as Agent SDK usage." Code: runner.py:131-132 passes `--tools ""`; tier 1 adds `--restricted --strict-mcp-config --disable-slash-commands` (runner.py:48, :143-144) to strip the coding-assistant surface.
- IMPLICATION: `claude -p` + API key is permitted and supported, but for this workload (schema-constrained JSON generation, no tools) the Messages API with structured outputs, prompt caching and the 50% Batch API is the path Anthropic documents for products, removes the CLI binary/login/Keychain dependency from the server, and gives server-side usage accounting instead of a client-side estimate.
