# Fact slice: apple-appstore (34 findings)

## Summary

Nothing on Apple's side blocks an individual from shipping a word-Dance iOS client, but five things decide the shape of the work. (1) Toolchain: since 28 Apr 2026 uploads must be built with Xcode 26+/iOS 26 SDK, Xcode 27 is accepted since 9 Sep 2026 and becomes mandatory April 2027; the owner Mac (macOS 26.7.1, arm64, 823 GiB free) already meets the macOS 26.6 floor of today's Xcode 27.2 (3.12 GB download) but has no Xcode installed; no-Mac routes exist (Xcode Cloud 25 h/month included, EAS 15 free iOS builds/month, GitHub macOS runners $0.062/min). (2) Review: the obvious parity route, a WKWebView/Capacitor shell, is exactly what Guideline 4.2 ("repackaged website") rejects, and the current backend would also break it: the CSRF rule only accepts the host or WD_PUBLIC_URL origin and the session is a SameSite=Lax cookie, so a bundled-asset shell cannot call the API without backend changes, while loading the remote URL instead is the 4.2 anti-pattern. (3) Compliance that is already satisfied in code: username/password-only auth (4.8 exemption), in-app account deletion (DELETE /api/account), a report endpoint plus admin queue and user deactivation (most of 1.2); gaps are an in-app privacy-policy link and published contact info, an explicit named disclosure/consent before learner-typed text is sent to Anthropic (5.1.2(i), Nov 2025), a demo account or invite because registration defaults to invite-only, and privacy-label/retention statements covering public words and raw Claude logs that outlive the account. (4) China: offering the app on the mainland storefront requires an MIIT APP 备案 number entered in App Store Connect (new apps since Sept 2023), which in practice needs a mainland-hosted server filed through a licensed access provider and, for an individual, a non-commercial app; AI-generated content has been grounds for China removals since Aug 2023 under the gen-AI/deep-synthesis rules, and Anthropic does not list mainland China/HK/Macau/Taiwan as supported regions; deselecting China mainland avoids the ICP field entirely. (5) Alternatives: TestFlight (100 internal / 10,000 external, 90-day builds, Beta App Review on the first build of each version) is a real distribution channel for a beta; Ad Hoc is 100 devices/year; EU web distribution is irrelevant. The PWA option is stronger than it was: iOS 26 opens every Home-Screen site as a web app with zero installability requirements, Web Push/Badging work for Home-Screen apps (Declarative Web Push since 18.4) and Home-Screen storage is exempt from the 7-day ITP purge, but word-Dance today ships no manifest, service worker, apple-touch-icon or Web Push backend, and PWAs still lack background sync, widgets, local notification triggers and App Store discoverability.

### [apple-appstore-7] (high) Toolchain – Capacitor requirement

- CLAIM: Capacitor 8 (current) requires Xcode 26.0 minimum, Node 22+, and uses Swift Package Manager by default (CocoaPods optional).
- EVIDENCE: https://capacitorjs.com/docs/getting-started/environment-setup (retrieved 2026-11-03): "Capacitor 8 requires a minimum of Xcode 26.0", "NodeJS 22 or higher".
- IMPLICATION: The React 19 SPA can be wrapped with Capacitor 8 on the owner Mac's toolchain, but see the 4.2 and CSRF findings before choosing that route.

### [apple-appstore-8] (high) Toolchain – App Transport Security

- CLAIM: iOS apps (native or WKWebView) block cleartext HTTP by default under App Transport Security and require TLS 1.2+, SHA-256 certificates, RSA≥2048/ECC≥256 and forward secrecy; word-Dance's HTTPS is optional (reverse proxy section) and the Secure cookie flag is only set when WD_PUBLIC_URL is https.
- EVIDENCE: https://developer.apple.com/documentation/security/preventing-insecure-network-connections (retrieved 2026-11-03): "ATS blocks connections that don't meet minimum security requirements ... App Transport Security has blocked a cleartext HTTP (http://) resource load"; code: docs/DEPLOY.md:360-362 ("Reverse proxy and HTTPS (optional)"), backend/wd/config.py:146-147 (public_url_is_https), backend/wd/security.py:222-238 (cookie secure only via https/X-Forwarded-Proto).
- IMPLICATION: The public server must have a real certificate and domain before any iOS client (or App Review) can reach it; the LAN http:// mode used on the Mac is not usable from an iOS app without ATS exceptions that reviewers question.

### [apple-appstore-9] (high) Code constraint – session cookie + CSRF origin rule vs an app shell

- CLAIM: Non-GET API calls are rejected unless the Origin header equals the request's host origin or the WD_PUBLIC_URL origin (plus http://localhost:5173 in dev), the session is an HttpOnly SameSite=Lax cookie with no token/Bearer alternative, and the SPA fetches with credentials 'same-origin'; a Capacitor/WKWebView shell serving bundled assets (origin capacitor://localhost) therefore cannot log in or mutate anything without backend changes, and the only zero-change alternative is loading the remote site URL in the WKWebView.
- EVIDENCE: backend/wd/deps.py:111-129 (csrf_violation: allowed = {host_origin, cfg.public_origin}, else "Origin mismatch"); backend/wd/deps.py:35 (DEV_ORIGIN); backend/wd/security.py:6 and :229-238 (cookie wd_session, httponly, samesite=lax); frontend/src/api/client.ts:101-103 (X-WD-Request header, credentials: 'same-origin'); backend/wd/config.py:159-161 (public_origin from WD_PUBLIC_URL).
- IMPLICATION: Feature parity via a webview shell needs either (a) an allow-list of app origins and cookie handling in the shell, or (b) a token-based auth path for a native client; option (c) 'load the website in a WKWebView' is the 4.2 'repackaged website' pattern.

### [apple-appstore-10] (high) App Review 4.2 Minimum Functionality

- CLAIM: Guideline 4.2 requires "features, content, and UI that elevate it beyond a repackaged website" and 4.2.2 bars apps that are primarily web clippings; a developer reported a hybrid app with a native shell but 2–3 WKWebView screens rejected ten times under 4.2 in Nov 2025, and Apple's forum staff pointed to 'Meet with Apple' App Review consultations rather than a written threshold.
- EVIDENCE: https://developer.apple.com/app-store/review/guidelines/ (retrieved 2026-11-03) §4.2: "Your app should include features, content, and UI that elevate it beyond a repackaged website. If your app is not particularly useful, unique, or 'app-like,' it doesn't belong on the App Store"; §4.2.2: "Other than catalogs, apps shouldn't primarily be marketing materials, advertisements, web clippings, content aggregators, or a collection of links"; https://developer.apple.com/forums/thread/806726 (Nov 2025).
- IMPLICATION: A pure WKWebView wrapper of the SPA is the highest-risk submission; reviewers look for native-feeling navigation, offline/local state, push, widgets or device integration reachable from the first screen.

### [apple-appstore-11] (high) App Review 4.8 Login Services / Sign in with Apple

- CLAIM: Sign in with Apple (or an equivalent privacy-preserving login) is required only when a third-party or social login (Facebook, Google, WeChat…) sets up the primary account; an app that "exclusively uses your company's own account setup and sign-in systems" is exempt, and word-Dance has only username+password registration/login with an optional invite code.
- EVIDENCE: Guidelines §4.8 (retrieved 2026-11-03): "Another login service is not required if: Your app exclusively uses your company's own account setup and sign-in systems"; code: backend/wd/routers/auth.py:79-80 (POST /api/auth/register), :120-121 (POST /api/auth/login), backend/wd/schemas.py:179-184 (RegisterRequest: username, password, display_name, email, invite_code), :234-236 (LoginRequest); grep of backend/wd and frontend/src for oauth|wechat|google|sign-in found no third-party login.
- IMPLICATION: No Sign in with Apple work is needed unless WeChat/Google login is added later, at which point Sign in with Apple becomes mandatory.

### [apple-appstore-12] (high) App Review 5.1.1(v) account deletion

- CLAIM: Apps supporting account creation must let people initiate deletion of the entire account in-app (deactivation-only and support-ticket flows are insufficient; a web link is acceptable only as the completion step); word-Dance already exposes DELETE /api/account with password re-entry, cascades the user row, deletes orphaned private words, but keeps public words the user created (created_by_user_id set NULL) and keeps raw Claude call logs on disk.
- EVIDENCE: Guidelines §5.1.1(v): "If your app supports account creation, you must also offer account deletion within the app"; https://developer.apple.com/support/offering-account-deletion-in-your-app/ (retrieved 2026-11-03): "only offering to temporarily deactivate or disable an account is insufficient", "Apps not operating in highly regulated industries should not require people to make a phone call, send an email ..."; code: backend/wd/routers/account.py:89-114 (delete_account), :99-110 (private orphan purge only), docs/SCHEMA.sql:197 (created_by_user_id ... ON DELETE SET NULL), frontend/src/pages/SettingsPage.tsx:548,621 and frontend/src/api/endpoints.ts:385; backend/wd/ai/runner.py:12 and :289-290 (raw stdout/stderr saved under claude-logs/YYYY-MM-DD/<id>.json), docs/CLAUDE_INTEGRATION.md:168-178 (lookup output echoes the learner's input string).
- IMPLICATION: The iOS client must surface the same deletion flow (native call to DELETE /api/account or the settings page); the privacy policy must state that de-identified public words and AI call logs are retained after deletion, or the logs must be purged on deletion.

### [apple-appstore-13] (high) App Review 2.1(a) completeness / demo account

- CLAIM: Submissions with a login must include demo-account credentials and have the back-end switched on; word-Dance's registration mode defaults to invite-only (open/invite/closed) with the first registrant becoming admin, so a reviewer cannot self-register without an invite code or pre-made account.
- EVIDENCE: Guidelines §2.1(a): "include demo account info (and turn on your back-end service!) if your app includes a login"; https://developer.apple.com/distribute/app-review/ (retrieved 2026-11-03): "If some features require signing in, provide a valid demo account username and password"; code: backend/wd/config.py:77 (registration_mode: str = "invite"), :321 (WD_REGISTRATION_MODE), backend/wd/routers/auth.py:94-98 (closed → reject, invite → consume_invite), README.md:59 (first account becomes admin).
- IMPLICATION: Create a reviewer account with content pre-generated (so AI/budget pauses do not blank the demo) and put it in App Review notes; the public server must be reachable from Apple's US reviewers.

### [apple-appstore-14] (high) App Review 1.2 User-Generated Content

- CLAIM: Apps where users contribute content (explicitly including AI content creation apps) must have a filter for objectionable material, a report mechanism with timely responses, the ability to block abusive users, and published contact information; 1.2 was tightened three times in 2026 (anonymous chat on 6 Feb, developer responsibilities on 8 Jun, and on 16 Oct explicit coverage of AI-generated nonconsensual imagery with Developer Code of Conduct consequences). Word-Dance has the report endpoint, an admin report queue, admin user deactivation and a safe_for_sharing gate on publishing user words, but no in-app contact information or privacy link.
- EVIDENCE: Guidelines §1.2 (retrieved 2026-11-03): "A method for filtering objectionable material ... A mechanism to report offensive content and timely responses ... The ability to block abusive users ... Published contact information"; https://developer.apple.com/news/?id=d75yllv4 (2026-02-06); ?id=a233fmpw (2026-06-08): "1.2: new paragraph clarifies developer responsibilities"; ?id=vvzx6cul and ?id=92th7e5i (2026-10-16): "Content moderation requirements now explicitly cover nonconsensual intimate imagery — including imagery generated using AI tools"; code: backend/wd/routers/words.py:259-284 (POST /api/words/{id}/report, daily cap), backend/wd/schemas.py:36 (ReportReason), docs/SCHEMA.sql:552-566 (content_reports), backend/wd/routers/admin_reports.py:57,71, backend/wd/routers/admin_users.py:97-105 (is_active deactivation), backend/wd/ai/lookup.py:354-359 (is_public = safe_for_sharing), docs/CLAUDE_INTEGRATION.md:214 (content prompt forbids sensitive topics); grep of frontend/src/i18n/zh.ts for 隐私|privacy|联系|contact returned nothing.
- IMPLICATION: Most of 1.2 is already engineered; add an in-app 'contact & privacy' entry (and keep the admin report queue staffed) and describe the safe_for_sharing filter in review notes; user notes are private (SCHEMA.sql:285) and are not UGC.

### [apple-appstore-15] (high) App Review 5.1.2(i) third-party AI disclosure

- CLAIM: Since 13 Nov 2025 apps must "clearly disclose where personal data will be shared with third parties, including with third-party AI, and obtain explicit permission before doing so"; word-Dance sends learner-typed strings (lookup), bank headwords plus the first 120 characters of a private note (consolidation) and dictionary-only data (content) to Anthropic through the operator's `claude -p` login, with no user identifiers.
- EVIDENCE: https://developer.apple.com/news/?id=ey6d8onl (2025-11-13): "5.1.2(i): Clarifies that you must clearly disclose where personal data will be shared with third parties, including with third-party AI, and obtain explicit permission before doing so"; Guidelines §5.1.2(i) full text (retrieved 2026-11-03); code: backend/wd/ai/lookup.py:63-65 ("raw strings only, no user identifiers"), backend/wd/ai/consolidate.py:48 (NOTE_MAX = 120), :126-128 (note added to prompt item), backend/wd/ai/content.py:86-93 (dictionary data only), docs/CLAUDE_INTEGRATION.md:239 ("No per-user data is ever included"), :275 (note is sent only in consolidation), :3 (claude CLI authenticated via operator login, no API key), backend/wd/ai/runner.py:124-149 (argv).
- IMPLICATION: The iOS app needs a one-time, named disclosure ('your typed words and notes are sent to Anthropic Claude to generate study content') with explicit opt-in before the first add-word action, mirrored in the privacy policy and in the 'User Content shared with third parties' privacy label; strictly, the web app should get the same.

### [apple-appstore-16] (high) App Review 5.1.1(i) privacy policy and privacy nutrition labels

- CLAIM: A privacy-policy link is required both in App Store Connect metadata and inside the app, and privacy details (nutrition labels) covering the developer's and third-party code's data collection are mandatory for every new app and update; word-Dance collects username, optional e-mail, learner notes, review logs, client IPs (rate limiting) and server logs keyed by user_id.
- EVIDENCE: Guidelines §5.1.1(i): "All apps must include a link to their privacy policy in the App Store Connect metadata field and within the app"; https://developer.apple.com/app-store/app-privacy-details/ (retrieved 2026-11-03): required for all new apps and updates; 'Data Linked to You' vs 'Not Linked' vs 'Used to Track You'; code: backend/wd/schemas.py:179-184, docs/SCHEMA.sql:114-118 (auth_throttle keys 'login:ip:1.2.3.4'), :285 (user note ≤500 chars), :325-334 (review_logs), backend/wd/routers/account.py:111 (log with user_id).
- IMPLICATION: Expect labels: Contact Info (e-mail, optional), Identifiers (user ID), User Content (notes, added words), Usage Data (study logs); no tracking; images are fetched server-side so Wikimedia/Openverse never see the device.

### [apple-appstore-17] (high) Age ratings (2025–2026 questionnaire)

- CLAIM: Apple replaced 12+/17+ with 13+/16+/18+ on 24 Jul 2025 and required all apps to answer the new questionnaire by 31 Jan 2026; a 'Social Media' question (redistribute/amplify/interact with UGC through a feed) is mandatory for new apps and updates since Sept 2026, and two new descriptors (Shared Location; Dating and Relationships) must be answered from 16 Nov 2026 with all apps done by 12 Jan 2027. 'User-Generated Content' and 'Messaging and Chat' are capabilities listed from 4+, while 'Unrestricted Web Access' (embedded browser) maps to the upper tiers.
- EVIDENCE: https://developer.apple.com/news/upcoming-requirements/ (retrieved 2026-11-03): "Provide responses to the updated age rating questions for each of your apps by January 31, 2026"; https://developer.apple.com/news/?id=tlur8uvi (2026-07-09): "A social media capability is defined as the ability to redistribute, amplify, or interact with user-generated content through a social feed or similar discovery method", "Beginning in September 2026, responses will be required"; https://developer.apple.com/news/?id=yxkh08us (2026-11-02): "Starting November 16, 2026 ... ### [apple-appstore-18] (high) Export compliance (ITSAppUsesNonExemptEncryption)

- CLAIM: Uploads go to a US server so US export rules apply regardless of the developer's country; encryption built into the OS (HTTPS via URLSession/WKWebView) is exempt from documentation, and setting ITSAppUsesNonExemptEncryption=NO in Info.plist skips the per-upload questionnaire, though Apple notes an exempt app 'might alternatively be required to submit a year-end self-classification report to the U.S. government'.
- EVIDENCE: https://developer.apple.com/documentation/security/complying-with-encryption-export-regulations (retrieved 2026-11-03): "If you distribute your app outside the U.S. or Canada, your app is subject to U.S. export laws, regardless of where your legal entity is based", "Typically, the use of encryption that's built into the operating system—for example, when your app makes HTTPS connections ... is exempt", "you might alternatively be required to submit a year-end self-classification report"; https://developer.apple.com/documentation/bundleresources/information-property-list/itsappusesnonexemptencryption (retrieved 2026-11-03).
- IMPLICATION: Set the key to NO; no documents needed as long as the client only speaks HTTPS; keep the BIS annual self-classification question in mind (open).

### [apple-appstore-19] (high) App Review 3.1.1 and China commission

- CLAIM: Any future unlock of features (subscriptions, premium content) must go through In-App Purchase; on the China mainland storefront Apple's commission dropped to 25 % (12 % for Small Business Program and post-first-year subscription renewals) on 15 Mar 2026.
- EVIDENCE: Guidelines §3.1.1 (retrieved 2026-11-03): "If you want to unlock features or functionality within your app ... you must use in-app purchase"; https://developer.apple.com/news/?id=dadukodv (2026-03-12): "Reduced from 30% to 25%", "from 15% to 12%" effective March 15, 2026.

### [apple-appstore-20] (medium) Kids / minors

- CLAIM: Apps may not use 'for kids/children' wording outside the Kids Category, apps that collect personal data from minors must have a privacy policy and comply with children's privacy law, and word-Dance's stated audience includes 初中 (junior-high, typically 12–15) learners while registration collects no birthdate.
- EVIDENCE: Guidelines §5.1.4 and §2.3.8 (retrieved 2026-11-03): "Apps not in the Kids Category cannot include any terms ... that imply the main audience for the app is children", "apps ... that collect, transmit, or have the capability to share personal information ... from a minor must include a privacy policy"; code: backend/wd/schemas.py:51 (STAGE_NAMES_ZH zk=初中), :179-184 (no age field).
- IMPLICATION: Market it as a general learner app (not 'for kids'); decide whether an age/guardian step is needed under PIPL for under-14s (out of this slice).

### [apple-appstore-21] (high) China App Store – ICP filing field in App Store Connect

- CLAIM: App Store Connect has an 'ICP Filing Number' section under App Information for apps distributed in China mainland, required by MIIT; the number and metadata must match the MIIT filing (Simplified Chinese localisation or primary language), it is shown on the product page once verified, and games/books/religious/news content need further NPPA or other permits; if China mainland is removed from availability the field does not apply.
- EVIDENCE: https://developer.apple.com/help/app-store-connect/reference/app-information/ (retrieved 2026-11-03): "The ICP number and metadata on the App Information page should match with the information you have filed with MIIT", "Once the provided ICP Filing Number is verified and saved, it will be displayed on your App Store product page", "If applicable, provide the required ICP filing information in the designated section under the 'App Information' tab"; https://developer.apple.com/forums/thread/743661 (posts Dec 2023 / Mar 2024): "If outside China, this is not a requirement", "If your app needs to be listed on the App Store and provide services to users in mainland China, you must fill in the ICP filing number".
- IMPLICATION: Shipping worldwide-except-China needs no ICP at all; shipping to mainland users on the App Store requires the filing before the first China release.

### [apple-appstore-22] (medium) China App Store – what the filing is (备案 vs 许可证) and who can get it

- CLAIM: MIIT's notice of 4 Aug 2023 (工信部信管〔2023〕105号) requires every APP providing internet information services inside China to complete 备案 (filing) via its network access provider or distribution platform, forbids operating without it, obliges platforms to verify, sets a 20-working-day issuance target, and states that apps started after the notice must file before launch; the existing-app window ran Sept 2023–Mar 2024 with inspections Apr–Jun 2024. An ICP 许可证 (licence) is a separate requirement for 经营性 (commercial) services; practitioner sources state that individual (个人) filings are accepted only for non-commercial apps and that filing goes through a mainland IDC/access provider, so a server hosted outside mainland China cannot be filed.
- EVIDENCE: https://www.miit.gov.cn/zwgk/zcwj/wjfb/tz/art/2023/art_920db564162e4312916a01bed6540ad8.html (2023-08-04, retrieved 2026-11-03 via curl): "未履行备案手续的，不得从事APP互联网信息服务", "由其网络接入服务提供者、APP分发平台 ... 通过'国家互联网基础资源管理系统' ... 采取网上提交申请、查验审核方式进行", "应在二十个工作日内予以备案", "在本通知发布后拟开展业务的APP，应按照本通知要求先履行备案手续后再开展业务", "存量APP备案阶段（2023年9月-2024年3月）... 监督检查阶段（2024年4月-2024年6月）"; secondary (retrieved 2026-11-03): https://www.secrss.com/articles/58923, https://zhuanlan.zhihu.com/p/654083172, https://www.netokok.com/sys-nd/163.html (individual filing non-commercial only; mainland server via licensed provider required).
- IMPLICATION: A China-storefront release forces a mainland-hosted backend filed under the owner's 身份证 (non-commercial) or a company, which collides with the Claude dependency (next finding); the realistic first step is to exclude China mainland from availability.
