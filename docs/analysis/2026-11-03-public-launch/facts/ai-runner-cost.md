# Fact slice: ai-runner-cost (33 findings)

## Summary

word-Dance's AI layer is a thin, well-isolated shell around `claude -p`: every handler (content/lookup/consolidate/svg) only sees `ClaudeResult` (interfaces.py:83-92) produced by `runner.run_claude`, which spawns the CLI with an env allow-list, parses the CLI's JSON envelope (`total_cost_usd`, `structured_output`, `subtype`, `modelUsage`, `session_id`) and classifies outcomes with regexes. Authentication today is exclusively the service user's claude.ai OAuth login (credentials in `$HOME/.claude*`, Keychain on macOS); `ANTHROPIC_API_KEY/AUTH_TOKEN/BASE_URL` are passed through from the process environment and nothing else — no `Settings` field, no `.env` support (install.sh rejects non-`WD_` lines), no doc, and every operator hint, banner and the systemd `ProtectHome` comment assume "log in as sqin". Anthropic's current Claude Code legal page (retrieved 2026-11-03) says OAuth login is for the subscriber's own ordinary use and developers "may not route requests through plan credentials on behalf of their users", so a public server or App Store app must move to Console API-key billing; in that mode the ledger's `cost_usd` (computed by the CLI at list price) becomes real money and all caps become real. Measured on this Mac (claude 2.1.292, claude-sonnet-5-5, tier 1): $0.0531 per 10-word content call ($0.0053/word, 30 s, 3.8k output tokens), $0.0120 per 1-word call, $0.0124 per SVG card, $0.0198 per consolidation, $0.0036 per probe; 62% of the $0.66 spent so far went to SVG fallbacks because 30 of the first 33 studied words got no photo. Default caps ($3/day, $40/month, 60 calls/hour, $1/day prewarm, $0.50/day SVG, concurrency 1-3) are tuned for one person: a full seed prewarm (9,162 words ≈ 917 calls ≈ $37-49) would take 37-49 days under the prewarm sub-cap, and at 100 DAU the nightly consolidation alone ($2-5/night) or new-word demand ($13/day pre-saturation) hits the daily cap, while at 1,000 DAU the 60 calls/hour ceiling (1,440 calls/day, shared by every kind) cannot even finish the nightly consolidations (1,000 calls ≈ 16.7 h). Every dollar cap is global and deferral is global ("今日 AI 额度已用完"), so one registered user exhausting the 200 adds/day quota (~$5 of lookups+content+SVG) can starve everyone; there is no per-user spend attribution in `ai_calls`. Replacing the CLI with the Messages API is a contained change behind the `ClaudeRunner` seam (new runner, status mapping, cost table, schema transform because structured outputs reject `maxItems`/`minItems>1` and require `additionalProperties:false`, config/deploy/docs, and a rewrite of the subprocess-based test double used by ~10 test files, smoke and dev scripts), and it would also remove the `/home/sqin`, Keychain, no-Docker and no-`ProtectHome` constraints. Data safety is strong by design (only normalised ≤48-char strings and, in the private consolidation prompt, a ≤120-char sanitised note reach Claude; `--tools ""`, empty cwd, schema + server post-validation), but raw prompts/outputs are kept 14 days on disk and the publish decision for a stranger's typed word rests on Claude's `safe_for_sharing` boolean.

## Findings

### [ai-runner-cost-1] (high) (a) auth path today

- CLAIM: The only supported credential is the service user's claude.ai OAuth login found by the CLI under HOME; the runner builds the child env from an allow-list (HOME, PATH, LANG, LC_ALL, TERM, NO_COLOR, TZ) with HOME = WD_CLAUDE_HOME or the parent's HOME, falling back to the literal '/home/sqin', and never passes --bare (tier 0 and tier 1 argv are fixed lists).
- EVIDENCE: backend/wd/ai/runner.py:6 ('Never --bare'), :124-149 (build_argv), :158-174 (claude_env), :162 (HOME fallback '/home/sqin'); backend/tests/unit/test_runner.py:96 asserts '--bare' absent; docs/CLAUDE_INTEGRATION.md:33 ('Never --bare (disables OAuth)'), :78-86; deploy/word-dance.service:15-16 (Environment=HOME=/home/__USER__, PATH), :33-34; https://code.claude.com/docs/en/iam (retrieved 2026-11-03: 'Bare mode does not read CLAUDE_CODE_OAUTH_TOKEN. If your script passes --bare, authenticate with ANTHROPIC_API_KEY or an apiKeyHelper instead'; credentials on Linux in ~/.claude/.credentials.json 0600, on macOS in the Keychain)
- IMPLICATION: A cloud VM must give the service user a real home directory holding an interactive browser login (or a code change to accept CLAUDE_CODE_OAUTH_TOKEN), or switch to an API key; the same login then serves every public user, which is the model Anthropic's terms disallow (see the terms finding).

### [ai-runner-cost-2] (high) (a) ANTHROPIC_* support is passthrough only

- CLAIM: ANTHROPIC_API_KEY, ANTHROPIC_AUTH_TOKEN and ANTHROPIC_BASE_URL are copied from the server process environment into the claude child env when non-empty and are read nowhere else: Settings has no field for them, Settings.from_env only reads WD_* variables, the .env validator in install.sh rejects any non-WD_ line, SECRET_KEYS masking covers only WD_ keys, and the unit sets only HOME/PATH/PYTHONUNBUFFERED/LANG.
- EVIDENCE: backend/wd/ai/runner.py:49-62 (PASSTHROUGH_ENV), :170-173; repo-wide grep for ANTHROPIC hits only runner.py, docs and test_runner.py:125,134; backend/wd/config.py:44-53 (SECRET_KEYS), :201-205 (WD_ only), :84-108 (claude fields: bin/home/path/cwd, no key); deploy/install.sh:110-113 (regex ^WD_[A-Z0-9_]+=...); backend/tests/unit/test_deploy_files.py:108,119; deploy/word-dance.service:15-17; macOS launchd plist ~/Library/LaunchAgents/com.word-dance.server.plist EnvironmentVariables (WD_DATA_DIR, HOME, PATH, LANG, PYTHONUNBUFFERED only)
- IMPLICATION: API-key billing works today only by injecting the key into the service environment outside .env (a systemd drop-in Environment= or second EnvironmentFile=, or the macOS plist/wrapper); a clean switch needs a WD_ANTHROPIC_API_KEY (or similar) setting mapped into claude_env plus SECRET_KEYS masking, install.sh/env.example/DEPLOY changes, and tests.

### [ai-runner-cost-3] (high) (a) CLI precedence makes a key take over silently

- CLAIM: Per Anthropic's current docs, in non-interactive -p mode ANTHROPIC_API_KEY is 'always used when present' and outranks the subscription login (ANTHROPIC_AUTH_TOKEN outranks both), so setting the key in the service environment flips billing to the Console organisation with no repo change; the repo's auth classifier already recognises 'invalid api key'.
- EVIDENCE: https://code.claude.com/docs/en/iam 'Authentication precedence' items 2-3 and 7 (retrieved 2026-11-03); backend/wd/ai/runner.py:71 (AUTH_RE includes 'invalid api key'), :272-273
- IMPLICATION: Operationally the switch is a one-variable change, but the admin banner, CLI hints and runbook would still tell the operator to 'log in as sqin' on an auth failure (see next finding).

### [ai-runner-cost-4] (high) (a) what an API-key switch must touch in this repo

- CLAIM: Operator-facing auth texts and preflight assume an interactive login: the admin banner stored in system_events says '请以 sqin 身份运行 claude 完成登录', probe and diag print 'run claude once as sqin to log in', DEPLOY's runbook says 'sudo -iu sqin claude', install.sh's preflight only demands a claude binary in PATH (exit 1) and treats a failed paid probe as a warning, and the unit deliberately omits ProtectHome because '/home/sqin/.claude' must be writable (pinned by a test).
- EVIDENCE: backend/wd/ai/common.py:37 (AUTH_BANNER_ZH), :264-279 (auth → 30-min pause + event with banner); backend/wd/ai/probe.py:200; backend/wd/diag.py:99; docs/DEPLOY.md:420; deploy/install.sh:11,48-49 (binary required), :142-143 (claude-check warns only); deploy/word-dance.service:33-34; backend/tests/unit/test_deploy_files.py:186 (asserts ProtectHome not set); docs/DESIGN.md:105 (Docker rejected because credentials live in /home/sqin/.claude*); docs/CLAUDE_INTEGRATION.md:86 ('Running the worker in Docker is explicitly unsupported')
- IMPLICATION: With an API key the correct remediation becomes 'check the key / Console credit', ProtectHome=yes becomes possible if the data dir and WD_CLAUDE_HOME leave /home (config.py:86,329 and runner.py:162 already support a separate HOME), and the Docker prohibition loses its premise; each of these is a doc+test+text change, none is deep.

### [ai-runner-cost-5] (high) (a) terms of use for a public service

- CLAIM: Anthropic's Claude Code legal page states OAuth authentication 'is intended exclusively for purchasers of ... subscription plans and is designed to support ordinary use', that developers building products 'should use API key authentication through Claude Console', that 'Anthropic does not permit third-party developers ... to route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users', that 'Customers may not pay for, resell, or intermediate Claude usage on their end users' behalf', and that advertised plan limits 'assume ordinary, individual usage'; the Mac install uses a claude.ai Enterprise login according to the project memory.
- EVIDENCE: https://code.claude.com/docs/en/legal-and-compliance (retrieved 2026-11-03, sections 'Can customers offer Claude Code in their products?' and 'Authentication and credential use'); memory note claude-cli-macos-needs-login-env.md (2026-11-02: 'claude.ai enterprise login, OAuth credentials in the login Keychain'); docs/CLAUDE_INTEGRATION.md:3 (verified 'authenticated for user sqin, no ANTHROPIC_API_KEY')
- IMPLICATION: Serving strangers (web or iOS) from the operator's subscription login is outside the permitted use and, for an employer-owned Enterprise seat, outside the operator's control; a public deployment needs a Console organisation and API key, which also changes the economics from 'included in subscription' to per-token spend.

### [ai-runner-cost-6] (high) (a)/(c) what cost_usd means under each auth mode

- CLAIM: The ledger's cost_usd is the CLI's total_cost_usd, which Claude Code 'computes ... locally from token counts at list price'; for subscribers 'usage [is] included in their subscription, so the session cost figure isn't relevant for billing', whereas under an API key it approximates the real bill; the same list-price figure is what --max-budget-usd compares against.
- EVIDENCE: backend/wd/ai/runner.py:238-241 (cost = total_cost_usd), :340-369 (ledger.finish_call); docs/CLAUDE_INTEGRATION.md:71 ('cost_usd ... recorded even when the call failed'); https://code.claude.com/docs/en/costs (retrieved 2026-11-03, 'Using the /usage command' note and 'Claude Code computes the dollar figure locally from token counts at list price'; '--max-budget-usd' counts the multiplied list figure)
- IMPLICATION: Every dollar cap, bisection rule and admin figure in the app is a list-price model; today it protects a subscription's usage window only indirectly, and after the API switch it becomes a real spend guard whose defaults ($3/day, $40/month) must be re-tuned for the user count.

### [ai-runner-cost-7] (medium) (a) subscription usage-limit messages are misclassified

- CLAIM: The outcome classifier recognises 529/503/'rate limit'/'too many requests' as overloaded (defer, pause after 6) and 'not logged in'/'login'/'authentication'/401/'invalid api key'/'credential' as auth (30-min pause), but Claude Code's plan-limit messages 'You've hit your session limit' / 'weekly limit' / 'Sonnet limit' match neither and fall to error (backoff 2/10/60 min, dead after 3 attempts, content_state='failed'), 'You've hit your team's shared budget' matches BUDGET_RE and triggers bisection, and 'Request rejected (429)' has no pattern (no \b429\b).
- EVIDENCE: backend/wd/ai/runner.py:71-74 (AUTH_RE, BUDGET_RE, OVERLOADED_RE), :269-280; backend/wd/ai/common.py:226-247 (budget → bisect; error → fail), :248-263 (overloaded), :264-279 (auth); backend/wd/jobs/queue.py:31,173-195 (backoff, dead at max_attempts=3); https://code.claude.com/docs/en/errors (retrieved 2026-11-03: exact message strings); the exact stdout/stderr wording in -p JSON mode is not documented there
- IMPLICATION: Under a subscription, a 5-hour window exhaustion would kill queued jobs within ~72 minutes instead of deferring them; under an API key, a 429 from the Start-tier spend cap (no retry-after) would be an 'error' unless its body contains 'rate_limit'. Add \b429\b and the plan-limit phrases to OVERLOADED_RE (or treat them as a pause) before any multi-user launch.

### [ai-runner-cost-8] (high) (b) the seam for a Messages-API runner

- CLAIM: All four handlers and the probe depend only on the ClaudeResult dataclass (ok/status/structured/cost_usd/call_id/model_used/error) returned through common.claude_call → runner.run_claude, and the Runner class implements the ClaudeRunner Protocol, so a direct-API runner can replace runner.py without touching content/lookup/consolidate/svg application logic.
- EVIDENCE: backend/wd/interfaces.py:83-109; backend/wd/ai/common.py:133-184 (claude_call: reserve then runner.run_claude); backend/wd/ai/content.py:401-423; backend/wd/ai/lookup.py:538-548; backend/wd/ai/consolidate.py:500-509; backend/wd/ai/svg.py:109-119; backend/wd/ai/runner.py:498-532 (Runner)
- IMPLICATION: The replacement is a contained module swap plus plumbing, not a rewrite of the AI feature set.

### [ai-runner-cost-9] (high) (b) every dependency on the CLI JSON envelope

- CLAIM: Envelope fields are consumed only in runner.parse_and_classify (type/result line detection, is_error, subtype=='success', structured_output dict, total_cost_usd, modelUsage first key, session_id, duration_ms, usage.input/output/cache_read/cache_creation tokens, result text) and persisted by ledger.finish_call into ai_calls (model_used, session_id, exit_code, stdout_path, flag_tier NOT NULL DEFAULT 0, max_budget_usd NOT NULL); raw argv/stdout/stderr are saved by save_raw; the probe compares structured_output for exact equality; the 'budget' status exists only because of --max-budget-usd.

### [ai-runner-cost-12] (high) (b) schema translation needed for structured outputs

- CLAIM: The five production schemas use exactly {type, properties, required, items, minItems, maxItems, description, enum} (pinned by a test), with maxItems 12/20/80/4/2/15 and minItems 1-2, and no additionalProperties; Anthropic's Messages-API structured outputs (output_config.format type json_schema, or client.messages.parse with pydantic) support enum/required/description but reject maxItems, minItems other than 0/1, and require additionalProperties:false on every object; the pydantic mirrors used for post-validation already exist.
- EVIDENCE: backend/tests/unit/test_schemas.py:22,66-70; docs/CLAUDE_INTEGRATION.md:140-204 (§4 schemas); backend/wd/ai/models.py:12-34 (pydantic BaseModel mirrors); claude-api skill python/claude-api/tool-use.md 'Structured Outputs' (messages.parse / output_config.format); https://platform.claude.com/docs/en/build-with-claude/structured-outputs.md (retrieved 2026-11-03: supported/unsupported keyword lists, stop_reason 'refusal'/'max_tokens', 50% Batch discount applies)

### [ai-runner-cost-18] (high) (c) user-facing behaviour when caps hit

- CLAIM: A refused reservation defers the whole job group to the cap's resume instant (next WD_TZ day 00:05 for daily/prewarm/SVG, 1st of next month for monthly, next hour +1 min for hourly, paused_until for pauses, +30 min when AI is disabled) without consuming attempts; the API exposes it as deferred_until / content_deferred_until, clients stop polling and show '今日 AI 额度已用完，例句将在明天补齐'; an explicit content request returns 409 budget_exhausted{resumes_at} or 503 ai_disabled; queued lookups are flagged '暂时无法校验' only when the kill switch is off; one budget_daily/budget_monthly/budget_svg system event is written per day.

### [ai-runner-cost-19] (high) (c)/(f) budget is global, quotas are per user

### [ai-runner-cost-20] (high) (d) hard throughput ceilings

### [ai-runner-cost-21] (high) (d) concurrency and the single-process lease

### [ai-runner-cost-22] (medium) (d) 100 vs 1,000 daily active users
