# DESIGN D2-admin-workbench — The complete admin workbench: the shared library becomes an admin-curated, versioned artefact. A library API + page (list/search by source, visibility, validity, content/image state, creator; publish/unpublish; validate; merge/rename; edit dictionary fields; hand-edit or roll back content; reject images; hide/takedown), a review queue for user-submitted words, a curator grant, content packs that move generated content from a compliant generator to the public server, export of curated words back to the seed, and library versioning with an audit trail. Phased so that the minimal subset (policy switch, review queue, pack import, takedown) ships before the first public user; the rest optimises long-term curation quality and contributor growth rather than minimal diff.
## SUMMARY
Today the library's three global layers are written by exactly three paths: the seed upsert (words/word_forms, backend/wd/seed.py:66-81), the Claude
generate_content handler (word_contents, backend/wd/ai/content.py:198-228) and images.store.activate (word_images, backend/wd/images/store.py:76-120); there is
no admin word CRUD, no review queue, no content import, and WD_AI_ENABLED=0 only idles the worker while user actions keep enqueueing jobs
(backend/wd/services/words.py:688-721, services/bank.py:465-477, jobs/scheduler.py:194-226). D2 turns the public server into a read-only consumer of an admin-
curated library and makes curation a first-class, audited workflow. The policy switch is a new env setting WD_AI_POLICY=live|admin_only|off (restart-only, never
flippable from the UI): it closes every end-user enqueue site at the source (no job, no content_state='queued'), skips nightly consolidation and prefetch,
reconciles already-queued user jobs at startup, and is reported to clients as ServerFlags.ai_mode so the SPA hides 生成例句 / 立即整理 and rewrites the 待校验 and 明天补齐
copy. Admin AI levers (prewarm, regenerate, refetch) stay available only where admin_ai_allowed() is true, which on the public server is false. Generation
happens off the public server: the recommended generator is a staging word-Dance instance run by a co-admin physically in a supported region with their own
personal Console API key through the existing claude -p runner (ANTHROPIC_API_KEY is already pass-through, backend/wd/ai/runner.py:49-62, plus --bare and a
classifier patch), pinned to claude-sonnet-5-5; the owner's mainland location and employer Enterprise seat rule the owner out as the AI operator, and the
current Mac deployment stops generating for anything public. A second, on-server engine is a new OpenAI-compatible runner adapter for a domestic model
(DeepSeek/Qwen/GLM/Doubao) behind the same ClaudeRunner protocol (backend/wd/interfaces.py:96-109) for admin-triggered long-tail generation, with a small human-
rated eval before it may write to the canon; hand-authored content covers corrections. Content travels as wdpack bundles (manifest + words/contents/images JSONL
keyed by lemma + content-addressed files) that are idempotent by content hash and imported in short chunked transactions next to the live service, never
touching jobs or per-user tables. The schema stays additive before launch (migration 0010: word_submissions, library_audit, library_versions, user_grants,
content_wishes, curation columns on words and word_contents, content_sha256) and the two CHECK-list widenings that need table rebuilds (word_images.provider
'upload', words.source 'admin') move to migration 0011 in the first month; the curator role is a grants table, not a users.role rebuild. Learners still grow the
library: adds resolve exact → form → ECDICT (so ECDICT must be installed on the public server), and only strings ECDICT does not know become a private
provisional row plus a word_submissions row that a curator approves, merges or rejects with no AI; approval reuses lookup.merge_into/rename_word and the seed's
trust semantics. The workbench UI is a 词库 tab plus a per-word page and a review-queue page inside /admin, built from the existing Pager/SearchBox/Tabs
primitives. Curated words flow back to data/seed through wd library export --format seed, and every curation write bumps kv library.revision and leaves an audit
row. The Mac's 48 contents and 30 SVGs were generated under the Enterprise seat; the recommended migration is to export them for the owner's personal instance
only and regenerate them on staging (about $1), importing nothing AI-generated from the Mac into the public server. The pre-launch subset is about 28.5 dev-
days, the first-month set about 18.5, and later work about 12.5, for roughly 59.5 dev-days in total.

any part of a personal public product, including prewarm; so "the admin runs prewarm with the current login" is rejected, and the current Mac deployment (OAuth,

supported region (Singapore, Japan, US …) will open a personal Anthropic Console organisation in that country with their own payment method and operate a
staging instance. (A4) The public server runs in a supported-region datacentre (Singapore/Tokyo per the earlier analysis) with no Anthropic credentials at all;
`ai_calls` on it stays empty and is the audit proof.  OPTION 1 — STAGING GENERATOR (primary for the bulk fill and periodic regeneration). WHERE: a staging word-
Dance instance (`wd serve`, WD_AI_POLICY=admin_only, WD_AI_ENABLED=1) on the co-admin's machine or a small VPS in a supported region, with a copy of the same

the staging admin UI (预生成 / 重新生成), i.e. an admin action on dictionary data, not on any end user's input. CREDENTIALS: `WD_ANTHROPIC_API_KEY` (new first-class
setting mapped into `claude_env` as ANTHROPIC_API_KEY, which is already on the allow-list, backend/wd/ai/runner.py:49-62; added to config.SECRET_KEYS so GET
/api/admin/config masks it) with `--bare` appended (today possible through WD_AI_EXTRA_ARGS, which build_argv appends verbatim at runner.py:147-148 and the fake
claude already tolerates, backend/tests/fake_claude.py BOOL_FLAGS; I make it a `cfg.ai_bare` flag). MODEL: pin `WD_AI_MODEL=claude-sonnet-5-5` (the id the
ledger already records as model_used); the content prompt and post-validation were only ever verified on sonnet (docs/CLAUDE_INTEGRATION.md:33). Budget: ≈
$0.004/word → whole seed ≈ $37–49 plus an image pass; raise WD_AI_DAILY/MONTHLY/PREWARM/HOURLY caps on staging only. Runner implications: build_argv unchanged
apart from --bare; `parse_and_classify` (runner.py:229-285) gains `\b429\b`, `enforced_spend_limit_reached`, `credit balance`, `insufficient` → classified as
`budget`/`overloaded` (deferral, not failure); AUTH_BANNER_ZH (backend/wd/ai/common.py:37) and probe.py:200 / diag.py:99 copy change from "以 sqin 身份登录" to "检查
WD_ANTHROPIC_API_KEY / Console 余额"; `ai_calls.model_used` still comes from `modelUsage` and cost from `total_cost_usd`, both present in API-key mode;
`word_contents.model` keeps the canonical id. Nothing else in the handlers changes. Output leaves staging as a content pack (see content_pack) and is imported
on the public server.  OPTION 2 — DOMESTIC MODEL ADAPTER ON THE SERVER (admin-triggered long tail; the only engine if Anthropic's written answer on cached
outputs is negative). WHERE: the public server itself (or staging). BY WHOM: admins/curators through the same admin levers under WD_AI_POLICY=admin_only; end
users never. CREDENTIALS: a provider key in `WD_LLM_API_KEY` with `WD_LLM_BASE_URL` (OpenAI-compatible chat/completions) and `WD_LLM_MODEL` (e.g. deepseek-chat,
qwen-plus, glm-4-plus, doubao-pro); owner-operated, no Anthropic involvement, and the registrable path if the product is ever hosted in the mainland
(PUBLIC_LAUNCH §2.4). Runner implications: `common.claude_call` calls `runner.run_claude` directly (backend/wd/ai/common.py:187), so a provider dispatcher is
needed: `WD_AI_PROVIDER=claude_cli|openai_compat` selects between the existing runner and a new `backend/wd/ai/runner_http.py` implementing the `ClaudeRunner`
Protocol (interfaces.py:96-109: run(conn, kind, system_prompt, user_prompt, schema, max_budget_usd, timeout_s, word_count, job_ids) → ClaudeResult). The HTTP
runner inserts the ledger row before the request (`ledger.insert_call`, kinds unchanged), sends system+user prompts with `response_format` json_object (schema-
level adherence is NOT guaranteed by DeepSeek/Qwen json mode; the existing server-side post-validation `content.validate_item` / `models.valid_items` is the
real gate, which is why this works at all), computes cost from `usage` × a price table (`WD_LLM_PRICE_IN_PER_MTOK`, `WD_LLM_PRICE_OUT_PER_MTOK`;
`total_cost_usd` does not exist), sets `model_used` from the response `model` field (ai_calls.model_used and word_contents.model are free text, so 'deepseek-
chat' fits and the UI can label it), and maps HTTP 401/403 → auth, 402/insufficient balance → budget, 429/5xx → overloaded, socket timeout → timeout, unparsable
JSON → the handlers' invalid_output path. Tier/probe/flag_tier are CLI concepts: `probe.check` gets a provider branch (one tiny JSON call), `claude-logs` saving
stores the raw response body instead of argv. Quality: there is no eval set in the repo; a `scripts/eval_content.py` (50 words, side-by-side sonnet vs
candidate, human-rated CSV) must pass before the adapter may write active versions; until then it writes versions with status 'superseded' for review.
Anthropic-compatible domestic endpoints via ANTHROPIC_BASE_URL/ANTHROPIC_AUTH_TOKEN pass-through (runner.py:54-56) work config-only with `claude -p` but their
`--json-schema` support and the CLI's self-computed `total_cost_usd` (Anthropic price table, wrong for a third party) make them a test-only shortcut, not the
production path.  OPTION 3 — HUMAN-AUTHORED. Curators write or correct meaning/examples/collocations/mnemonics in the workbench; stored through `store_content`
with model='human', prompt_version='manual-v1', origin='human', cost 0, ai_call_id NULL; validated by the same `validate_item` rules (CJK meaning, 3–4 examples
containing the headword or a known form). Realistic for corrections, featured words and the review queue; not for 9,162 words.  RECOMMENDED HYBRID: Option 1 for
the one-off fill and periodic prompt-version regenerations (known quality baseline), Option 2 as the on-server admin-only engine for newly approved contributed
words and report-driven regenerations so the public server does not depend on the co-admin's availability, Option 3 for corrections. Every content version
carries its origin and model, and the learner-facing card shows 「AI 生成 · <model>」 or 「人工编写」. If A3 cannot be satisfied, run Option 2 only (the design does not
change; only which runner is configured on which box).
## ARCHITECTURE
COMPONENTS. (1) Public server: `wd serve` (single process, kv.worker_lease) with WD_AI_POLICY=off (packs supply all content) or admin_only (domestic adapter on-
box), WD_AI_ENABLED=0 in the pure read-only case, WD_SVG_VIA_CLAUDE=0, ECDICT installed (deploy/fetch_ecdict.sh with a mirror URL), images IoWorker optional.
Holds the live library (words, word_forms, word_contents, word_images + DATA_DIR/images), the review queue (word_submissions), audit (library_audit), versions
(library_versions, kv library.revision), per-user data. (2) Staging generator: same code, WD_AI_POLICY=admin_only, WD_AI_ENABLED=1, co-admin's Console key,
claude -p --bare, claude-sonnet-5-5; its database = seed + dictionary-only packs from public; it runs prewarm/regenerate and exports content packs.
Alternatively/additionally the domestic adapter on the public server. (3) Curation workbench: the SPA's /admin gets a 词库 tab (list/search/filters/bulk actions),
/admin/library/:id (dictionary form, content versions with editor/activate/reject, image candidates, submissions, reports, audit trail, holders count),
/admin/review (queue with ECDICT probe, similar lemmas, approve/merge/reject, bulk approve), and a packs panel (inbox import, export since, versions); admins
and curator-granted users. (4) Content packs: tar.gz bundles in DATA_DIR/packs/{inbox,outbox}, moved by scp/rsync between staging and public, imported by `wd
library import` or the inbox API. (5) Seed round-trip: `wd library export --format seed` → scripts/pack_seed.sh → git commit → every deployment picks it up
through the existing kv.seed_version hash check (main.py:303-315). (6) Clients: unchanged read endpoints (GET /api/vocab, /api/words/{id}, /content, /image,
/today, /screen/next); no client cache (cache: no-store both sides), so every curation write is visible on the next request; `ServerFlags.ai_mode` drives which
affordances render.  DATA FLOW. Dictionary layer: seed file → import-seed (unchanged) → words/word_forms; curator PATCH → words (+curated_by/at, audit, revision
bump, card LRU invalidated via updated_at); approved submissions → words trust flags; seed re-import now skips rows with curated_at set (one WHERE clause in
seed.py:66-81) so curation is not silently reverted. Content layer: staging prewarm → word_contents on staging → `wd library export --scope contents,images
--since <rev>` → pack → public `wd library import` → new word_contents versions (origin 'import', pack_id, content_sha256),
words.active_content_id/content_state='ready'/difficulty filled exactly like store_content → clients read it on the next poll. Hand edits → PUT content → new
version origin 'human'. Image layer: staging/public fetch_image (IoWorker, no Claude) or pack files → DATA_DIR/images/<2hex>/<sha>.jpg|svg + word_images;
curator activate/reject; admin upload after migration 0011. Contribution loop: learner add/import → resolve exact→form→ECDICT→provisional (no lookup job under
policy) → word_submissions(pending) → curator decision → publish/merge/reject → (if admin AI allowed) content job, else the lemma is listed in the next
dictionary-only pack for staging → content pack back. Demand loop: 不熟悉 marks on content-less words and the 「想看例句」 action write content_wishes → the workbench
orders "missing content by demand" → prewarm-by-list on staging. Versioning: every curation write bumps kv library.revision; packs record base_revision;
library_versions rows mark seed imports, pack imports/exports and named snapshots; the admin overview shows revision, pending submissions, open reports,
coverage.
## POLICY SWITCH
CONFIG. New `WD_AI_POLICY` ∈ {live, admin_only, off}, parsed with config.py's `choice()` (like WD_REGISTRATION_MODE, config.py:321), default `live` (today's
behaviour), env-only and restart-requiring on purpose: a policy guarantee must not be re-opened by the admin 恢复 AI button, which writes kv.claude.enabled='1'
(routers/admin_ops.py:330). WD_AI_ENABLED and kv.claude.enabled / claude.paused_until keep their meaning as the worker kill switch and pause. Semantics: `live`
= every enqueue site active; `admin_only` = end-user sites closed, admin sites open, the worker runs them if WD_AI_ENABLED=1 and a provider is configured; `off`
= no AI from anyone: `budget.ai_enabled()` (ai/budget.py:114-119) and `bank.ai_enabled()` (services/bank.py:219-223) return False regardless of WD_AI_ENABLED,
so the ClaudeWorker gate idles (jobs/worker.py:249-258) and ServerFlags.ai_enabled is false. Helpers in new `backend/wd/ai/policy.py`: `user_ai_allowed(cfg)` =
policy == live; `admin_ai_allowed(conn, cfg)` = policy in (live, admin_only) and budget.ai_enabled and provider configured; `reconcile(conn, cfg, now)`.
Exposure: `Settings.ai_policy`, GET /api/admin/config, `wd check`, and `ServerFlags.ai_mode: 'live'|'admin_only'|'off'` added to schemas.py:140-147,
routers/auth.py:52-62, frontend/src/api/types.ts:29 and docs/API.md §9 in one contract commit (scripts/check_contract.py audits it).  GATED ENQUEUE SITES when
policy != live. (1) services/words.py `_create_provisional` (688-709), `_ensure_lookup` (711-721) and the [网络]-only branch of `_resolve_ecdict` (676): no
`enqueue_lookup`; instead `submissions.open(conn, word_id, user_id, source)` and the bank row is created as before. (2) services/bank.py
`enqueue_content_if_needed` (465-477): returns None without touching content_state; this covers bank._apply_unfamiliar (618), batches._enqueue_content_for
(341-352), scheduler.prefetch (289), suggestions accept (195) and lookup.py:487. (3) routers/words.py content_request (305-334): 503 ai_disabled before the
quota check. (4) routers/bank.py bank_consolidate (139-167): 503. (5) services/bank.py set_attention 'retry' (842-846): no lookup enqueue; it touches the
pending submission's updated_at instead (409 invalid_transition if none). (6) jobs/scheduler.py nightly_consolidation (194-226): returns 0; prefetch (243-290):
returns 0 (today it checks ai_enabled only); requeue_dead_once: skips content/lookup types. (7) images/handler.py `_svg_allowed` (101-102): fallback SVGs
(priority < 90, not `requested`) require policy == live; an explicit `svg:<id>:req` from admin refetch stays allowed when admin_ai_allowed. (8) routers/words.py
report target=image (270-282): auto-reject of the shared image only when policy == live; otherwise the report is filed for curators. Defence in depth in the
handlers: under admin_only, `content.select_jobs` finishes a generate_content job as `skipped: policy` unless its payload carries `plan_id`, `force` or
`trigger:'admin'`; `lookup.select_jobs` and the consolidate handler skip every job the same way (lookup_word is never enqueued under policy; the review queue is
human-decided).  ADMIN SITES. Prewarm (admin_ops.py:354-366) keeps its 503 on ai_enabled plus admin_ai_allowed; regenerate (376-395), report-resolve regenerate
(admin_reports.py:48-54) and the new workbench "generate" actions now check admin_ai_allowed and answer 503 ai_disabled instead of enqueueing a job that idles
forever; refetch-image with provider=claude_svg likewise. Everything non-AI in the workbench (publish/unpublish/invalidate/merge/rename/edit dictionary/PUT
content/activate or reject versions/reject images/decide submissions/import packs) is always available.  STARTUP RECONCILE (main.startup after seed_check,
main.py:473-490, and `wd library reconcile`): when policy != live, cancel queued lookup_word, consolidate_bank, non-requested generate_svg and generate_content
jobs without plan_id/force; reset words.content_state 'queued' → 'none' for words whose live content job was cancelled (removes the misleading 「今日 AI
额度已用完，例句将在明天补齐」 state, frontend reads queued+eta null as deferred); open a word_submissions row for every `is_valid_english IS NULL` word that has holders
(legacy provisional words enter the queue); write system_events('ai_policy', {policy, cancelled, submissions_opened}). Idempotent; it never claims jobs (it
cancels them in short transactions, the same pattern as prewarm.cancel_leftovers).

## CONTENT PACK
FORMAT (wdpack v1, a tar.gz or directory): manifest.json {format:'wdpack', format_version:1, created_at, created_by (username), source_instance (kv
public_url_guess or a configured name), base_revision (kv library.revision at export), seed_version (kv), prompt_versions:[…], scopes:[words,contents,images],
counts:{words,contents,images,files,bytes}, files:{path:sha256}, manifest_sha256}; words.jsonl (one record per lemma: lemma, display, kind, phonetic,
translation[], definition[], pos, collins, oxford, exam_tags[], bnc, frq, exchange{}, stages[], cet6_star, sources, ecdict_id, is_public, is_valid_english,
safe_for_sharing, difficulty, validated_by, curation_note, updated_at — the seed record shape plus the trust/curation columns, so `--format seed` is the same
writer with the extra keys dropped); contents.jsonl (lemma, content (the Content object without version/created_at), prompt_version, model, origin
ai|human|import, status active|superseded|rejected, cost_usd, author (username or null), created_at, content_sha256 = sha256 of canonical JSON of {content,
prompt_version, model}); images.jsonl (lemma, provider, provider_ref, query, source_url, landing_url, title, creator, creator_url, license, license_url,
attribution_text, alt_zh, width, height, mime, file_bytes, sha256, file 'files/<2hex>/<sha>.jpg|svg', status, created_at); files/<2hex>/<sha256>.jpg|svg
(identical layout to DATA_DIR/images so store.write_bytes dedupes by hash). Everything is keyed by lemma because ids differ between instances; per-user data is
never in a pack; packs never carry jobs or ai_calls (the ledger stays on the instance that paid).  IDEMPOTENCY AND MERGE RULES. Pack level:
library_versions.sha256 UNIQUE on the manifest hash → importing the same pack twice is a no-op (exit 0, 'already imported'). words: upsert by lemma, only the
keys present in the record, `updated_at` last-writer-wins (a local row newer than the record is left alone unless --prefer-pack); trust flags are never
downgraded by a pack (is_public/is_valid_english only move up, takedowns are explicit curator actions or the seed retired list); created_by_user_id is never
touched; word_forms rebuilt from exchange like seed.py for records that carry exchange. contents: if a local row with the same (word, content_sha256) exists →
skip; else insert as version MAX+1 with the pack's prompt_version/model/created_at, origin 'import', pack_id; an 'active' record becomes active locally
(previous active → superseded, words.active_content_id/content_state='ready', difficulty filled when NULL — the same statements as store_content) unless the
local active version is origin 'human' (curator edits win by default; --prefer-pack overrides); 'superseded'/'rejected' records are inserted as history only.
images: if a word_images row with the same (word, sha256) exists → skip; else write_bytes (idempotent by hash), insert the row; activate when the record is
active and the word has no active photo, or --replace-images. Partial failure: each chunk of 200 lemmas is one BEGIN IMMEDIATE (busy_timeout 5 s covers
concurrent learner writes); a failed chunk aborts the run, leaving earlier chunks committed; re-running resumes idempotently. verify: recomputes file hashes and
the manifest hash, checks format_version ≤ supported, warns when prompt_versions differ from the server's PROMPT_VERSION.  VERSIONING. format_version (importer
refuses a newer major), base_revision (export) and library_versions rows (kind pack_export on the source, pack_import on the target, with counts and the actor),
kv library.revision incremented once per import. Incremental exports use `--since <iso>` (updated_at / created_at) or `--since-revision` (via the audit table).
`--only-active` for lean content packs; `--with-images` for image packs (≈ 60 KB per photo, so a full image pack is hundreds of MB and travels by rsync).  HOW
IT MOVES. Staging → public: `wd library export … --out outbox/contents-<rev>.wdpack.tar.gz` on staging, `rsync` over SSH (both boxes are admin-operated) into
DATA_DIR/packs/inbox on the public server, then `wd library import inbox/<file>` (CLI) or POST /api/admin/library/packs/import {file} from the packs panel (the
API only imports files already in the inbox, avoiding multipart/body-limit work). Public → staging: `wd library export --scope words --filter validated_by=admin
--since <last>` (dictionary-only, kilobytes) the same way; the panel's 导出待生成词表 button produces it. Git: `--format seed` output goes through scripts/pack_seed.sh
into data/seed. Small content-only packs can also be downloaded from GET /api/admin/library/packs/export?since=.

## RISKS
- Anthropic policy inference: pre-generating in a supported region on admin triggers and serving the cached outputs to mainland readers is the defensible reading of the commercial terms but not a written safe harbour (docs/PUBLIC_LAUNCH_AND_IOS.md §2.3); if Anthropic answers no, the staging generator must stop and the domestic adapter becomes the only engine — the dispatcher design keeps that swap configuration-level, but the content already served would need a decision.
- Operator discipline: the owner must never hold or use Claude credentials for this product (location + Enterprise seat); staging credentials live only on the co-admin's box; the public server's empty ai_calls table is the audit proof. A single 'quick prewarm from the Mac' breaks the chain.
- Dependence on one co-admin for all Claude generation (availability, their Console billing, their own location changing); mitigated by the on-server domestic adapter and by packs being durable artefacts.
- Provenance of the Mac's existing 48 contents / 30 SVGs (Enterprise seat): importing them into the public library would taint an otherwise clean chain; regenerate instead.
- Domestic model quality is unmeasured for this prompt (no eval set in the repo); json_object mode does not guarantee the schema, so everything rests on the existing post-validation; mitigated by the 50-word human-rated eval and 'superseded-only' writes until it passes.
- Review queue staffing: unknown strings now wait for a human instead of 20 s; without curators the queue ages and learners churn; mitigated by ECDICT-first (most real words never queue), bulk approve, per-user open-submission cap, SLA tile and the curator grant.
- Seed re-import revert trap: without the curated_at guard any seed import (startup hash check, install.sh) reverts curator edits to seed lemmas; with the guard, the reverse risk is seed corrections not reaching curated rows unless the curator clears curation or uses --force; documented in the workbench.
- Single-process SQLite: a pack import of ~9k contents is tens of MB and thousands of writes; chunked 200-row transactions keep writers under busy_timeout, but image packs of hundreds of MB must be rsynced, and `wd backup --with-images` becomes mandatory because images are part of the curated artefact.
- Schema evolution: 0010 is additive, but 0011 rebuilds words and word_images (CHECK lists) under the FK-off recipe; it is a stop-the-world release with a pre-migrate snapshot; test_db pins the recipe, test_registry_complete reads 0001's jobs CHECK list (untouched: no new job types are introduced, curation runs synchronously/CLI and never claims jobs).
- Frozen contract churn: ServerFlags.ai_mode, AddResult.status pending_review, User.grants, new DTOs — each needs API.md + schemas.py + types.ts in one commit and passes scripts/check_contract.py.
- Card staleness: dictionary PATCH invalidates the server LRU (key includes updated_at) but the browser keeps /media/card/{id}.svg for 24 h; content-addressed photos are immutable by design.
- Curator visibility widening (visible_word_sql → 1=1 for curators) exposes other users' private provisional words to curators by design; submissions deliberately exclude per-user notes; a careless new read path could still leak — keep the predicate helper in every word-reading query.
- Image providers from the public host: Singapore/Tokyo fine, mainland VPS blocked (Wikimedia) → pack-only images and 换一张 disabled; Openverse quotas (15/min, 160/day) bound the staging image pass to days.
- GFW/latency and the two-instance topology add operational complexity (two .env profiles, sync discipline, pack ordering); mitigated by idempotent packs and the later sync timer.
- Legal/attribution: contributed-word licence and CN AI-content labelling (per-card 「AI 生成 · model」 label) must be in place before public users; ECDICT MIT notice stays.
- Effort: ≈ 28.5 dev-days before the first public user is 6+ full-time weeks for one developer; the policy switch + frontend gating (5 days) alone makes a read-only launch safe if the rest slips, at the cost of a dead-end add path until the queue ships.
