# DESIGN D3-model-and-compliance — Model and compliance first: make the AI layer provider-agnostic behind the existing ClaudeResult seam, then choose where generation runs (domestic model on the public server vs Claude off-shore via a co-admin) so that no mainland end user ever triggers a model call, the owner never personally calls Claude, and the same code can later re-enable live AI lawfully under a 备案'd domestic model. Optimise for policy robustness and optionality; keep schema changes additive and keep every curation writer out of the job queue.
## SUMMARY
The codebase already separates the four GLOBAL library tables from everything per-user, every reader goes through words.active_content / images.image_meta, and
all four handlers see only ClaudeResult (interfaces.py:83-109), so "admin curates, clients read" is structurally cheap; what is missing is (1) a policy that
stops end-user actions from enqueueing model jobs (today WD_AI_ENABLED=0 only idles the worker, worker.py:249-261, while bank.py:465-477, words.py:690-721,
scheduler.py:194-300 keep enqueueing), (2) a runner that is not the owner's claude CLI login, (3) a way to move content and images between machines, and (4) a
minimal takedown/review surface. Generation must not use the current login: the owner is physically in mainland China (403 from api.anthropic.com) and the seat
is an employer Enterprise seat, so under Anthropic's supported-regions and OAuth rules the owner can neither be the Customer nor the caller. I therefore
recommend a two-adapter runner: keep claude_cli (runner.py:124-149, 229-285) for tests and for an optional off-shore staging box operated by a co-admin in a
supported region with their own personal Console API key, and add openai_http, an httpx adapter for an OpenAI-compatible domestic model
(DeepSeek/Qwen/GLM/Doubao) that runs on the public server itself and is reachable from Singapore/Tokyo and from the mainland. The default production shape is
curated policy + openai_http on the server: the admin fills the 9,162-word seed through the existing prewarm plan (prewarm.py:84-170, priority 90, caps raised
once), regenerates on reports, and no Anthropic credential ever exists on the public box, which removes the Anthropic end-user-region question entirely and
leaves only mainland-side duties (PIPL notice/consent/age, per-block AI labels, human review of contributions, ICP only if hosted onshore). Claude stays
available as a quality top-up delivered as content packs exported from the staging box, under the explicit caveat that serving Claude outputs to mainland
readers is an inference, not a written safe harbour, carried by the co-admin as Anthropic's Customer. The policy switch is WD_AI_POLICY=curated plus
WD_AI_PROVIDER and WD_CUSTOM_WORDS: every user enqueue site becomes a no-op that leaves content_state at none (never queued), lookup/consolidate are never
enqueued or claimed, the worker additionally refuses content jobs that lack plan_id/force and SVG jobs that lack requested, and a wd policy reconcile command
cancels leftovers; admin levers (prewarm, regenerate, report-resolve, refetch) keep working through the unchanged budget/ledger chain. User-added words still
grow the library without AI: install ECDICT on the server so most real words become public validated rows via words._resolve_ecdict (words.py:652-687), and
unknown strings become private provisional rows WITHOUT a lookup job that an admin approves, rejects, merges (reusing lookup.merge_into) or validates with an
admin-triggered lookup; publication is always an explicit admin act. Content packs are a tar of manifest.json + contents.jsonl + images.jsonl +
files/<2hex>/<sha>.{jpg,svg} (+ optional seed-format words.jsonl), idempotent by (lemma, item sha256) and image sha256, imported by a CLI that writes
words/word_contents/word_images in short transactions next to the live service and never touches jobs (the fetch-image/images-prune precedent). Schema changes
are additive only (migration 0010: word_contents.source/source_ref, word_images.source_ref, words.hidden_at/curated_by_user_id, ai_calls.provider,
users.terms_*), the model NOT NULL column simply records 'deepseek-chat' or 'human', and the CHECK lists for words.source, word_images.provider and jobs.type
are not touched before "later". Migration from the Mac is a fresh public database: same seed file, no carry-over of the 48 contents/31 SVGs generated under the
Enterprise seat (regenerating them costs cents), the owner's own bank moved with the existing per-user export/import. Before the first public user: policy
switch, frontend hiding/re-copy, the HTTP adapter plus a 50-word quality eval to pick the model, pack tooling, hide/unhide, the seed fill and an image backfill;
first month: review queue, hand-written content, admin 词库 tab, per-block AI labels, contribution export back to the seed; later: a Messages/Batch adapter for
the off-shore box, image uploads, a curator role, and the live-mode-for-mainland path that needs an entity and 登记. Total ≈ 39 dev-days (20 before launch, 8.5
first month, 10.5 later).

## ARCHITECTURE
Components and data flow, curation to client.  1) Public server (SG/Tokyo VPS; one wd serve process; SQLite WAL; data dir with images/). Config:
WD_AI_POLICY=curated, WD_AI_PROVIDER=openai_http (or none), WD_CUSTOM_WORDS=ecdict_review, WD_SVG_VIA_CLAUDE=0, WD_ECDICT_DB_PATH set,
WD_REGISTRATION_MODE=invite at first. Global library = words/word_forms (seed importer, seed.py:70-81, 247-300, unchanged), word_contents (writers: the
generate_content handler via the provider-agnostic runner, the pack importer, the admin content endpoint — all through one store_content), word_images (writers:
fetch_image/generate_svg handlers via images.store.activate, store.py:95-123, and the pack importer through the same function). Readers unchanged:
words.active_content (words.py:428-440), images.image_meta, card renderer; clients have no cache (frontend-consumption digest), so an import is visible on the
next request; only /media/card/{id}.svg may lag 24 h for dictionary-field edits.  2) Provider-agnostic AI runner on the server:
backend/wd/ai/providers/{claude_cli,openai_http}.py selected by cfg.ai_provider; runner.run_claude/Runner remain the façade so content.py:401-411,
lookup.py:534-545, consolidate.py:505-515, svg.py:111-121 and probe.py:73-88 are untouched. Shared pieces stay: budget.reserve/can_spend (budget.py:187-285) for
caps and the running reservation, ledger.insert_call/finish_call (ledger.py:26-102) for the ai_calls row inserted before the request, common.handle_failure for
outcomes, claude-logs/ for raw responses (pruned by WD_AI_LOG_KEEP_DAYS). New ai/pricing.py (usage → USD), ai/schema_transform.py (strict variant of the five
schemas), ai/policy.py (the gate helpers). Under curated policy only admin-originated jobs exist (prewarm plan_id, force regenerate, requested SVG, admin
lookup) and the ClaudeWorker's type list shrinks to generate_content/generate_svg/prewarm_plan (+ lookup_word only for payload actor='admin'); the IoWorker
keeps fetching photos (fetch_image is not an AI call) from Wikimedia/Openverse/keyed providers, including an admin image-backfill plan at priority 90.  3)
Optional off-shore staging box (co-admin): a second full instance with its own data dir and lease, WD_AI_PROVIDER=claude_cli + WD_ANTHROPIC_API_KEY (+ --bare),
same seed, same admin prewarm; produces packs with `wd pack export`. It never shares the public database or job queue, so the single-process/kv.worker_lease
invariant is untouched.  4) Content pack channel: `wd pack export` (any instance) → tar.gz → rsync/scp/object storage → `wd pack import` on the public server.
The importer is a plain SQLite client in short BEGIN IMMEDIATE transactions (≤ 200 rows each, the fetch-image/images-prune precedent; ops digest finding 17-18),
never claims or enqueues jobs, writes system_events('pack_imported') and kv.pack.last, and exposes the library version (seed sha256 + last pack id) in GET
/api/admin/health next to kv.seed_version.  5) Admin curation surface (require_admin, deps.py:190-193): existing prewarm/regenerate/refetch/report tabs plus a
new 词库 tab backed by routers/admin_words.py: list/search, hide/unhide (takedown), review queue of provisional words (is_valid_english IS NULL),
approve/reject/merge/admin-lookup, hand-written content editor, image backfill plan, library version. Contributions flow: learner add → ECDICT hit publishes (no
AI) or provisional private row without a lookup job → admin decision → optional admin AI generation → visible to all.  6) Clients (web now, PWA/iOS later) read
ServerFlags.ai_policy / custom_words (routers/auth.py:52-63, schemas.py:140-147, types.ts:29) and hide every AI affordance; all per-user features (筛词, 不熟悉, SRS,
batches, export/import) keep working without any model call. Compliance artefacts produced by the architecture: ai_calls on the public server lists provider and
model for every call (none for Anthropic), word_contents.source/model tells per item whether a human or which model wrote it (feeds the per-block AI label), and
the review queue gives human pre-publication control over user-contributed headwords.
## POLICY SWITCH
CONFIG (frozen at startup like every WD_* value, reported by GET /api/admin/config and ServerFlags): - WD_AI_POLICY ∈ {live, curated}; default live (today's
behaviour, so dev/tests are unchanged); the public server sets curated. - WD_AI_PROVIDER ∈ {claude_cli, openai_http, none}; default claude_cli. none = no
adapter: ClaudeWorker idles exactly like the kill switch and prewarm/regenerate/probe answer 503 ai_disabled; use it when all generation happens on the staging
box via packs. - WD_CUSTOM_WORDS ∈ {live, ecdict_review, ecdict_only}; default live. Under curated, live is a ConfigError (an explicit choice is forced).
ecdict_review: ECDICT hits publish as today (words.py:669-676), unknown strings create the private provisional row (is_public=0, is_valid_english NULL,
created_by_user_id) but NO lookup_word job, and the bank row shows 待审核 instead of 待校验; ecdict_only: unknown strings are refused with a new 422 word_unknown
before any insert. - Provider settings: WD_AI_BASE_URL, WD_AI_API_KEY (SECRET), WD_AI_JSON_MODE ∈ {schema, object}, WD_AI_HTTP_TIMEOUT_SEC,
WD_AI_MAX_OUTPUT_TOKENS, WD_AI_PRICE_TABLE_JSON, WD_AI_USD_PER_CNY, WD_AI_COST_SCALE (scales budget.ESTIMATES for cheap providers), WD_ANTHROPIC_API_KEY
(SECRET, claude_cli only, implies --bare). - kv: claude.enabled / claude.paused_until / claude.available keep their semantics as the runtime kill switch, pause
and availability for whatever provider is configured (key names renamed only in a later cleanup); new kv policy.reconciled_at. - ServerFlags gains ai_policy,
custom_words, ai_provider_kind ('none'|'model'); ai_enabled keeps meaning "a provider is configured and not killed" so admins see it.  GATED ENQUEUE SITES under

## CONTENT PACK
FORMAT: a tar.gz (or directory) named <pack_id>.tgz containing - manifest.json: {format: 'wd-pack/1', pack_id (uuid), created_at, created_by (instance id +
admin username), generator: {provider, model, prompt_version, system_prompt_sha256, schema_sha256}, seed_sha256 the words were taken from, counts {contents,
images, words}, licence note, min_schema_version (migration number required), sha256 of each member file}. - contents.jsonl: one line per content item: {lemma,
display, item_sha256, content: {word, valid, meaning_zh, meaning_en, examples[{en,zh}], collocations, mnemonic_zh, image_keywords, image_alt_zh, difficulty},
model, prompt_version, source ('claude_cli'|'anthropic_http'|'openai_http'|'human'), generated_at, cost_usd, reviewed_by?}. item_sha256 = sha256 of the
canonical JSON of content + model + prompt_version. - images.jsonl: {lemma, provider (existing CHECK values only until 'upload' lands), provider_ref, query,
source_url, landing_url, title, creator, creator_url, license, license_url, attribution_text, alt_zh, width, height, mime, sha256, file:
'files/<2hex>/<sha256>.<jpg|svg>'} — the same columns as word_images (0001_init.sql:245-276) so store.activate can be called verbatim. -
files/<2hex>/<sha256>.{jpg,svg}: the content-addressed binaries exactly as DATA_DIR/images stores them (store.rel_path), so a pack is also a partial images/
tree. - words.jsonl (optional): seed-format records (15 fields, seed_row, seed.py:170-215) for dictionary additions/corrections; imported ONLY through seed
semantics into a curated seed file, never silently upserted (see the kv.seed_version path trap, seed-pipeline finding 17): the importer writes them to
<data>/seed-contrib.jsonl for the operator to merge into WD_SEED_PATH, or applies them directly when --apply-words is given and WD_SEED_PATH already points at
the curated file. - curation.jsonl (optional): {lemma, action: hide|unhide|merge_into, target?, note} applied through the same service functions as the admin
API.  IDEMPOTENCY: contents are keyed by (lemma, item_sha256): if the word's active content already carries that source_ref the item is skipped; otherwise a new
version is inserted through content.store_content (MAX(version)+1, previous active → superseded, words.active_content_id/content_state='ready', difficulty
filled when NULL; content.py:198-228) with model/prompt_version/source/source_ref from the item; --keep-newer skips words whose active content is newer than the
item; items whose lemma is unknown are reported and skipped (never create words rows from a content pack). Images are keyed by sha256: the file is written with
store.write_bytes (dedupe by hash, 0600, atomic) after verifying sha256(file bytes) == row.sha256 and the path shape (FILE_RE), SVGs are re-run through
sanitize_svg.clean, and store.activate is called only when the word's active image has a different sha (previous → superseded, image_state 'ready'). Every
import writes kv.pack.last, kv.pack.<id>.imported_at and system_events('pack_imported', {pack_id, counts, skipped}); re-importing the same pack is a no-op.
Validation on import: every content item passes content.validate_item(last_attempt=True) against the current word row (headword presence, CJK, lengths,
blocklist) — the same gate as model output — and the manifest hashes must match.  VERSIONING: pack_id + created_at + generator block; the library version shown
to admins = sha256(seed_version || sorted imported pack ids) in /api/admin/health; prompt_version inside items lets select_jobs's 'already_ready under current
PROMPT_VERSION' rule (content.py:364) keep working, and a future prompt bump is a new pack, not a code release.  MOVEMENT: produced by `wd pack export` on the
generating instance (staging box with Claude, or the public server itself for backups/seeding a second instance), transferred by scp/rsync/object storage,
applied by `wd pack import` on the public server next to the live service (short transactions; the importer never claims jobs, so the kv.worker_lease rule is
respected); visible to all clients immediately because nothing is cached client-side; the 24-h private cache of /media/card/{id}.svg affects only dictionary
edits. Sizes: 9,162 contents ≈ 15 MB of JSONL; images ≈ 40-80 KB each (≤800 px JPEG) → ~0.5 GB for a full photo set, hence --since/--stage slicing. Export also
serves as the off-box backup of curated content that `wd backup` only covers inside the whole-DB snapshot.

## RISKS
- Domestic-model quality on idiomatic English examples is unverified for this prompt: validate_item enforces headword/CJK/length floors but not naturalness; mitigate with the 50-word eval before the seed fill, human spot checks per stage, and the Claude pack path for weak stages.
- Structured-output support differs per vendor (json_schema strict vs json_object; DeepSeek requires the word 'json' in the prompt; some models ignore enum/minItems): the transform + json_object fallback + pydantic/validate_item gate handle it, but invalid_output rates may be higher and the bisection/backoff path will cost extra calls; measure in the eval.
- Vendor content filters can reject prompts containing certain words (e.g. data_inspection_failed): mapped to per-call error so bisection isolates the word, but those words end at content_state='failed' and need hand-written content or the Claude pack.
- Ledger cost accuracy depends on a maintained price table and a CNY→USD rate; the daily/monthly caps still protect spend because reservations are conservative, but admin cost views may drift; keep the table in config with a dated source comment.
- The Claude pack path rests on the cached-output reading of Anthropic's supported-regions policy (an inference, PUBLIC_LAUNCH §2.3) and on a co-admin who becomes the Customer; if Anthropic answers no, drop the path (the domestic path is unaffected) and never run prewarm from any machine the owner operates.
- Curated mode does not remove mainland obligations: PIPL notice/consent/age, 标识办法 per-block labels and agreement clause, potential 生成式AI 暂行办法 applicability to publishing generated text, and ICP if hosted onshore; offshore + individual leaves only blocking as the regulator's remedy, which is an availability risk (GFW) as much as a legal one.
- Leftover queued jobs and 'queued' content_state from the live era would show misleading copy and could run if someone flips WD_AI_ENABLED; mitigated by `wd policy reconcile` at startup and the worker's payload guard, but both must be tested against a DB that already holds such rows.
- Pack import next to the live service holds BEGIN IMMEDIATE write locks; keep batches ≤ 200 rows and short transactions, or writers hit busy_timeout (5 s + retries) — measure on a production-sized copy; a full 9,162-item pack plus images should be imported during a quiet window.
- ECDICT-hit words become public without review (dictionary data, but it includes the [网络]-only and misspelt entries noted in the seed digest); if the owner wants every contribution reviewed, the ECDICT branch must also insert as pending, which lengthens the admin's queue.
- Image governance: any single learner's 换一张/report still replaces the shared photo (threshold 1), and Wikimedia is unreachable from a mainland host; raise the threshold and keep images flowing via packs if hosting moves onshore.
- Operational coupling to kv.worker_lease: the staging box must never share the public DB, and no curation tool may claim jobs; the pack importer and reconcile are written as plain SQLite clients, and `wd worker-once`/`tick` remain refused while the service runs.
- Seed path trap: dictionary edits made outside the seed file are reverted by the next seed re-import (kv stores only the hash); route dictionary corrections through the curated seed file (WD_SEED_PATH) and keep words.jsonl in packs advisory.
- Single developer time: ~20 dev-days before launch; the runner split touches the most-tested module (test_runner.py, fake_claude, smoke) and must keep the claude_cli path byte-identical to avoid regressions.
