# SLICE content-media  (37 findings)
## SUMMARY
The shared "content" layer is two GLOBAL, versioned tables keyed by word: `word_contents` (one `active` row per word holding a validated JSON object with
meaning_zh, meaning_en, 3-4 bilingual examples, collocations, mnemonic_zh, image_keywords, image_alt_zh, difficulty, plus
version/prompt_version/model/created_at) and `word_images` (one `active` photo or Claude SVG per word with provider, licence, attribution and a content-
addressed file under WD_DATA_DIR/images). Nothing in this layer is per user: the prompt is built from dictionary columns only,
`words.active_content_id`/`active_image_id` point at the shared rows, and every reader (word detail, study item, screen card, template card) calls the same
`words.active_content` lookup. Content is produced exclusively by the `generate_content` job handler, which runs on the server's ClaudeWorker and spawns the
local `claude` CLI (OAuth-authenticated as the service user) in batches of up to 10 words; the only INSERT into `word_contents` in the codebase is that handler,
and the only INSERT into `word_images` is `images.store.activate` fed by the `fetch_image`/`generate_svg` handlers. Jobs are enqueued by nine sites: marking a
validated word unfamiliar (priority 10/20), batch build and study_today (20), the 03:30 prefetch (30, ≤50/user, skipped at ≥50% daily spend), `POST
/api/words/{id}/content/request` (10, 60/day/user), `lookup_word` validating a custom word (10), consolidation/suggestion merges (20), admin regenerate and
report-resolve (10, `force`), and the admin-only `prewarm_plan` (90); bulk import and browsing never enqueue. All of them funnel through one dedupe key
`content:<word_id>` and the global guards in `budget.can_spend` (kill switch WD_AI_ENABLED + kv.claude.enabled, pause, 60 calls/hour, $3/day, $40/month, prewarm
sub-cap $1/day plus "spent_today < 50% of daily", SVG sub-cap $0.50/day); refusals defer jobs rather than failing them. Prewarm covers public, valid, unmerged
words of a stage (or every word with a stage for `all`, which is the whole 9,162-word seed) that still have `content_state IN ('none','failed')`, fans out
5×batch (50) words every 2 minutes, is capped at 2,000 words per plan and 503s when AI is off; at default budgets it yields roughly 250 words/day (≈37 days for
the seed), and with caps raised the 60-calls/hour cap bounds it to ~600 words/hour (~15 h of calls). When content is missing the API returns `{state, content:
null, eta_s, deferred_until}` and the UI falls back to the ECDICT translation with a 「生成例句」 button or the 「明天补齐」 copy; study never waits for content and
`finalize_building` flips batches to ready immediately when AI is off, and the image is never null because the deterministic template card is rendered from DB
data. Images come from Wikimedia then Openverse (keyed Pixabay/Pexels appended), are SSRF-checked, re-encoded to ≤800px JPEG, stored as
`images/<2hex>/<sha256>.jpg|svg` with licence/attribution columns, and served only at cookie-gated `/media/...` URLs; a Claude SVG is drawn only when no photo
exists, the word is actually studied, priority < 90, `WD_SVG_VIA_CLAUDE=1` and the SVG budget allows. Users can report content/image/dictionary problems
(20/day), which snapshot the active content/image ids; the admin can only resolve a report by re-running AI (`regenerate` → forced content job, `refetch_image`
→ reject the shared image and re-fetch) or dismiss it. What is ABSENT for server-side curation: there is no PUT/PATCH/POST endpoint that writes content text, no
CLI or seed path that imports/exports `word_contents` or `word_images`, no admin word browser (regenerate/refetch exist only as API calls and are reachable in
the UI only from the reports tab), no reviewed/approved state (word_contents' `rejected` status is never written), and bumping `PROMPT_VERSION` re-enqueues
nothing because every enqueue site requires `content_state IN ('none','failed')`. The data model itself is curation-friendly (global rows, logical pointers,
template card and all readers driven by `active_content_id`), so an operator could in principle insert rows and flip pointers by hand or with a new importer,
but today that path exists only as raw SQLite.
