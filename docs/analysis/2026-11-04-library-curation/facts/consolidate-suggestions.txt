# SLICE consolidate-suggestions  (35 findings)
## SUMMARY
DESIGN §5.4 names 整合与更新 as two Claude jobs: `lookup_word` (per added word, minutes after an add; another slice) and `consolidate_bank`, the nightly per-user
bank sweep that is this slice. The scheduler tick enqueues `consolidate_bank {user_id, trigger:'nightly'}` once per local day at 02:30 for every active,
onboarded user whose bank rows (user_words in new/learning) changed since the last run or whose words still have `is_valid_english IS NULL` / `difficulty IS
NULL`; a user can also press 立即整理 (POST /api/bank/consolidate, 60-min cooldown, 503 when AI is off/paused) and an operator can run `wd consolidate <username>`;
there is no admin HTTP endpoint. The handler builds one prompt per user: up to 2,000 bank headwords plus up to 80 items, each carrying the user_words id, the
normalised typed text (≤48 chars), the stored headword, whether dictionary data exists, the difficulty, and the first 120 sanitised characters of the learner's
private 备注 — the only prompt in the system that ever sees the note. Claude returns one verdict per item (ok / lemmatize / merge_duplicate / fix_spelling /
invalid_word / split_phrase / fill_data) plus confusable_groups and difficulty_tags. Some effects are auto-applied to GLOBAL `words` rows: fill_data writes
phonetic/pos/translation/definition/difficulty onto non-seed words (and flips source user→claude), difficulty_tags set `words.difficulty` on any word including
seed rows, and invalid_word sets is_valid_english=0/is_public=0 on provisional words; a validated `target` that does not yet exist is created as a private
provisional `words` row with its own `lookup_word` AI job, so consolidation can add (private, unvalidated) words to the global table. Everything else lands in
the PER-USER `bank_suggestions` table: auto lemmatize repoints (7-day undo), open fix_spelling/merge/split/invalid suggestions (30-day expiry), and accepted
confusable_group rows that feed the 易混 chips. Accepting a suggestion only rewrites the user's own user_words/push_items/review_logs (repoint, merge with the
losing row set to removed, or remove) and never writes `words`/`word_contents`, though it may enqueue a `generate_content` AI job for the target and an undo can
revert the auto-filled `words` columns or un-tombstone a merged word. Gating is only the shared AI chain — kill switch WD_AI_ENABLED / kv.claude.enabled, pause,
hourly/daily/monthly caps, a $0.05 reservation, $0.40 per-call cap, 240 s timeout; there is no opt-in setting, no minimum bank size, no per-user switch and no
consolidate-specific switch. With AI disabled the Claude worker idles, queued consolidate jobs are left untouched (and accumulate one per user per day because
the scheduler never checks the kill switch), no consolidation_runs rows are written, and the UI still shows the button but receives 503 「AI 功能当前不可用」. Nothing in
the push/SRS pipeline depends on consolidation: batches, grading and the scheduler run independently, difficulty NULL falls back to the stage index, confusables
fall back to [], and the inbox stays empty (lookup_word still writes fix_spelling rows while it runs). Privacy-wise the prompt contains the user's whole bank
word list, user_words ids and note excerpts, and the full argv (prompt included) is persisted under claude-logs for 14 days; usernames and e-mails are never
sent. For a mainland launch this feature is a live Claude call driven by end-user input and a nice-to-have that can be dropped by leaving AI off, at the cost of
bank-hygiene suggestions, auto-filled data for user-added words, difficulty tags and 易混 chips.
