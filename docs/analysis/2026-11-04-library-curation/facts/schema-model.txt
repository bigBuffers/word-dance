# SLICE schema-model  (34 findings)
## SUMMARY
The library lives in one SQLite file whose complete baseline schema is backend/wd/migrations/0001_init.sql (byte-identical to docs/SCHEMA.sql, enforced by a
unit test); only two later files exist, 0008 (additive indexes) and 0009 (a data-only repair of words.phonetic), with numbers 0002-0007 deliberately skipped.
The global, shared library is exactly four tables: words (one row per normalised lemma, UNIQUE), word_forms (inflection to lemma), word_contents (versioned AI
example content, one row per (word_id, version), at most one status='active' per word via a partial unique index) and word_images (one active image per word,
binaries on disk under DATA_DIR/images). Every learner-specific thing is per-user: user_words (bank state, needs_attention, attention_msg, suggested_word_id,
SRS fields), review_logs, daily_stats, push_batches/push_items, consolidation_runs, bank_suggestions, user_settings; jobs, ai_calls, kv, system_events,
provider_* and content_reports are global bookkeeping. A words row carries provenance in source (CHECK 'seed'|'ecdict'|'claude'|'user'), sources, ecdict_id and
created_by_user_id, trust in is_public/is_valid_english/safe_for_sharing, lifecycle in
content_state/image_state/active_content_id/active_image_id/merged_into_word_id, and level data in stage_zk/gk/cet4/cet6, stage_min, cet6_star, difficulty, frq,
bnc, collins, oxford; there is no soft-delete, hidden or archived column and no triggers, so updated_at is set only by application UPDATEs. Visibility is not
enforced by the schema: is_public plus created_by_user_id plus the holder's own user_words row form a documented predicate that deps.visible_word_sql() emits
and every reading route is supposed to include; a user-created provisional word (source='user', is_public=0) is therefore visible to its creator and to any
other user who adds the same string (they share the single lemma row) but not to third parties, and admins see everything. Words become public only through the
seed upsert, an ECDICT hit, or a Claude lookup/merge verdict; Claude paths are the only ones that set is_public back to 0. word_contents rows are inserted in
exactly one place (ai/content.py store_content) and word_images in one place (images/store.py); there is no admin, import or hand-edit write path to either, no
'admin'/'upload' provenance value in any CHECK list, and no table or column for approval, curation, publication or content packs (grep-proven). Deleting a words
row cascades to word_forms, word_contents, word_images, user_words, push_items and content_reports, sets NULL on
merged_into_word_id/suggested_word_id/target_word_id, and leaves review_logs.word_id, jobs payloads and the logical pointers (active_content_id,
active_image_id, ai_call_id, content_reports.image_id/content_id) dangling; the only DELETE FROM words in the codebase is the orphaned-private-word cleanup
during account deletion. Migrations are applied by db.run_migrations from four entry points (wd migrate, wd serve startup, wd worker-once, wd claude-check),
each pending file inside one BEGIN IMMEDIATE with FK enforcement off and a foreign_key_check before the runner's own bookkeeping insert; a pre-migrate snapshot
backups/pre-migrate-<from>-to-<to>.db.gz is written first except on a fresh database, its failure aborts the migration, and such snapshots are never pruned. The
seed import (ON CONFLICT(lemma) DO UPDATE of dictionary columns, forcing source='seed', is_public=1, trust flags 1 and merged_into_word_id=NULL, never touching
content pointers or per-user rows, auto-run at startup when kv.seed_version differs from the file's sha256) is the one existing admin-side channel that updates
shared dictionary data for all clients without any end-user AI call; AI gating in this slice is config WD_AI_ENABLED combined with the runtime kv keys
claude.enabled, claude.paused_until and claude.available documented in the kv header.
