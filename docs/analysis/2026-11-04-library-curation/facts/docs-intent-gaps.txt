# SLICE docs-intent-gaps  (33 findings)
## SUMMARY
The design documents define the shared library as an operator-seeded canon (9,162 ECDICT/syllabus words imported with source='seed', is_public=1,
is_valid_english=1, safe_for_sharing=1, "seed words are trusted") living in the GLOBAL tables words/word_forms/word_contents/word_images ("Content is never per
user"), while user_words, review_logs, daily_stats, push_batches/push_items, bank_suggestions, consolidation_runs and user_settings are PER-USER. User-typed
words enter the same global words table as private provisional rows (is_public=0, created_by_user_id) under a global UNIQUE(lemma), and the one stated promotion
rule is purely automatic: a row becomes public only when Claude's lookup_word returns is_english=true AND safe_for_sharing=true (decision log #4, principle 6
"Shared data is validated data"); the docs contain no human review queue, moderation, promotion-to-canon or unpublish step, and ECDICT-hit words skip validation
entirely. Integrity rules are UNIQUE lemma, tri-state is_valid_english, safe_for_sharing, a source CHECK of seed/ecdict/claude/user (no 'admin'),
merged_into_word_id, the word_forms headword guard, a deterministic validator plus relatedness rule for any Claude-proposed headword, never-auto-applied typo
fixes, and seed words being immune to AI invalidation. AI-optional operation is a first-class design decision (principle 5 "Never-empty fallbacks", decision
#10, kill switch WD_AI_ENABLED=0 / kv.claude.enabled='0' → "the app runs on ECDICT data + template cards", finalize_building flips batches to ready at once,
browsing never enqueues jobs), and both the docs and tests pin the degraded states. Of the 7 MUST-HAVEs, #1, #2, #3 and #6 need no AI; #7's image half needs no
AI (Claude SVG is an optional last resort, template card never fails) but its example-sentence half exists only as Claude-generated word_contents because the
seed carries no examples; #5 works without AI only for words resolvable via seed/ECDICT (unknown strings become permanently 待校验 dead-ends); #4 is intrinsically
Claude Code (lookup_word, consolidate_bank, generate_content). Operator-side global content generation already exists as the admin prewarm plan (admin-only,
never automatic, budgeted) plus per-word regenerate/refetch-image, and the seed file can be updated via wd import-seed (idempotent upsert that never touches
content or user data, auto-run when the file's sha256 changes). However, the kill switch only stops the worker: adds still create provisional rows and lookup
jobs, unfamiliar marks and batch builds still enqueue content, and the scheduler still enqueues nightly consolidate_bank per user, so queued end-user-originated
jobs would all run the moment AI is re-enabled — config alone is not a policy guarantee. Consolidated gap list for an "admin-curated shared library, zero end-
user AI" mode: already exists — seed import/update path, admin prewarm/regenerate/refetch, visibility rule, GET-only browsing, degraded card copy; config-only —
WD_AI_ENABLED=0 (or kv.claude.enabled) to silence the worker, WD_SVG_VIA_CLAUDE=0, WD_ECDICT_DB_PATH for instant dictionary resolution, raised budget caps for a
one-off full-seed prewarm, WD_REGISTRATION_MODE; small code change — stop enqueueing lookup/content/consolidate jobs when a "no end-user AI" flag is set (or
refuse unknown strings instead of creating provisional rows), hide 生成例句/立即整理 and reword the "tomorrow" copy using ServerFlags.ai_enabled, route admin-initiated
regeneration through a separate switch; new feature — admin word-curation API/UI (publish/unpublish/merge/delete/rename/ban, provisional-word review queue), an
admin privileged add/promote path with provenance/licence columns, export of curated words back to data/seed, non-AI content authoring or import (hand-written
examples), and per-user AI attribution (already identified in PUBLIC_LAUNCH A1/A2/B5/C7/D8, cross-referenced not duplicated here).
