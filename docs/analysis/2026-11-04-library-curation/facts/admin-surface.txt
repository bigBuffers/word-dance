# SLICE admin-surface  (35 findings)
## SUMMARY
The admin surface is exactly 21 HTTP routes (API.md endpoints 54–74) in three routers (backend/wd/routers/admin_ops.py, admin_reports.py, admin_users.py), every
one gated by deps.require_admin, which only checks users.role == 'admin'; the schema and Pydantic models allow just two roles ('user','admin'), and no
curator/moderator/editor concept exists anywhere in code, schema or design docs. Someone becomes admin by being the first account ever registered (auth.py
bootstrap), by `wd create-admin`, by `wd promote <username>`, or by another admin posting role:'admin' (UI button 设为管理员); demotion/deactivation of the last
active admin is refused (409 last_admin). The UI (/admin, 管理, AdminPage.tsx) has seven tabs: 概览 (counts, spend, image mix, queue, provider quotas, health incl.
seed_version/last_backup), 用户与邀请 (disable/enable, make admin, reset password, create invite), 任务 (filter, 重试, 重排所有失败任务, dev-only run-once), AI (pause/resume,
probe, 预生成 prewarm form, call ledger), 内容反馈 (reports: 重新生成 / 换图 / 忽略), 事件 and 配置 (read-only, secrets masked). The CLI adds import-seed, create-admin/set-
password/promote/demote/invite, backup/restore, claude-check, worker-once, tick, build-batch/push-now, consolidate, fetch-image/images-prune, stats/check/logs.
On GLOBAL data (words, word_contents, word_images) an admin can only (a) ask Claude to regenerate content for a validated word (endpoint 68 or the report-
resolve regenerate flag), (b) enqueue a new image fetch optionally pinned to a provider including claude_svg (endpoint 69 / report refetch_image / `wd fetch-
image`), (c) run a budgeted prewarm over public validated words of a stage (endpoint 67, Claude), (d) re-import the seed file (`wd import-seed --file`,
dictionary columns only, forces is_public/is_valid_english/safe_for_sharing=1), (e) prune cached images, and (f) back up / restore the whole SQLite database.
Everything else an admin can change is PER-USER (user rows, invites, a user's batch via push/run, consolidate <user>) or operational (jobs, pause, events).
There is no endpoint, UI control or CLI command to create a word, edit lemma/phonetic/translation/definition, write or edit content by hand,
hide/unpublish/delete a word, flip is_public/is_valid_english/safe_for_sharing, promote a user's provisional word to public, list words by creator, see
needs_attention across users, export/import words or content, or publish a library version; the only version signal is kv.seed_version (sha256 of the seed
file). Report moderation never alters the word's text or visibility: it either enqueues a forced generate_content job (validated words only), rejects the active
image and enqueues fetch_image excluding it, or just marks the report resolved/dismissed. Every admin content lever therefore routes back into the same Claude
job pipeline, and the AI gate (WD_AI_ENABLED plus kv.claude.enabled, plus kv.claude.paused_until) is shared by admin-triggered and end-user-triggered calls:
prewarm answers 503 ai_disabled, regenerate/refetch 202 but their jobs idle in the queue while the ClaudeWorker gate is closed, and the user-facing
content/request endpoint uses the identical gate, so there is no 'AI for admins only' mode today. Admins do see every word (visibility predicate becomes 1=1),
so they can open any private/provisional word by id, but there is no admin listing to discover such words beyond the overview counts and the reports table.
