# SLICE seed-pipeline  (32 findings)
## SUMMARY
The shared word library is a 9,162-record JSONL seed (data/seed/vocab.jsonl.gz, sha256 a68127…, record count verified by decompressing it) that was built once
in the P0 commit by scripts/build_seed.py from two external inputs that are NOT in the repo: ECDICT release 1.0.28 stardict.db (MIT; licence text in
data/licenses/ECDICT-LICENSE) and six mahavivo/english-wordlists syllabus files (no licence published; only head-word membership is used). The seed set is the
union of every ECDICT row tagged zk/gk/cet4/cet6 and every syllabus head word found in ECDICT; each record carries 15 fields (word, phonetic, translation[],
definition[], pos, collins, oxford, stages[], exam_tags[], bnc, frq, exchange{}, sources[], ecdict_id, cet6_star), and the only stage axes are 初中/高中/四级/六级 —
考研/TOEFL/IELTS/GRE exist solely as display-only exam_tags copied from ECDICT's tag column. Rebuilding requires `make seed ECDICT_DB=… WORDLISTS_DIR=…` plus
`scripts/pack_seed.sh` (gzip -9 -n for a reproducible hash); the intermediate vocab.jsonl is gitignored. Import into SQLite is backend/wd/seed.py: `wd import-
seed [--file] [--force]` from the CLI, step 6 of deploy/install.sh right after `wd migrate`, and automatically inside `wd serve` startup (`main.seed_check`)
whenever kv.seed_version differs from sha256(WD_SEED_PATH); there is no HTTP/admin endpoint that imports or edits the seed (grep of backend/wd/routers for
import_seed/seed finds only admin_ops.py:200 reading kv.seed_version for the 词库版本 display). The import is one BEGIN IMMEDIATE transaction doing an INSERT … ON
CONFLICT(lemma) DO UPDATE over the GLOBAL tables words and word_forms only; it never deletes words, never duplicates (UNIQUE ux_words_lemma), updates only rows
whose seed-managed columns actually changed, and never references user_words, word_contents, word_images, active_content_id, content_state, difficulty or
created_by_user_id (PER-USER and generated data survive untouched). Consequently an operator CAN fix a definition or add a word by editing the JSONL and re-
importing: the changed lemma is updated in place, new lemmas are inserted (source='seed', is_public=1, is_valid_english=1), and no AI call is involved — but
existing AI-generated word_contents for a corrected word are not invalidated or regenerated, and records removed from the file stay in the database. The most
important trap is that kv stores only the hash, not the path: after `wd import-seed --file custom.jsonl`, the next service restart sees kv.seed_version ≠
sha256(repo seed) and re-imports the repo seed, reverting every shared lemma, so curated content must replace data/seed/vocab.jsonl.gz or WD_SEED_PATH must
point at the curated file. The ECDICT stardict.db is a separate, optional runtime artefact (deploy/fetch_ecdict.sh, WD_ECDICT_DB_PATH): services/ecdict.lookup
is step 3 of lemma resolution (exact → form → ecdict → provisional) and in GET /api/lookup; it is never used for seed phonetics; when configured it turns an
off-seed dictionary word into a new global words row with no Claude job, while without it the same word becomes a private provisional row plus an end-user-
triggered lookup_word Claude job. Seed words are never AI-validated or AI-filled (is_valid_english=1 short-circuits lookup; content apply treats valid=false on
a seed word as an anomaly; fill_data refuses seed words), so the seed pipeline is the sole author of dictionary columns for the 9,162 core words. Today's
production sequence to change library content is: rebuild or hand-edit the JSONL → update stats.json total_words → scripts/pack_seed.sh → commit → `git pull &&
deploy/install.sh` (stops the unit, migrates, imports, restarts) or simply restart the service.
