## 0 一页结论

1. **同类 App 怎么做**（11 款，第 2 节）：手机号 + 短信验证码是主身份（欧路除外），配运营商「本机号码一键登录」；微信是可与手机号互绑的第三方登录，多数以手机号为锚，但欧路、墨墨（网页端扫小程序码注册）、多邻国允许仅凭微信建号、之后再补绑；Apple 登录主要出现在 iOS 版（一般认为是为满足苹果审核指南 4.8）；**没有一款把邀请码当注册门槛**，K-12 类用「班级号 / 老师邀请家长」作注册后的可选步骤。儿童类 App 都以手机号为账号：洪恩要求注册人声明自己是监护人，斑马、小猿、百词斩允许孩子本人持号注册、登录时弹窗确认「是否满 14 周岁、是否有监护人陪同」；「家长账号 + 孩子档案 / 切换」在海外（Khan Academy Kids、多邻国）是确认做法，国内 App 的多孩流程官方页面未能核实。
2. **个人开发者（无营业执照、无 ICP 备案、服务器在东京）今天能用什么**（第 3 节）：
   - **微信**：开放平台的网站 / App 微信登录、公众号网页授权、扫码关注登录都要先做「开发者资质认证」，而认证只对企业 / 个体工商户 / 机构开放（官方登录页写明第一步就是认证；「个人不可认证」为微信客服与开放社区的一致答复）。**唯一开放的是小程序**：个人可注册、可做登录桥，但小程序认证 30 元/年、要做小程序备案、接口域名必须 ICP 备案（备案要求域名接入大陆主机）、拿不到用户手机号与跨应用统一标识（unionid）；而且个人小程序**没有从 App / 外部网页直接拉起小程序的官方能力**（URL Scheme / URL Link「目前仅针对国内非个人主体的小程序开放」）——手机上扫不了自己屏幕上的码，微信登录在手机端必然比同类 App 多一步（用户自己打开小程序输入配对码，5.3 节）。
   - **手机号**：2025 年起所有短信签名须企业实名报备，三大云与短信宝明确个人不能报备（互亿无线、螺丝帽未说明，视为不可依赖）。个人可自助开通且有官方文档背书的大陆验证码通道只有**阿里云「号码认证服务 → 短信认证」**（系统签名 + 固定文案，个人实名即可，仅 +86，¥0.06/条，纯 HTTPS 接口；「从东京调用没有障碍」是推断，第 0 天实测）。境外短信路由到大陆号码基本不可用；一键登录只有极光写明接受个人实名，且只对手机端有意义。
   - **邮箱**：合规、便宜、不要求备案；QQ / 163 对境外来信过滤严，应改用阿里云 / 腾讯云**邮件推送 API**（约 ¥0.002/封；阿里云共 2000 封免费但每天最多免费 200 封；腾讯云个人账号只能走 API），前提是先有一个自有域名并配好 SPF / DKIM / DMARC 记录。
   - **顺带可用**：QQ 登录（QQ 互联接受个人开发者，但回调域名须备案——与小程序共用备案域名，第二步）；Apple 登录在网页 / Android 也能用（Sign in with Apple JS，个人开发者账号即可）。
3. **法规**（第 4 节）：实名义务按服务类型触发（信息发布、即时通讯等）；我们的解读（非官方，监管未对学习类 App 作过正式解释）是学习者私有的生词与备注不构成信息发布，一旦出现把学习者文字展示给他人的功能就要补手机号核验。但 2022 年《移动互联网应用程序信息服务管理规定》第 13 条要求「依法严格落实未成年人用户账号真实身份信息注册和登录要求」，教育部 2019 年文件也期待教育 App「后台实名、前台自愿」——所以**未成年学习者的账号应挂在一个经核验的手机号上**（家长的或学生本人的）。另一方面「不得因用户不提供非必要个人信息而拒绝基本功能」（学习教育类基本功能无需任何个人信息），所以成人的邮箱路径与「不注册先看看」要保留。未满 14 岁的数据是敏感信息，需监护人同意（法律未规定验证方式，业界做法是声明 + 监护人手机号）；未成年人模式对教育 App 目前非强制（2026-09 国务院征求意见稿可能把面向 16 岁以下的 AI 服务纳入）；注销必须有、≤15 个工作日；iOS 壳一旦提供微信登录，就必须同时提供满足 4.8 三项条件的等价登录，实务上就是 Apple 登录。
4. **推荐**（第 5 节）分三步：
   - **第一步，现在就能做**（约 15 人日，分两个可独立上线的切片）：手机号验证码（阿里云短信认证代发、验证码由我们生成与校验）+ 邮箱验证码（邮件推送 API）+ 保留用户名密码登录；新注册模式 `verified`（必须验证手机号或邮箱，邀请码降为可选「加入码」）；无密码账号的重认证（改密 / 注销用验证码）、找回密码、二次放号防护、防刷与短信日预算；家长账号 + 孩子子账号（切换过「家长门」，孩子自己的设备用一次性登录码）；年龄声明与监护人同意留痕、隐私政策与儿童规则页、存量账号的补充信息流程、登录页只读演示。
   - **第二步，需要备案域名 + 大陆中转主机**（开发约 1 周，两道备案串行 4–8 周）：个人小程序「单词之舞」做微信登录桥（电脑扫码、手机输配对码）+ QQ 登录 + Apple 登录；有被管局要求「校外培训」前置审批而卡死的风险，预设退出条件。
   - **第三步，有公司之后**：开放平台认证 → App 内原生微信登录、一键登录、自有品牌短信签名、运营商二次号查询。
5. **需要你确认的决定**见第 6 节（13 项，每项有建议默认值）。

## 1 现状（代码事实，2026-11-10）

- **注册** `POST /api/auth/register`：用户名（2–32 个字母 / 数字 / 下划线 / 汉字）+ 密码（8–64）+ 可选昵称、邮箱、邀请码；`WD_REGISTRATION_MODE` 三档 `open / invite / closed`，邀请码只在 `invite` 档要求（管理员用 `wd invite` 或管理页签发，sha256 哈希存储、可限次数与期限）；`users` 表为空时首个注册者成为管理员（不看模式、不要邀请码）。按 IP 限流：注册 5 次/小时，登录 20 次/10 分钟（成功也计数）；按用户名的失败锁定 10 次后 15 分钟起步、每再错 5 次翻倍、最长 24 小时——任何人都能触发别人的锁定，且没有解锁命令（`PUBLIC_LAUNCH_AND_IOS.md` A4 / A8 已记录）。
- **登录** `POST /api/auth/login`：用户名 + 密码，Cookie 会话（一个浏览器一把钥匙，每用户最多 20 个会话）；`GET /api/auth/me` 返回用户、设置、服务器标志。
- **邮箱**：可选字段，`POST /api/account/email/request-code` / `verify` 发 6 位码（HMAC 哈希存 `email_codes`，15 分钟、5 次尝试、每用户 3 次/小时），只服务邮件推送渠道（`users.email` + `email_verified_at`、设置项 `email_enabled`），**不用于登录**；发信走 `WD_SMTP_*`，发信抽象 `Mailer` 已存在。
- **账号**：改密码、注销（级联删除）、导出 / 导入已有——但改密与注销都以**当前密码**为唯一重认证手段（`verify_account_password`，10 次 / 15 分钟预算；前端表单同样写死）；`users.password_hash` 与 `username` 都是 `NOT NULL`。没有手机号、没有第三方身份、没有年龄门槛、没有找回密码、没有隐私政策页。
- **引导**：新账号带 `onboarding_state`，未完成前学习端点返回 409 `onboarding_required`、前端 `RequireOnboarded` 拦截——新流程可以复用。
- **客户端**：网页 + Capacitor 远程壳（Android 已构建；iOS 工程已建、尚未构建与真机验证），壳直接加载线上站点，`<html>` 带 `native-ios` / `native-android` 类可按端隐藏入口；壳内第三方 SDK 登录需原生插件——个人没有微信开放平台资质，**两端都不内置微信 SDK**。
- **提醒**：webhook 渠道（Bark、Server酱）今天已能把每日提醒发进 iPhone 与微信。

| 邮件推送（阿里云 / 腾讯云） | **是** | 阿里云：共 2000 封免费、每天最多免费 200 封、之后约 ¥0.002/封，发信域名要过 SPF / DKIM / DMARC / MX 四项；腾讯云：¥0.0019/封、1000 封免费，2026-03-02 起个人账号只能走 API；都不要求备案 | 都要先有自有域名；阿里云个人账号能否开通文档未明示（第 0 天实测）；QQ / 163 对境外 SMTP 过滤严，所以不用东京自建 SMTP | R3-44～48、R6-14、15 |
| QQ 登录（QQ 互联） | 可能 | 官方「成为开发者」接受个人；网站地址与回调地址须工信部备案且一致 | 有了备案域名即可；电脑扫码、手机拉起 QQ，没有同机扫码问题；中小学生中 QQ 使用率高；第二步与小程序同期（开工前再核） | R6-07 |
| Apple 登录 | **是** | 个人开发者计划（¥688/年，iOS 壳本就需要）；iOS 原生 + 网页 / Android 用 Sign in with Apple JS（Services ID + 域名验证） | 返回 Apple 验证过的（可中继）邮箱，可作已验证渠道并满足 4.8 | R4-37、R6-08 |

## 4 法规与商店规则要点

- **实名**：《网络安全法》（2026-01-01 修订后为第 26 条）、《反电信网络诈骗法》第 21 条、《互联网用户账号信息管理规定》第 9 条、2022 年《移动互联网应用程序信息服务管理规定》第 6 条，都把真实身份核验绑定在「信息发布、即时通讯」等服务上；2016 年「所有 App 后台实名」的规定 2022 年已废止。**我们的解读（非官方）**：学习者私有的生词本和备注不是信息发布；一旦出现把学习者文字展示给他人的功能（共享词表、评论、班级动态）就触发手机号 / 证件核验。教育部 2019 年《关于引导规范教育移动互联网应用有序健康发展的意见》期待教育 App 对注册用户「后台实名、前台自愿」（R4-01～11）。
- **未成年人账号的实名**：2022 年 App 规定第 13 条（官方原文，2026-11-10 核对）：「应用程序提供者应当坚持最有利于未成年人的原则……**依法严格落实未成年人用户账号真实身份信息注册和登录要求**，不得以任何形式向未成年人用户提供诱导其沉迷的相关产品和服务」。对 K-12 产品意味着未成年学习者的账号应落在一个经核验的手机号上（家长的或学生本人的），不宜只靠用户名密码匿名注册（R6-02）。
- **不得强制**：《常见类型移动互联网应用程序必要个人信息范围规定》——学习教育类、工具类的基本功能**无需任何个人信息**，以用户不提供非必要信息为由拒绝基本服务属违规（PIPL 第 16 条、App 规定第 12 条同旨）。我们的解读：把手机号设为使用前提与这些规定有张力；对标里的洪恩、小猿、斑马都以「法律法规及安全」为由强制手机号且未见被通报，说明执行偏松，但保留成人邮箱路径与「不注册先看看」是更稳妥的选择（R4-45、46）。
- **未成年人**：未满 14 岁的个人信息是敏感信息（PIPL 第 28、31 条），需监护人同意并有专门的儿童规则；法律没有规定验证方式，业界用「声明 + 监护人手机号 / 账号确认」（华为用家长账号密码确认）；未成年人模式只对游戏、直播、音视频、社交强制，教育 App 非强制，但设备级一键开关要兼容。**注意** 2026-09-18 国务院《关于保障未成年人健康安全使用网络的规定（征求意见稿）》（意见截止 2026-10-17，尚未生效）：向未满 16 岁提供「可能影响未成年人认知的人工智能服务」须通过未成年人模式，且未设教育类豁免，并要求服务提供者具备未成年人用户识别能力——本项目只向学习者展示生成好的例句 / 舞步、不开放对话，落入的可能性低，但年龄段声明与子账号模型要为将来一键切到未成年人模式预留开关。面向未成年人的 AI 业界通行做法是「讲解思路、不直接给答案」（教育部 2021 年叫停拍照搜题；2026-03 起《分类办法》把宣扬代写代抄、抄袭作弊列为不良信息），不是明文要求（R4-13～29、R5-01～15）。
- **注销**：必须提供、不得设置不合理条件、≤ 15 个工作日；本项目已有级联注销，但今天只能凭密码触发——无密码的手机号 / 微信账号要按 5.2「重认证」补验证码路径，否则新账号既不能注销也不能设置首个密码，违反本条与苹果 5.1.1(v)；家长 + 孩子模型下子账号的去向见 5.1。苹果要求 App 内可删除整个账号，Google Play 要求 App 内 + 网页（R4-30～36）。
- **苹果 4.8**：App 内以微信等第三方登录建立主账号时，必须另提供一个满足三项条件（只收集姓名邮箱、允许隐藏邮箱、未经同意不为广告采集行为）的等价登录；自有手机号 / 邮箱验证码登录不满足「可隐藏邮箱」，实务上即 Sign in with Apple；App 只用自有账号体系则豁免。条文不区分原生与网页内容，远程壳里加载的线上登录页就是 App 的登录页（R4-37～39）。

## 5 推荐方案

### 5.1 账号模型（三端共用）

- **`users` 保留为「一个学习者一个账号」**（全部学习数据按 `user_id`，不动），**只加列、不重建**：`account_kind`（`learner` / `guardian`，默认 `learner`）、`guardian_user_id`（孩子账号指向家长账号，可空，`REFERENCES users(id) ON DELETE RESTRICT`）、`age_band`（`u14` / `14plus` / `adult`，注册时声明，可空 = 未声明）、`age_declared_at` / `age_declared_ip`（声明留痕；声明不做进一步核验，隐私政策如实写明）、`guardian_consent_at`、`password_set_at`（可空；老账号回填为 `created_at`）、`guardian_pin_hash`（家长门，可空）。
  - `password_hash` **保持 `NOT NULL`**：纯手机号 / 邮箱 / 第三方账号写入一个随机密钥的 bcrypt 哈希作「不可用密码」（`verify_password` 永不匹配、仍付一次 bcrypt 耗时，登录口看不出有无密码，现有登录代码零改动）；「有无密码」看 `password_set_at`（API 暴露为 `User.has_password`，设置页据此显示「设置密码」或「修改密码」）。原因：SQLite 去掉 NOT NULL 要重建表，`users` 被 12 张表外键引用，重建按仓库规则是停机迁移；加列则是 0012 / 0014 / 0015 / 0017 一类的纯附加迁移。
  - `username` **保持 `NOT NULL UNIQUE`**：手机号 / 邮箱 / 微信 / Apple 注册的账号和家长建的子账号，由服务器生成不可猜的占位用户名（`u_` + 8 位 base32，满足 `USERNAME_RE`，撞上即重生成），不在界面展示，因此这类账号的昵称必填；之后可在设置页一次性自定义用户名。密码登录框同时接受用户名 / 手机号 / 邮箱（扇贝的做法），占位用户名从不需要用户输入。老账号与 `wd set-password / promote / demote <username>` 照旧。
  - 不变量：`role='admin'` 的账号必须有密码（应用层保证——`promote` / 管理页提升无密码账号时 409 `password_required`；表级 CHECK 要重建表，不加）。
- **新表 `identities(user_id, provider, subject, verified_at, last_login_at, disputed_at, meta_json)`**，`provider ∈ {phone, wechat_mini, qq, apple}`；`(provider, subject)` 在 `disputed_at IS NULL` 的行上唯一（部分唯一索引，二次放号的争议绑定让位给新账号，见 5.2）；手机号存 E.164（+86 后 11 位、首位 1）；Apple 以其 `sub` 为 subject。**邮箱不进 `identities`**：继续只有 `users.email` + `email_verified_at` 一份真相（写入时 NFKC、去首尾空白、整体小写；已有部分唯一索引），只有 `email_verified_at IS NOT NULL` 的邮箱才算一个可登录渠道——这样今天读这两列的邮件推送链路、`email_not_verified` 门槛、「改 / 清空邮箱即清空验证并关闭推送」全部不动。别人用某邮箱验证通过时，同一事务里把原持有者那一行未验证的 `email` 清空，再写到验证者名下（未验证的占用不算数）。Apple 返回的邮箱（含隐私中继地址）只作为可选的推送收件地址候选，需用户在设置里走一次邮箱验证码才成为已验证邮箱。
- **登录方式不变量按账号类型定义**：孩子账号（`guardian_user_id` 非空）不要求登录方式（访问路径是家长切换或孩子登录码）；学习者至少一个（密码或已验证渠道）；家长账号必须有**已验证手机号 + 第二因子**（密码或已验证邮箱）——家长会话可切换到所有孩子，接管代价最高。解绑 / 清空邮箱 / 删任一身份行时服务端校验不变量，否则 409 `last_login_method`；解绑邮箱同事务清空 `email_verified_at` 并关闭 `email_enabled`。
- **绑定规则**：绑定前必须先向目标发码并校验（`purpose=bind_*`），再在同一事务内写入；`(provider, subject)` 已属其他账号 → 409 `identity_taken`，响应不透露对方任何信息；换绑只能由持有方先解绑；**第一步不做账号合并**（同一人用邮箱和手机号各注册了一个账号时提示「请用原登录方式登录后在设置里绑定」）。
- **新表 `login_codes(id, channel, target, purpose, user_id NULL, code_hash, expires_at, attempts, used_at, ip, created_at)`** 取代 `email_codes`：`code_hash = HMAC-SHA256(WD_SECRET_KEY, code:channel:target:purpose)`；`purpose ∈ {login, bind_phone, bind_email, rebind_phone, reauth, reset_password}`，`bind_* / reauth / reset` 必填 `user_id` 并在校验时比对会话用户；同一 `(channel, target, purpose)` 新码作废旧码；10 分钟有效（原邮箱码 15 分钟一并改为 10 分钟、邮件文案同步）；错 5 次即作废；`hmac.compare_digest` 比较；过期行由调度器每小时 GC（与会话 GC 同处）。`email_codes` 第一步只停写不 DROP（DROP 不是附加迁移），留到下一次本就要停机的迁移再删。
- **`sessions` 加列 `actor_user_id`**（签发该会话的家长，NULL = 本人登录），供 5.2 的切换与边界使用。
- **家长 + 孩子**：家长用自己的手机号注册（`guardian`，首次设置时必须再补一个因子：设密码或绑邮箱），在「我的孩子」里为孩子建子账号（昵称 + 年级，不要孩子的手机号；建第一个孩子时设 6 位家长 PIN），一键切换到孩子账号学习（切回要过家长门）。孩子自己的平板 / 旧手机：家长在「我的孩子」里生成一次性 8 位**登录码**（10 分钟有效，可重发），孩子设备输入后得到一条绑定该设备的 90 天会话；或为子账号设一个简单用户名 + 密码（复用现有登录）——两者都不需要孩子有手机号。已满 14 岁的学生直接用手机号注册 `learner`；孩子满 14 岁后由家长发起「独立」：孩子用自己的手机号完成验证码绑定并设密码 → `guardian_user_id` 置空、`age_band='14plus'`、家长失去切换权，不可逆、写系统事件。**依据**：PIPL 第 31 条与 Khan Academy Kids / Duolingo 的做法；比国内对标 App 的「孩子自填手机号 + 弹窗声明」更稳妥，也比「多档案」改动小（学习数据模型不变）。
- **家长注销时子账号的去向**：`ON DELETE RESTRICT`——不用 CASCADE（家长一键注销会无提示抹掉孩子的全部学习数据），也不用 SET NULL（留下一批无监护人、无登录方式的 `u14` 账号）。`DELETE /api/account` 增加可选字段 `delete_children`：名下仍有未独立的子账号而未传 `true` 时返回 409 `has_children`（列出孩子）；传 `true` 时同一事务里：已绑定自己已验证手机号的孩子自动独立（数据保留），其余子账号随家长一并注销——这正是《儿童个人信息网络保护规定》第 20 条「监护人通过注销等方式终止使用」应删除儿童信息的要求。注销确认页列出受影响的孩子，勾选确认后才发送。另提供单个子账号的注销（过家长门）。
- **迁移**：`0018_auth_identities.sql`，纯附加（新表 `identities`、`login_codes`；`users` 加列；`sessions.actor_user_id`），可 `--no-restart`，Mac 上一次 `launchctl kickstart -k`；`docs/SCHEMA.sql` 不改（0001 基线由测试钉住），表注释进迁移文件头，DESIGN §10 的 Identity / Registration / Throttling 行同步；回滚 = 只回代码，新列与新表留着无害。第二步的 `wechat_tickets` 放进第二步的迁移。

### 5.2 注册与登录流程（第一步）

- **手机号**：页面勾选「已阅读并同意用户协议与隐私政策」后才能发码（手机号在发码时就已被处理，同意必须在此之前；与扇贝 / 百词斩一致）→ 输入 +86 手机号 → 图形验证码（自托管滑块，`verified` 模式下所有未登录的发码请求都要过；已登录用户的改绑 / 重认证免）→ 发送验证码（阿里云短信认证代发）→ 输入 6 位码 → **服务端校验即作废该码，并在同一个 `BEGIN IMMEDIATE` 事务内按 `(phone, subject)` 查 `identities`：已绑定 → 签发会话（登录）；未绑定 → 插入 `users`（占位用户名、不可用密码、`onboarding_state` 未完成）+ `identities` + 会话**（唯一约束冲突说明另一请求刚用同一手机号完成注册，按登录处理）。新账号随后在会话内进入「首次设置」（昵称、我是家长 / 我是学生并声明年龄段、可选加入码），完成前学习端点照旧 409 `onboarding_required`。「已验证」这一事实只存在于服务端的同一事务里，不接受客户端自报，也不需要另发一次性凭证。不设密码也可以（之后在设置页「登录方式」里设，见「重认证」）。
- **邮箱**：同一套流程，目标就是 `users.email`（不另建身份行），验证码走阿里云 / 腾讯云邮件推送，替换现有 `email_codes`；邮箱注册只面向成人（自我声明）。
- **用户名密码**：对老账号永久保留为登录方式；`verified` 模式下新用户必须先验证手机号或邮箱，用户名密码只能作为附加方式在首次设置或设置页添加，邀请 / 加入码不能绕过验证；只有 `open` 档允许纯用户名密码注册（公开后不建议）；`invite` 档保持今天的行为。失败锁定键改为「输入的标识 + IP」（用户名 / 手机号 / 邮箱均可作键），加 `wd unlock <标识>`；验证码登录不走锁定键，由下文的发送 / 校验限额兜底。
- **验证码的生成与校验（短信与邮箱同一套）**：验证码一律由本服务生成（6 位十进制，`secrets.randbelow`）并按 5.1 的 `login_codes` 规则存储校验。短信通道**只借阿里云代发**：`SendSmsVerifyCode` 的 `TemplateParam` 传具体值 `{"code": "<本地码>", "min": "10"}`（官方允许自传 4–6 位数字验证码），**不调用** `CheckSmsVerifyCode`，长度、有效期、尝试次数全部由我们控制，邮箱与短信的校验代码只有一份。用途 → 赠送模板：登录 / 注册 → 100001，换绑手机号 → 100002，重置密码 → 100003，绑定新手机号 → 100004，验证绑定手机号 → 100005（100002–100005 的正文公开文档未列出，开通后在控制台核对）。适配器只负责「发送」：阿里云返回 `FREQUENCY_FAIL` / `BUSINESS_LIMIT_CONTROL` → 429 `rate_limited`（带 `Retry-After`），其他失败 → 503 `sms_send_failed`；被阿里云拒绝的发送官方不计费，也不计入日预算。
- **重认证（敏感操作）**：改密码、注销、解绑最后一个渠道 / 换绑手机号、孩子独立、从孩子切回家长，现有代码只认「当前密码」。改为「用任一已绑定的登录方式再过一次」：有密码可输密码；否则向已验证的手机号 / 邮箱发 `purpose=reauth` 的验证码（模板 100005）；只绑了微信 / Apple 的账号重新扫码 / 重新授权（第二步）。错误次数并入现有 10 次 / 15 分钟的密码校验预算。契约：`POST /api/account/password` 在账号尚无密码时可省略 `current_password`、改带 `code`（首次设密码）；`DELETE /api/account` 接受 `{password}` 或 `{code}` 二选一；设置页按账号状态显示「设置密码 / 修改密码」，注销弹窗对无密码账号改为发码确认。
- **忘记密码**：输入用户名或任一已绑定渠道 → 发码（`purpose=reset_password`，模板 100003，走同一限流与预算）→ 校验 → 设新密码 → 吊销该用户所有其他会话、写系统事件。响应对「用户名不存在 / 未绑定渠道」与成功一致（202），防枚举；没有任何已验证渠道的老账号仍走管理员 `wd set-password`。
- **邀请码 → 加入码**：`invite` 档保留给私测期；`verified` 档下邀请码变为可选的**加入码**，只表示「加入某位家长的家庭」（把新账号挂到该家长名下，复用 `invite_codes.created_by`）：家长在「我的孩子」页通过新端点 `POST /api/account/join-codes` 签发（`max_uses ≤ 10`、有效期 ≤ 30 天），管理员端点不变。老师 / 班级第一步不做（D11）。
- **管理员与引导**：「`users` 为空时首个注册者成为管理员」只对用户名密码注册与 `wd create-admin` 生效；手机号 / 邮箱验证码以及第二步的微信 / QQ / Apple 在站点尚未初始化时一律 403 `setup_required`，绝不创建管理员。管理员账号只接受密码登录：验证码 / 第三方登录命中 `role='admin'` 时 403 `password_required`（绑定渠道本身不受限，管理员通知仍可用）；管理员不能解绑密码。这是管理员二次验证到来之前的底线。
- **二次放号防护**：大陆手机号注销满 90 天最短冻结期即可重新放号，号码新主人仅凭验证码就能进入原主人未改绑的账号——这正是工信部 2025 年起推「二次号码焕新 / 一键解绑」的原因（R6-03、04）。个人拿不到运营商「二次号查询」接口（需企业实名，R6-06），第一步用三条规则兜底：① 验证码登录命中的手机号身份若 `last_login_at` 距今 ≥ `WD_PHONE_STALE_DAYS`（默认 90；会话固定 30 天不续期，活跃用户不会误触），不直接签会话，先显示掩码昵称与注册年月，问「这是你的账号吗」——选「是」再过一个因子（密码或已验证邮箱验证码；两者都没有的账号给「联系管理员」路径并记事件），选「不是」则旧绑定写 `disputed_at`（旧账号保留密码 / 邮箱登录，有邮箱则发通知），用该手机号新建账号，管理页列出争议绑定可人工恢复（微信对「新手机号提示已注册过」的处理正是「不是我的，继续注册 → 旧绑定自动解除」，R6-05）；② 家长账号必须有第二因子（5.1）；学习者账号首次登录后横幅提示「设一个密码，换号也不怕丢进度」；③ 设置页「更换手机号」：旧号收码（100002）→ 新号收码（100004），并提示「换号前先在这里改绑」。
- **未成年人**：所有未成年人账号都挂在已验证手机号上（家长的，或 14 岁以上学生本人的）。注册时的年龄段声明是「家长 / 学生（已满 14）」二选一；未满 14 岁只能由家长创建子账号，监护人同意时间、家长身份与声明 IP 记录在案；子账号默认关闭任何面向他人的功能（目前本就没有），AI 例句继续可用；提供《儿童个人信息处理规则》页面。
- **防刷与成本**：限额按端点与键分列如下，都走现有 `auth_throttle`；全站日预算 `WD_SMS_DAILY_CAP`（默认 200）才是真正的成本闸，按 IP 的限额只防脚本，不该挡住共用一个出口 IP 的一个班、一个家庭（今天 `register:ip` 在任何校验之前就计数、`login:ip` 把成功登录也计入，部署手册已记下「同一 Wi-Fi 每小时 ≤ 4 人注册」的实际限制——而本方案的目标用户正是共用出口 IP 的群体，所以下表属于必做项）。

  | 端点 | 键 | 限额 | 说明 |
  |---|---|---|---|
  | 发送验证码 | `code_send:target:<E.164 或邮箱>` | 1 次/分钟、5 次/小时、10 次/天 | 第一道线；阿里云侧的 60 秒间隔与天级流控是第二道 |
  | 发送验证码 | `code_send:ip:<ip>` | 每小时 20 次（`WD_CODE_IP_HOURLY`，可调） | 按「一个班一节课一起注册」校准；超限提示稍后再试并写管理员通知 |

  发送端对已注册 / 未注册目标返回同样的 202 与同样的耗时（都真实发送），枚举只在校验成功后暴露——这是「登录注册合一」的既定代价。图形验证码选自托管：不引入第三方脚本（保持 CSP `script-src 'self'`，兼容 Google Play 家庭政策与儿童类目，不依赖大陆可达性），代价是能被专业脚本绕过，所以真正的兜底是三层：每号 / 每 IP / 每号段频控 → 全站小时与日上限 → 超限自动关闭短信入口并通知管理员；云验证码（腾讯云每月 1 万次免费、阿里云 ¥0.005/次）留作被刷后的升级项。成功登录签发 30 天会话，减少重复发码；家长 ⇄ 孩子切换走家长门，不发码。
- **切换与边界（家长 ⇄ 孩子）**：浏览器和壳只有一个会话 cookie，签发孩子的会话就会换掉家长的会话，所以：`POST /api/auth/switch/{child_id}`（需家长会话且该孩子属于本人）新建一条 `user_id = 孩子、actor_user_id = 家长` 的会话并换 cookie，同时删掉家长当前这条会话（其他设备上的家长会话不受影响）；`POST /api/auth/switch/back` 只接受带 `actor_user_id` 的孩子会话，且必须过**家长门**（家长密码，或 6 位家长 PIN，或家长任一已验证渠道的新验证码兜底；PIN 失败按登录锁定的节奏计数），通过后吊销孩子会话、重新签发家长会话——共用平板上孩子不能随手切回家长。孩子会话一律 403 `guardian_required`：切换他人、身份绑定 / 解绑、改邮箱、改密码、注销；学习、设置、生词库照常。孩子账号的昵称 / 年级 / 注销 / 吊销会话 / 独立由家长在「我的孩子」完成（`/api/guardian/children/*`，需家长门）。客户端把切换当作一次登录处理；壳里的每日提醒随当前账号的推送设置重排（一台设备一条提醒）。`GET /api/auth/me` 增加 `session.guardian`（家长昵称，本人登录时为 null）供前端显示「切回家长」。
- **存量账号**（今天的 ≤ 10 位朋友与管理员）：迁移时 `account_kind='learner'`、`age_band=NULL`（未声明）；老账号下次登录弹一次「补充信息」：选家长 / 学生（已满 14）/「这是孩子的账号」，可选绑定手机或邮箱，可跳过、30 天后再提醒一次；选「这是孩子的账号」时输入家长手机号验证后挂到该家长名下（「认领为子账号」流程，家长账号不存在则顺带创建）；管理员账号不强制绑定，建议绑邮箱以便找回。
- **三端**：网页、iOS 壳、Android 壳都走同一套网页流程；一键登录（极光，个人可实名）作为壳内的可选增强留到第二步评估。
- **配置新增**：`WD_SMS_PROVIDER=off|aliyun_verify`、`WD_ALIYUN_ACCESS_KEY_ID`、`WD_ALIYUN_ACCESS_KEY_SECRET_FILE`（RAM 子用户，只授号码认证服务的系统策略；`*_FILE` 校验沿用 `WD_AI_FALLBACK_API_KEY_FILE`：必须是可读普通文件、组 / 他人可读时告警）、`WD_SMS_DAILY_CAP`（200）、`WD_SMS_HOURLY_CAP`（40）、`WD_CODE_IP_HOURLY`（20）、`WD_PHONE_STALE_DAYS`（90）、`WD_MAIL_PROVIDER=smtp|aliyun_dm|tencent_ses` + `WD_MAIL_API_KEY_FILE`、`WD_REGISTRATION_MODE` 增加 `verified`、`WD_CAPTCHA=on|off`。每个新变量同时写入 DEPLOY §4 表与 `deploy/env.example`（契约测试会校验），密钥加入 `config.SECRET_KEYS`；`WD_MAIL_PROVIDER` 替换的是整个 `Mailer` 实现（验证码与每日邮件渠道共用），`ServerFlags.email_configured` 的语义改为「所选提供方的必需变量齐全」，错误码 `smtp_unconfigured` 名字保留、文案改为「服务器未配置邮件发送」。

### 5.3 微信、QQ、Apple（第二步，前提是备案域名）

- **备案（两道，串行，4–8 周）**：① 先在腾讯云用一台**大陆**轻量主机做个人网站备案（备案要求主机包年包月 ≥ 3 个月；域名须在工信部批复的境内注册商注册并实名、与主体一致，与东京主站的境外域名分开；平台初审 1–2 个工作日 + 管局 1–20 个工作日）；② 再在微信公众平台做**小程序备案**（同样 1–20 个工作日；同一主体证件不能同时在两个平台提交首次备案，所以只能串行）。备案的服务内容与小程序类目一律选「工具」，网站名、小程序名与简介避免「教育 / 培训 / 中考 / 高考 / 提分」字样，把产品表述为个人学习工具——小程序备案与网站备案的前置审批表都含「校外培训」（省级教育部门批文），面向中小学生的内容若被认定为校外培训，个人拿不到批文（PUBLIC_LAUNCH §3.1 已指出）。**退出条件**：若管局要求校外培训前置审批，放弃第二步，微信登录等到有公司主体再做。备案后的义务：首页悬挂 ICP 备案号并链接工信部网站，30 日内完成公安联网备案并悬挂公安备案号；接入商会核查实际解析 IP 必须是其境内服务器、内容与备案一致，「个人备案的域名实际反代到境外」属灰色地带，可能在抽查时被取消接入（R6-09～13）。
- **大陆中转主机与小程序内容**（二选一，D8）：(a) 小程序只做「登录 / 绑定确认 + 静态的今日一句」，中转只转发 `/api/auth/wechat/*`，不展示个人进度——有被以「无实质内容」驳回的风险（运营规范 2.5.29）；(b) 小程序展示今日单词与进度，中转按路径白名单转发只读学习接口，学习数据经大陆主机。两者都要：中转主机上有一个最小首页（产品说明、两个备案号），不转发任何触发 AI 的端点（与地区门控一致），并预先准备把小程序 API 整体迁到大陆主机的方案以应对接入核查。
- **小程序**：个人注册「单词之舞」（类目：工具），小程序认证 30 元/年；`wx.login` → 后端 `code2Session` 得 openid（`session_key` 用完即弃，不入库、不下发）。
- **登录桥（双通道）**：新表 `wechat_tickets(ticket_hash, poll_secret_hash, kind, bind_user_id, status, openid, user_id, web_ip, web_ua, created_at, expires_at)`，`kind ∈ {login, bind, reauth}`，`status ∈ {pending, scanned, confirmed, consumed, expired, cancelled}`，票与轮询密钥只存 sha256。
  - **电脑网页**：向后端要一张票 → 后端生成 `ticket`（128 bit，留在小程序码场景值 32 字符之内）和只回给**发起浏览器**的 `poll_secret`（HttpOnly Cookie，3 分钟）；页面显示以 ticket 为场景值的小程序码，每 2 秒轮询一次，轮询必须同时出示 ticket + poll_secret，否则一律 404（创建与轮询都按 IP 限流）→ 用户微信扫码，小程序带 scene 打开 → 小程序**一律先显示确认页**（发起方 IP、浏览器、时间；`kind=bind` 时写明「绑定到 昵称 X」），用户点「确认登录 / 确认绑定」后票才进入 `confirmed`，**已绑定用户也不跳过**——否则任何人把登录页的码当「扫码领学习卡」发给受害者，受害者一扫，攻击者的浏览器就轮询到受害者的会话（二维码劫持；微信自家网页扫码登录同样要在手机上点「允许」）→ 网页轮询到 `confirmed` 后一次性换取会话（票转 `consumed`）。
  - **手机网页 / 壳**：同一部手机扫不了自己屏幕上的码，个人小程序又没有 URL Scheme / URL Link，所以改为**配对码**（设备码思路，RFC 8628）：页面显示 6 位配对码并提供「复制并打开微信」按钮，用户在微信里搜索或从最近使用打开小程序「单词之舞」，输入配对码、看到同样的确认页、点确认；网页轮询到 `confirmed` 后完成登录。微信内置浏览器里可试「长按识别图中小程序码」，无官方文档，列为实测项。
  - 规则：`kind=login` 且 openid 已绑 → 确认后给发起方签会话；未绑 → 在小程序里走 5.2 的「首次设置」直接建号（与墨墨一致，手机号为可选补绑），或先用验证码登录已有账号再绑定；`kind=bind` 的 `bind_user_id` 取自创建票时的网页会话、之后不可改，openid 已绑其他账号则拒绝「该微信已绑定其他账号」。票 3 分钟有效、一次性，过期 / 已消费行并入每小时 GC。
- **QQ 登录**：QQ 互联接受个人开发者，回调域就是上面那个备案域名；标准网页 OAuth（电脑扫码、手机拉起 QQ），`identities.provider='qq'`。开工前再核一次个人申请条件。
- **Apple 登录**：`identities.provider='apple'`（subject = Apple 的 `sub`）；iOS 壳用 Capacitor 插件，网页 / Android 用 Sign in with Apple JS（Services ID + 域名验证），个人开发者计划即可。**微信 / QQ 入口在 `html.native-ios` 下不渲染，直到 Apple 登录同批上线**（4.8）；Android 壳不需要 Apple 登录。两端壳都不内置微信 SDK。
- **订阅消息**：小程序可向家长发「一次性订阅消息」（孩子今日学习完成 / 该复习了），但每条都要家长先点一次「允许」；它弥补的是「不依赖第三方（Server酱）」的缺口，不是从无到有——今天的 webhook 渠道已能把提醒送进微信。

### 5.6 安全不变量（给实现与评审对照）

1. 「已验证」只在服务端同一事务里成立：校验即作废、建号 / 登录在同一 `BEGIN IMMEDIATE` 内，不接受客户端自报。
2. 敏感操作一律重认证（密码，或任一已绑定渠道再过一次）；无密码账号也能注销与设密码。
3. 家长 ⇄ 孩子：会话记录签发者；切回必须过家长门；孩子会话不能动账号与身份；子账号的注销 / 独立由家长完成。
4. 第三方登录桥：票与轮询密钥只存哈希，轮询绑定发起浏览器，用户必须在小程序里确认，已绑定也不跳过。
5. 二次放号：久未登录的手机号身份要第二因子；家长账号必须有第二因子。
6. 管理员只接受密码登录；验证码 / 第三方注册绝不创建管理员。
7. 费用闸：每号 / 每 IP / 每号段频控 → 全站小时与日上限 → 自动关闭入口并通知。
8. 发送端响应对已注册 / 未注册一致；验证码场景不引入可被第三方触发的锁定。

## 8 术语

- **E.164**：手机号的国际格式（`+8613800138000`），存储与比较都用它。
- **HMAC 哈希存储**：验证码不明文入库，只存带服务器密钥的哈希，泄库也猜不出码。
- **SPF / DKIM / DMARC / MX**：发信域名的四条 DNS 记录，告诉收件方「这封信确实是该域名授权发出的」，QQ / 163 没有它们几乎必拒。
- **openid / unionid**：openid 是用户在某个小程序 / 公众号里的唯一标识；unionid 是同一主体多个应用间的统一标识，个人小程序拿不到。
- **`code2Session`**：小程序把 `wx.login` 得到的临时 code 交给后端，后端向微信换取 openid 的接口。
- **小程序码 / 场景值**：可带 ≤ 32 个字符参数的小程序二维码，用来把一次登录请求的票带进小程序。
- **URL Scheme / URL Link**：从短信、外部网页、App 直接拉起小程序的链接能力，个人主体不开放。
- **配对码（设备码）**：网页显示一个短码、用户在另一处输入以完成授权的方式（RFC 8628），用来绕过「同一部手机扫不了自己屏幕」。
- **二次放号**：运营商把注销 90 天以上的手机号重新投放市场，新机主可能收到原机主账号的验证码。
- **家长门**：从孩子账号切回家长账号前的一道确认（家长 PIN / 密码 / 验证码）。
- **苹果 4.8**：App Store 审核指南 4.8「Login Services」——用第三方登录建主账号的 App 必须另提供一个等价的隐私友好登录。
- **ICP 备案 / 小程序备案 / 公安备案**：在大陆提供网站或小程序服务前向通信管理局（经接入商）与公安机关登记的手续，域名必须接入大陆主机。
